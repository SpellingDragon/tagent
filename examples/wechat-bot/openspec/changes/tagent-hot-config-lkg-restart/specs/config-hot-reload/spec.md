## Purpose

让 tagent 进程在配置文件变更后自动完成重解析、校验与配置快照原子切换，失败时保留旧配置继续服务并留审计痕迹，全程无需重启进程。

## ADDED Requirements

### Requirement: 配置文件变更自动触发重载

系统 SHALL 在配置文件发生变更（写入/替换/属性变化）后，经事件归并窗口（debounce）自动触发一次完整的配置重载流程（重新读取 → 解析 → 校验 → 与当前快照比对）。监听 SHALL 支持文件系统事件机制（fsnotify），并在该机制不可用时降级为定时轮询（比较 mtime 与 size）。

#### Scenario: 保存有效配置变更后热载生效

- **WHEN** 进程运行中，配置文件的一个白名单字段被修改并保存
- **THEN** 在归并窗口结束后系统完成重解析与校验，进程内配置快照切换为新值，后续配置读取返回新值，且进程全程未重启

#### Scenario: 文件系统事件机制不可用时降级轮询

- **WHEN** fsnotify 类事件机制创建失败（平台限制或权限不足）
- **THEN** 系统降级为定时轮询（间隔不超过 1 秒量级）检测 mtime/size 变化，触发同样的重载流程，行为与事件驱动模式一致

#### Scenario: touch 类无实质变更不触发重载

- **WHEN** 配置文件 mtime 被更新但内容未变（如 touch 或原子替换为相同内容）
- **THEN** 重载流程经内容/指纹比对判定无实质变更，不切换快照，不产生用户可见的配置变化

### Requirement: 重载成功后原子切换配置快照

系统 SHALL 在新配置完整通过解析与校验后，以原子方式（读无锁、写整体替换）将进程内活跃配置快照切换为新快照。配置消费点 SHALL 经统一读取入口获取当前快照，不得在启动装配期之后缓存裸配置引用。

#### Scenario: 快照切换原子性

- **WHEN** 快照切换与并发的事件处理/配置读取同时发生
- **THEN** 任一读取者读到的快照要么是完整的旧快照、要么是完整的新快照，不存在混合态或部分生效

### Requirement: 坏配置保旧并留审计

系统 SHALL 在重载流程任一步失败（YAML/JSON 解析错误、字段类型错误、字段值非法）时保留当前活跃快照继续服务，进程不退出，并记录审计信息：ERROR 级日志（含失败原因与文件路径）与失败计数递增。

#### Scenario: 坏 YAML 保留旧配置

- **WHEN** 配置文件被写入无法解析的 YAML 内容
- **THEN** 进程内配置快照保持为重载前的值，进程继续正常运行，日志出现 ERROR 级重载失败记录，失败计数递增

#### Scenario: 字段非法保留旧配置

- **WHEN** 配置文件是合法 YAML 但包含越界或类型错误的字段值
- **THEN** 校验失败，快照保持旧值，进程不退出，审计记录（ERROR 日志 + 计数）与坏 YAML 场景同构

#### Scenario: 坏配置修复后再次生效

- **WHEN** 配置文件从坏内容被修复为有效变更
- **THEN** 下一次重载成功，快照切换为修复后的值，热载能力自愈

### Requirement: 重载全程可观测

系统 SHALL 为重载链路提供可观测留痕：变更检测触发、重载开始与完成、快照切换、失败保旧，均有对应日志记录，使一次完整重载流程可依时间序在日志中回放。

#### Scenario: 日志回放一次完整热载

- **WHEN** 一次成功的配置热载完成
- **THEN** 日志依时间序呈现"检测到变更 → 重载开始 → 校验通过 → 快照已切换"的完整链路
