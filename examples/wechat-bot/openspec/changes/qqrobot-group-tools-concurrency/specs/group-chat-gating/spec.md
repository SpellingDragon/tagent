## Purpose

扩大群聊触发面（群主 @、昵称触发）并防止无效 LLM 调用：活跃窗口、冷却、预算三重门控，方案已与用户对齐。

## ADDED Requirements

### Requirement: 触发条件扩展

在既有 @ 机器人门控（is_you + BotOpenID fallback）基础上，系统 SHALL 支持：群主 @ 机器人、消息含机器人昵称时触发聊天管线；触发判定 MUST 在门控层完成，不增加 LLM 调用。

#### Scenario: 群主 @ 触发聊天

- **WHEN** 群主在群内 @ 机器人（mentions[].is_you 为 true）
- **THEN** 消息进入聊天管线（与普通成员 @ 同路径），无额外权限差异

#### Scenario: 昵称触发

- **WHEN** 群消息文本包含机器人昵称（不含 @ 结构）
- **THEN** 消息进入聊天管线；昵称匹配 MUST 大小写不敏感且避免误匹配子串（如昵称为"梦"时不匹配"梦想"）

### Requirement: 防无效 LLM 调用门控

进入聊天管线前，消息 MUST 通过三重门控，任一不过即静默丢弃（可记日志，不产生回复）：

1. **活跃窗口**：仅最近活跃（如最近一条群消息在 N 分钟内）时响应该群触发
2. **冷却**：同一群两次 LLM 调用间隔不低于冷却时长
3. **预算**：LLM 调用预算（次数 / token）耗尽时不再调用，直至预算窗口重置

#### Scenario: 冷却期内重复触发被丢弃

- **WHEN** 同群在冷却期内再次触发（无论 @ 还是昵称）
- **THEN** 不发起 LLM 调用，不产生回复，日志记录一次丢弃原因

#### Scenario: 活跃窗口外触发被丢弃

- **WHEN** 群处于非活跃状态（最近 N 分钟无消息）
- **THEN** 昵称触发被忽略；@ 触发的处理不受此门控影响（@ 仍全量处理）

#### Scenario: 预算耗尽

- **WHEN** 当日 / 当窗口 LLM 调用预算耗尽
- **THEN** 后续触发被丢弃并记录；窗口重置后恢复
