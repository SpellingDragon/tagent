## Why

tagent 框架的四层组织结构中，第 2 层（MCP servers，如 toolmcp）已具备配置热同步（hot-sync）能力，而第 3 层（Agents，org 下 per-agent 的工具注册表与身份配置）仍是冷配置：任何配置变更都需要重启整个 Agent 进程才能生效。这导致运行中的会话因配置调整被迫中断（在有状态会话、常驻 Agent 场景下代价尤为高昂），也使配置调试的迭代周期变长。

本变更引入 Agent 层配置热重载：无需重启进程，即可让 Agent 的第 3 层组织配置（身份、工具注册表、模型/超时等）在运行期生效。方案复用 toolmcp 已验证的 hot-sync 模式（配置指纹比对 + 缓存实例复用），把"配置文件 → 组织结构"的映射从进程启动期一次性构建，改为按配置指纹惰性重建。

## What Changes

- 新增 Agent 配置指纹机制：对第 3 层组织配置做规范化指纹计算，作为缓存键与失效判据
- 新增配置变更检测：运行期检测配置文件变更并比较指纹，决定是否触发重建
- 新增组织结构惰性重建：指纹变化时按新配置重建第 3 层组织结构（Agent 身份/工具注册表），旧实例安全退役
- 在途事件处理策略：重建期间在途处理的事件继续使用旧配置完成处理，重建完成后新事件使用新配置
- 坏配置降级策略：新配置校验失败时保留旧配置继续服务，不中断进程
- 新增热重载相关可观测性：变更检测、重建、降级事件均有日志与计数器留痕

## Capabilities

### New Capabilities

- `agent-config-hot-reload`: Agent 第 3 层组织结构配置（身份、工具注册表等）的运行期热重载能力，覆盖指纹计算、变更检测、惰性重建、在途事件处理与坏配置降级

### Modified Capabilities

（无——现有能力的需求未变；agent 配置加载在启动期构建的既有行为不变，本能力是其增量）

## Impact

- **代码**：Agent 配置加载/组织构建路径（惰性重建入口、指纹计算、缓存实例复用）、事件分发/执行路径（在途事件与重建的并发边界）
- **依赖**：复用 toolmcp hot-sync 的既有模式（配置指纹 + 实例缓存），不引入新外部依赖
- **行为影响**：Agent 进程内配置生效无需重启；风险集中在坏配置降级、并发安全与状态平移，见 design.md 风险清单
