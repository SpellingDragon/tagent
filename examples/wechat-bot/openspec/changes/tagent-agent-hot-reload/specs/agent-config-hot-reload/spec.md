## Purpose

Agent 第 3 层组织结构配置（per-agent 身份、工具注册表、模型/超时等）的运行期热重载能力：无需重启 Agent 进程，配置变更即可生效。复用 toolmcp hot-sync 已验证的模式（配置指纹 + 实例缓存复用），覆盖指纹计算、变更检测、惰性重建、在途事件处理与坏配置降级。

## ADDED Requirements

### Requirement: Agent 配置指纹计算

系统 SHALL 对 Agent 第 3 层组织配置计算规范化的配置指纹，作为配置实例的缓存键与失效判据。指纹 MUST 覆盖影响 Agent 行为的全部配置维度（身份、工具注册表、模型与超时等），且对语义等价的配置 MUST 生成相同指纹（规范化后再计算，不受无关空白/键序影响）。

#### Scenario: 语义等价配置产生相同指纹

- **WHEN** 两份仅键序、缩进或无关空白不同的 Agent 配置被计算指纹
- **THEN** 两份配置得到相同的指纹值

#### Scenario: 任一行为维度变化即改变指纹

- **WHEN** Agent 配置中的身份、工具注册表或模型/超时任一维度发生变化
- **THEN** 计算出的指纹与变化前不同

### Requirement: 运行期配置变更检测

系统 SHALL 在运行期检测 Agent 配置文件变更并比较配置指纹：指纹与当前活跃配置实例一致时 MUST 跳过重建（复用既有实例）；指纹不同时 MUST 触发组织结构重建。

#### Scenario: 指纹未变化时跳过重建

- **WHEN** 配置文件 mtime 变化但规范化后的指纹与当前活跃实例一致
- **THEN** 系统复用既有配置实例，不触发重建，不产生额外开销

#### Scenario: 指纹变化时触发重建

- **WHEN** 配置指纹与当前活跃配置实例的指纹不同
- **THEN** 系统按新配置触发第 3 层组织结构重建

### Requirement: 组织结构惰性重建

指纹变化时系统 SHALL 按新配置重建第 3 层组织结构（Agent 身份与工具注册表），重建 MUST 是惰性触发（检测到变更时才重建，而非每事件全量重建），重建后的新实例 MUST 替换旧实例成为活跃配置；旧实例 SHALL 安全退役（不再接收新事件，在途依赖见"在途事件处理"需求）。

#### Scenario: 变更后新事件使用新配置

- **WHEN** 组织结构重建完成且新事件到达
- **THEN** 新事件按重建后的新配置（新身份/工具注册表）处理

#### Scenario: 惰性触发不做无谓重建

- **WHEN** 配置在两次检测之间无指纹变化
- **THEN** 不发生重建，活跃配置实例被复用

### Requirement: 在途事件处理

重建期间在途处理的事件 SHALL 继续使用其开始处理时的旧配置实例完成处理；重建 MUST NOT 等待在途事件全部完成后才开始，重建完成 MUST NOT 立即杀死正在处理的在途事件。

#### Scenario: 在途事件继续按旧配置完成

- **WHEN** 事件 A 已开始处理（持有旧配置实例引用）且此时触发了重建
- **THEN** 事件 A 按旧配置继续处理直至完成，不被中断或杀死

#### Scenario: 重建不等在途事件

- **WHEN** 存在在途事件且指纹变化触发重建
- **THEN** 重建立即进行，不阻塞等待在途事件完成；重建完成后新到达事件使用新配置

### Requirement: 坏配置降级

新配置解析或校验失败时系统 MUST 保留旧配置实例继续提供服务，进程 MUST NOT 因坏配置崩溃或退出；降级事件 MUST 被记录（日志/计数），修复配置后的下一次检测 MUST 能再次尝试加载并生效新配置。

#### Scenario: 坏配置保留旧实例继续服务

- **WHEN** 新配置文件解析或校验失败
- **THEN** 系统保留上一个有效配置实例继续服务，进程不退出，降级事件被记录

#### Scenario: 修复后可再次生效

- **WHEN** 坏配置被修复并通过校验后的下一次变更检测运行
- **THEN** 新配置被加载并重建生效，恢复热重载正常路径

### Requirement: 热重载可观测性

热重载流程 SHALL 产生可观测留痕：指纹变化/重建开始与完成、在途事件按旧配置完成、坏配置降级，均 MUST 有日志与（可用的）计数器记录，便于运维排查。

#### Scenario: 重建全程留痕

- **WHEN** 一次完整的指纹变化→重建→新配置生效流程发生
- **THEN** 日志中能依时间序找到变更检测、重建开始与完成、新配置生效的记录

#### Scenario: 降级事件可发现

- **WHEN** 坏配置触发降级
- **THEN** 日志与计数器中存在该降级事件的记录
