# 群聊上下文保真 + 出站真提及修复

## Why

2026-09-12 20:32-20:53 群聊实测（日志取证实证）暴露三类缺陷叠加导致机器人回复质量崩坏：

1. **历史快照失真**：入站消息进历史快照前 `<@openid>` 提及标记被剥掉、图片/GIF 消息渲染为空行 → 模型做指代消解（"该 @ 谁"）无材料。后果实例：群主 20:47 问"该 @ 谁"，正确答案是 G411（他 20:39 问"哪里搞来的这些簧图"，问图的是他），机器人却 @NANA（仅凭"嘴替是吧"存在感乱猜）。
2. **出站假 @**：回复文本里的 `@NANA`/`@Misaki` 是纯文本，QQ 官方真提及必须 `<@member_openid>` 形态 → 当晚 5 次回复提及全部无效。
3. **无兜底**：persona 无"拿不准就反问"规则，模型在无材料时按存在感乱猜。

另：用户评价最近回复"很奇怪"（20:51 @NANA 答豆包榜单、20:53 @Misaki 答非所问），疑与机器人自身历史回复缺失导致上下文重复/错位有关，一并排查。

## What Changes

- **F1 入站历史保真**（渲染点在 service/gate 下，grep 实证）：提及 `<@openid>` → `@显示名`（映射来源：同窗口帧 username↔openid 关联 + 既有 profile 注册表；查不到回退 `@成员`）；图片/GIF 消息 → `[图片]`/`[GIF]` 占位；核实机器人自身回复是否进历史，缺失则补。
- **F2 出站真提及**（robot.go 发送路径）：发送前把文本中 `@显示名` 反查 openid → 替换为 `<@openid>`；查不到保留原文。
- **F3 persona 软规则**：指代类问题只点名上下文明确出现过的人，拿不准就反问（persona 文件落点先 grep 实证）。
- **F4 历史 char cap 裁剪缓解**（视取证结论）：20:51 G411 提问是否被历史 char cap 裁掉待实证，若属实则缓解。

## Impact

- 代码：service/gate 历史渲染路径、robot.go 发送路径、persona 提示词文件
- 风险面：历史快照格式变更影响所有群聊会话；出站替换影响所有含 @ 的回复
- 不入库：config.yaml 键位改动仅落本机（.gitignore），代码内默认值为仓库权威
- 验收：go test 全绿 → build → restart.sh 上线，单实例 + 运行中 exe md5 = 盘上新件 + 心跳正常；提交推送 main
