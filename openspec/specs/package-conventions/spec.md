# package-conventions Specification

## Purpose

定义机制子包的挂法（只含事件词汇、消费接线、扩展策略三类文件）与命名归位规则（同一概念一个正名，与语义不符的内部名改回语义），作为新包准入与评审的判据。

## Requirements

### Requirement: 机制子包挂法

机制子包 SHALL 只含三类文件：事件词汇（事实/事件类型与身份）、消费接线（谁驱动）、扩展策略（可插拔面）；业务逻辑 MUST NOT 住机制子包（属领域包）。新包准入 MUST 回答三问：业务还是机制？机制挂哪三类文件？事实/消费/扩展各是哪个文件？

#### Scenario: 机制包自检
- **WHEN** 检查任意机制子包的文件
- **THEN** 每个文件可归入事件词汇/消费接线/扩展策略之一，第四类文件不存在

### Requirement: 命名归位

同一概念 MUST 只有一个正名（历史旧名仅保留在命名沿革注释）；与语义不符的内部名 MUST 改名归还语义（如回放的已消化标记不叫冥想）。

#### Scenario: 冥想正名与标记归还
- **WHEN** 检查认知整理机制与回放标记集的命名
- **THEN** 认知整理机制名为 meditation（旧名 curation 仅存于命名沿革注释），回放标记集名为 consumed
