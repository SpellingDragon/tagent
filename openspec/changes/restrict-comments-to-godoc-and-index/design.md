# 设计：注释形态白名单与文档分工

## Context

代码现状（实测）：557 个 Go 文件、22,501 行注释；体内/流程注释仅 471 行，其余 21,498 行贴着声明——**问题不在注释位置，而在注释内容**：贴着声明的大多是设计论证、机制流程、决策与迭代记录，而非该 API 的契约。指令类注释极少（`//go:build` 5、`//go:embed` 1、`//nolint` 1、`TODO(` 1），说明机械豁免面很小。仓库无许可证头约定，因此不需要第三类豁免。

项目已有两份现态文档层：`docs/wiki/`（机制、边界、缺口，已重写为纯现态）与 `openspec/specs/`（SHALL 契约）。注释与它们大面积重复，且注释版本更陈旧、更易腐化。

测试面同样失配（实测）：401 测试文件对 156 生产文件，根包 70:16、`agent/` 109:28、`tool/action` 31:7、`agent/task` 20:3——同一职责的不同工况被平铺成多个文件；28 个测试文件名与 49 个函数名带变更任务号/批次号，编号在其所属变更归档后即不可解。既有活规格 `architecture-guardrails` 的「变更局部性准绳」已经把「一个变更意图一个落点」立为内聚准绳（并明确 god file 解体属冻结后另变），`wiki-code-sync` 已禁止 wiki 承载内部审计编号——本次把同一条纪律延伸到代码与测试面，不新立第二套标准。

## Goals / Non-Goals

**Goals：**

- 代码内注释只剩两种形态：go doc 契约注释、文档索引单行；设计/逻辑/过程说明在代码内**零残留**。
- 每个包与每个导出符号都有可读的 go doc；`docs/api/` 作为生成物入库并保持新鲜。
- 三条硬门：注释剥离等价（证明「只动注释」）、政策扫描零违规、文档覆盖与新鲜度。
- 知识不丢失：删除前完成承接判定，wiki/specs 该补的先补。

**Non-Goals：**

- 不改行为、签名、命名、文件划分（本变更的机器证据即「注释剥离后逐字节相同」）。
- 不以注释行数下降作为验收指标（见 D8），不追求「注释越少越好」。
- 不重写 wiki 篇章结构与撰写约定；不把 `docs/.dev/` 历史归档纳入清理。
- 不引入新依赖（扫描器与生成器只用 Go 标准库/`go` 命令与既有 shell 设施）。

## Decisions

### D1 允许形态一：go doc 契约注释（正面清单 + 禁止清单）

位于 package 或声明的 doc 槽位，以标识符名开头（Go 惯例），内容**只允许**：该 API 是什么；输入输出与单位；前置/后置条件；nil/零值/空集语义；失败与错误语义；幂等与重试语义；并发安全性；调用方必须履行的义务（获取即须释放等）；有效范围/边界（含「不保证什么」）。

**禁止**（一律迁出或删除）：设计理由与取舍（「之所以…因为…」「选择 A 排除 B」）；实现机制与流程叙述（「先 A 再 B」「在 X 锁内完成」——代码自身已表达）；迭代与过程标记（决策/条目编号、轮次、日期、「已移除/已废弃/历史上/曾经的坑/教训/审阅发现」）；跨模块行为说明（属 wiki）；对 bug 的叙事性描述。

判据一句话：**「换一个实现方式，这句话还成立吗？」成立→契约（留）；不成立→实现叙述（走）**。

### D2 允许形态二：文档索引

固定语法，一行，位于相关声明的 doc 槽位末尾：

```go
// 契约: docs/wiki/agent/agent-architecture.md#213-执行代与发布executor-generations
// 规格: openspec/specs/swappable-executor
```

允许目标仅 `docs/**` 与 `openspec/specs/**`。**禁止**指向 `openspec/changes/**`（含归档）与任何过程工件——那是迭代史，不是现态文档。索引不承载解释；一行只放一个锚点，多个锚点分行。

### D3 机械豁免清单（穷举，新增须显式登记）

`//go:build`、`//go:generate`、`//go:embed`、`//go:noinline` 等编译器/工具指令本身；`//nolint` 及其简短规则名；cgo 预导言（`//export`、`#include` 等）；一行式 `TODO(owner): <可执行动作>`（不得含说明与理由）。豁免由扫描器规则表持有，禁止就地注释「例外理由」。

### D4 测试文件政策

测试没有对外 API，故其 doc 槽位只允许：一行测试意图（`// TestXxx 验证 <契约/不变量>`——what，不含 why 与机制）＋文档索引。断言消息字符串、测试名、表驱动用例的 `name` 字段**是代码而非注释**，是承载期望与判据的首选位置（把原注释里的「期望什么」移进断言消息，而不是留在注释里）。测试体内解释性注释一律删除。

### D5 零行为证明门

`scripts/check_comment_only.sh <baseline-ref> [path...]`：对每个变更文件，用 `go/parser` 读入基线与当前版本，剥离全部注释 token 后经 `go/printer` 规范化输出，逐字节比对；任何非注释差异即整批失败。工具本身入本仓库（Go 标准库实现，无新依赖）。

### D6 政策扫描器

`scripts/comment_policy/`（Go 程序，`go run ./scripts/comment_policy ./...`）判定：①注释不在 doc 槽位（体内/游离）→ 违规；②doc 注释命中迭代标记/理由叙述正则表 → 违规；③含路径引用但不符合 D2 语法 → 违规；④指向 `openspec/changes/**` → 违规；⑤package 无 doc、导出符号无 doc → 违规；⑥豁免命中 D3 清单 → 通过并计数。正则表在脚本内显式列出并逐条注因；**长度不作为判据**（长契约注释合法，短黑话注释非法），超长仅告警供人工复核。人工终判不可省：扫描器是网，不是尺。

### D7 go doc 生成物

`scripts/gen_godoc.sh`：遍历两模块全部包（含 `examples/wechat-bot`），每包生成 `docs/api/<模块路径>>.md`（`go doc -all` 视图），并生成 `docs/api/index.md`（包清单＋覆盖率摘要）。入库；CI 重跑并要求无差异（新鲜度门）。生成物是**唯一允许的派生文档**，不得手工编辑（改注释重新生成）。

### D8 验收判据不设行数目标

以「政策扫描违规数＝0」＋「覆盖门通过」＋「抽查记录」为准；注释行数是结果不是目标。**禁止为凑指标删除契约信息**——同一处内容若确属契约且无处安放，即 D1 允许保留，不得因「太多注释」而删。

### D9 知识承接分层与顺序

同一事实只在一处：机制/边界/缺口→wiki 对应章；SHALL 行为契约→`openspec/specs/**`；API 用法契约→代码 doc；代码→最多一行索引指回。每批固定工序：**先读注释清单→判定三分类→补 wiki/specs→再删注释→过门**。已识别至少需补章的判据：换代与常驻构建的状态重建边界、热更各门的先后理由与粘性、任务 TTL 单轴回收理由、投递对账终止判据、执行代退役三条件、跨重启世系保真与 unknown 血统扣留。

### D10 批次划分（以知识域为单位，域内两类变换分两次提交）

清扫与合并都以**知识域**为工作单元（同一判据不被两次打开）：根组合包 / `agent` 核心 / `agent` 子包（task·compress·governance·reliability）/ `memory`+`event`+`plugin` / `tool`* / `rl`+`evolution`+散包+examples+`tests`+`evals`。每个域内固定顺序：**先 T（测试文件族收敛与标识去编号）→ 后 G（该域注释清扫）**；两类变换分别成批、各过自己的门（T 过合并不变量门，G 过注释剥离等价门），绝不混在同一提交里——否则两类可证明变换会互相抵销证据。

### D11 上报条件（不静默处理）

①注释承载的知识在 wiki/specs 均无合适落点且与撰写约定冲突→停下上报，不强行删除或降格保留；②注释与实现矛盾→以代码为准，并核对 specs 是否同样失真，若契约文档也错→上报修订，不在注释里「修正事实」；③需要新增扫描豁免→上报并登记理由，不悄悄放宽正则。

### D12 测试文件族＝职责，工况＝子测试

合并单位是**生产职责**，不是变更批次、也不是文件大小：一个职责的全部工况（正常/降级/异常/并发/边界/性能断言）收敛到同一 `*_test.go`，以 `t.Run` 表驱动区分工况；测试文件族与所辖生产文件族一一对应。每个测试文件在其文件级 doc 槽位写一行 `// 契约: <生产文件路径>` 声明所辖职责——这既是 D2 的合法索引形态，也是「同一职责只有一个测试文件」的机器判据。

**边界**：本变更只动测试文件划分。生产 god file（`context_manager.go`/`tool_agent.go`）的解体按 `architecture-guardrails` 既定安排另做，MUST NOT 借合并之名顺手拆生产文件（那会把「只动注释＋只动测试」两类可证明变更混成一次不可证明变更）。

### D13 标识去编号（文件名与函数名两层）

任务号/批次号/日期（`d2_`…`d14_`、`m3_`、`w1_`、`org_m34_`、`restart30`、`hy3_`、`TestD52_*`、`TestMonitor33_*` 等）在文件名与函数名两层一律清除，改为职责语义名（测哪个契约＋何种工况）。每批产出旧→新映射表入台账；`go test -list '.*'` 逐包计数不变；重命名同步 docs/scripts/CI 中所有引用，终门要求旧标识引用残留为 **0**（grep 判定）。

### D14 合并的机器不变量

`scripts/check_test_merge.sh <baseline-ref>`：①基线以来**非测试 Go 文件零变化**；②受影响包测试清单与基线一一对应（依据映射表校验双射，无丢失/无静默新增）；③每个测试函数的断言调用计数不降（`require.*`/`assert.*`/`t.Fatal*`/`t.Error*`）；④`t.Parallel()` 分布不因合并改变（并行度是语义，不是排版）；⑤合并后该包含 `-race` 全绿。任一不满足即整批失败回退。

### D15 helper 归一与近重复处置

编译器会抓同名冲突，抓不到**近重复**（两个形状相似的 fake/fixture）。规则：归一为一个实现，差异以参数或子类型表达；每次归一在台账记录「谁保留、谁退出、语义差是什么」。无法等价归一时（各自承载不同契约前提）→ 保留两者并在各自 doc 注明适用前提，不得靠删除规避判断。

### D16 端到端链保持单一落点

贯穿链（常驻重挂、跨发布回流、多级委派、崩溃对账）MUST NOT 为满足按包分文件而拆散；`tests/` 与 `evals/` 的链级落点保留，包内局部测不得以「分别通过」替代整链证据（沿用 `resident-release-evidence` 的禁拼链纪律）。

### D17 顺序：同域内先收敛、后清扫

合并会搬动注释，清扫会重写注释。若先清扫后合并，注释刚定稿就被整段搬移，台账与判读都要重做；若全局先做完所有合并再清扫，跨域知识又要第二次打开。故取**同域内 T→G**：该域测试文件族先收敛到位（只搬移与改名，不动注释内容），随后一次性把该域（生产＋收敛后的测试）的注释收敛为契约形态。工具与门（G1）必须在任何域之前完成——没有机器证据就没有「只动注释」「只动测试」的断言资格。

## Risks / Trade-offs

- **过度删除**（最高风险）：把单位、nil 语义、调用义务当叙述删掉。缓解：D1 正面清单＋D8 无行数目标＋每批人工抽查记录＋生成物可读性复看。
- **借道重写**：清理时顺手改代码。缓解：D5 硬门在批内先跑，失败即回退。
- **扫描器双刃**：正则误报会让人批量加豁免，反把违规洗白。缓解：D6 规则表显式化＋豁免计数入台账＋D11 上报门槛。
- **文档膨胀**：承接内容把 wiki 撑成第二座注释山。缓解：D9 同一事实单处；承接前先查是否已覆盖；wiki 撰写约定（现态、不记过程）继续约束新章。
- **测试合并致覆盖静默缩水**（与「过度删除」同族）：helper 归一吞掉某侧前提、断言合并时被取交集。缓解：D14 清单双射＋断言计数不降为硬门、D15 近重复逐条裁决留痕、每批 `-race` 全绿。
- **改名打断外部引用**：CI 过滤器、文档锚点、脚本 `-run` 表达式。缓解：D13 映射表＋终门要求旧标识引用残留为 0；实测当前 `.github`/`scripts`/`docs` 对被改编号标识**无引用**，风险面自封闭。
- **生成物漂移**：`docs/api/` 忘记重生成。缓解：CI 新鲜度门。

## Migration / Rollback

纯注释与新增文件，无数据/接口迁移。逐批提交；任一批回滚＝`git revert` 该批提交即恢复原注释，不影响行为。终态提交顺序：工具与门 → 各清扫批 → 生成物与 CI → 终门记录。
