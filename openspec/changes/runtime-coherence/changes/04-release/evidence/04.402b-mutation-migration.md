## 一、漂移的真实形态（不是 old 片段陈旧）

### 2.2 fault 形态（位置化三处一致）

把变异补丁应用到副本树后逐 hunk 核对（`/tmp/m401-preview`，产品树零写入）：

```diff
--- assembly/request.go
-	endedAt event.EventID
+	ended           int
-func (h replayEntry) endedPrefix() int { … 按身份解析 … }
（方法整体删除）
-	prefix := held.endedPrefix()
+	prefix := held.ended
-	r.replays[addr] = replayEntry{projection: projection, window: window}
+	r.replays[addr] = replayEntry{projection: projection, window: window, ended: projection.Len()}
-	… a.sequence.endedPrefix(), a.boundary.ProjectionBudget)
+	… a.sequence.ended, a.boundary.ProjectionBudget)
--- assembly/facts.go
+	position := held.projection.Len()
 	var landed bool
 	held.projection, landed = foldIntoProjection(ctx, held.projection, entry, held.window)
 	if evt.Type == event.TypeAgentOutput {
-		held.endedAt = entry.Key
+		held.ended = position
 	}

-		held.endedAt = entry.Key
+		held.ended = position
 	}
-	prefix := held.endedPrefix()      # chainAlreadyPresented
+	prefix := held.ended
-	return held.endedPrefix(), true   # NoticeBoundary
+	return held.ended, true
-	boundary := held.endedPrefix()    # notice read
+	boundary := held.ended
```

fault 语义（与迁移前一致，一句）：**把 in-flight 边界的解析从「按身份（`event.EventID`＋`endedPrefix` 现序解析）」改回「按位置（`int`，在 fold 之前记 `Len()`）」**——age fold 重写序列后，存下的位置要么命名了别的材料，要么越过已缩短的序列被 `AssembleBudgetPrefix`/读侧夹到末尾，于是 in-flight 通知被折进 ended 前缀，请求里出现第二条副本。

字段名、赋值、解析三处一律位置化；`position` 仍取 fold **之前**的 `Len()`，这是原条目冻结的形态（注释「the mutant records the position the entry lands at in the sequence as it stood before that step」）。新增的第 9 处读点用同一替换规则，因此它跟随同一个陈旧位置值，不引入新语义。
