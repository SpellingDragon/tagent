## 二、G3 flake 处置（`TestReceiptAndBackgroundStaySeparate`）

### 2.1 修复前（本树 HEAD 基线，未改测试文件）

```sh
go test ./tests/integration/execution -run '^TestReceiptAndBackgroundStaySeparate$' -count=10 -v
# rc=1；9 PASS / 1 FAIL
#   receipt_background_separation_test.go:285: second invocation message ledger = map[call-a settle notice:1 call-b settle notice:1 … unexpected:1]
go test ./tests/integration/execution -run '^TestReceiptAndBackgroundStaySeparate$' -count=100 -v
# rc=1；96 PASS / 4 FAIL，四型原文：
#   :230 no request presents the three inputs beside both settled bodies within the wait
#   :197 tool role messages under call-b = 2, want the single admission receipt and no second synchronous response
#   :286 … map[call-a settle notice:1 … third input:1 tool call turn:1 unexpected:1]
#   :286 … map[call-b settle notice:1 fast settled body:1 … tool call turn:1 unexpected:1]   （缺 call-a settle notice）
```

另跑 3×10 轮插桩批（rc 依次 1/0/1），捕获第三型 `:197 tool role messages under call-a = 0`。插桩（`t.Logf("DEBUG-UNEXPECTED …")`）已撤，收尾 `grep -c "DEBUG-"` = 0。

**机制（插桩捕获原文，`requests=3` 的失败轮）**：驱动 1 的末请求不是本 range 的收尾决策，而是 **settle 驱动的后续 range**——其最后一条消息是无 ticket 的 user 角色 settle 行（`tagent: task task-d9206d… settled`），即该 range 自己的输入。该 view 里 call-b 有 `action_command` 已结 body 与 `task_settled` 通知各 1，call-a 一条 tool 角色消息都没有：**准入收据 `ok` 是 in-flight 材料，按设计不重放到新 range 的历史**（测试自身在 ledger 前一条断言已写明"the receipt is the in-flight confirmation requests[1] holds, not a committed fact"）。

### 2.2 改动（同一原则，三处，均在测试文件内）

1. **`awaitSepFlush` 谓词扩到断言所需的八族**（派单指定）：除三个输入与两条 settled body 外，再要求 call-a／call-b 各一条 `task_settled` ticket 的 settle 行；新增 `sepCarriesSettleNotice`（角色、call 身份、ticket kind、行文逐项与断言面同形）。超时仍为 15s，语义未延长。
2. **`closingView` 一处内联计数改用 `sepToolSlots`**：原内联循环把 settle notice 也数成 answer，与同文件 `sepToolSlots` 已声明的"one-slot rule counts answers only（settle notice 是交付事实，不是回答）"自相矛盾；复用后规则只有一份。判据本身未变（仍要求每个 call 恰 1 条 answer）。
3. **驱动 turn-2 前等两笔通知落账**：尾部原有的"等 `query.ObjectNotice` 两笔均 `DetailRetired`"循环原样抽为 `awaitSepNoticesBooked`（两处共用：驱动前与尾部断言前）。依据是测试自身契约"the next invocation reads the shared history the drives already ended committed"——落账异步于一拍的交付，驱动不得抢跑。

## 三、残留（未修，待裁）
