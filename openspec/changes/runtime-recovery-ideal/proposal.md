# 运行时恢复理想态：语义收敛计划

> 2026-11-20 重整。保留变更身份 `runtime-recovery-ideal`；`7b0cde162627ad37f1d364bbf3508b3bd0518431` 是待复核候选，不是完成证明。本轮只完成规划，不实施产品、测试、主规格、CI、权限、提交或归档。

## Why

原始问题包含日志持续增长、长期重启变慢、重复处理和恢复后的历史可读性。用户已接受日志保留历史而物理增长，并要求不改写已提交事实；不能把另一项计数通过说成原文件封顶目标已达成。当前目标进一步明确为：先排除伪前提、结构自证和跨域联系遗漏，再选择更少特殊机制的实现，而不是继续围绕旧方案补丁式清零。

现有候选包含有价值的原子提交、单写者、可寻址索引、状态托管及夹具修复，也包含需要重新验证的假设。四路只读复审指出：提交与应用顺序、快照与尾部截止点、审批失败后的可见状态、凭证读取失败后的再次驱动，需要在真实路径构造反例；探测长度的样本不能证明索引损坏，产物身份不含正文否定了部分内联理由，局部变异 killed 不能证明全部能力。详见 [design.md](design.md) 的证据分级与目标矩阵。

## What Changes

只保留三个活动执行单元，复用既有目录，不新建平行变更或新的运行框架：

| 单元 | 活动目录 | 要回答的问题 |
|---|---|---|
| 提交—应用—义务 | `changes/12-consumer-state-lifecycle/` | 谁确认提交、谁应用状态、谁结清义务；运行与恢复如何保持同一顺序及失败语义 |
| 历史读取—派生索引 | `changes/06-bounded-open-index/` | 哪些数据是权威，哪些只是可重建索引；每次读取实际需要哪些历史与字节 |
| 能力契约—验证体系 | `changes/13-verified-completion/` | 公开能力有没有兑现，旧要求有没有承接，正式入口是否从原始运行事实得出结论 |

每单元按取证、设计、实施、验证和独立审查推进。取证允许证伪旧怀疑；设计比较保留现状、最小修正、删并或替代，不预先指定新存储库、游标字段、接口数量或全局拒绝策略。选择后才填写精确实施签发记录，未签发的实施叶不能派。

## 保留与重新核定

- 保留不可变事实、领域身份等价、原子批和耐久屏障、单写者隔离、原文与顺序可读、失败不冒充成功、未完义务不丢、原授权 scope 不放宽。
- 保留 builtin 默认可用、自定义拓展、摘要预算与租约采样、中段票据自主召回；核对默认装配与可禁用/覆盖的实际范围。
- 保留早期事实的可发现性与按已知键读取之间的区别；执行权限、环境和工作目录跨重启保持，不因旧类型不存在而删除行为要求。
- 重新核定全局拒 cut、Repeat 接口、双压缩端口、正文内联、完整性校验时机、探测上限和常开计量。它们是实现选项，不由旧测试名称或规则条数自动证明必要。
- 不恢复已明确删除的退位/冷读/lifecycle 兼容机制；旧冷根继续用已验证的外部转换流程。若新证据要求改变已批准的用户目标，先记录影响与真实替代方案，再取得明确决定。
