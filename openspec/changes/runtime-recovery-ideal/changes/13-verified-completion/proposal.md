# 能力契约—验证体系

> C单元，活动叶13.101–13.106全部待执行。旧R任务与证据保存在父变更历史快照；本单元不因旧9/9或CI脚本存在而完成。

## Why

候选已经有大量检查器、变异、运行摘要和规格清理，但原始执行事实、能力承诺、设计正确性和发布许可被混用。一个词形变异被杀不能证明没有死语义，一个父测试通过不能证明所有子锚运行，旧类型消失不能证明发现能力或用户隔离可被取消。

本单元先重新核定用户可感知的能力，再比较更薄的验证链：原始结果只有一份解释，已有工具在正式入口复用；不为守住旧方法数或文件名规则制造新的生产结构。

## What Changes

- 核定完整旧项、P0–P8、原症状、公开模式和数据边界，给A/B提供明确需求输入。
- 重新比较builtin默认、声明禁用/覆盖/贡献、状态生命周期和压缩预算的公开范围，先签发后实施。
- 统一runner、bundle、DoD对原始日志/实际argv/候选身份的解释；保留缺测、skip、超时、红控制与过期拒绝。
- 把原规范、实际能力、golden、文档和合并输入一次对齐；不取消没有仓内实现的外部工具负例。
- 在最终矩阵之前独立审能力承接与证据系统，F2/F3/F4仍由一级直管。

## 边界与依赖

- 依赖：13.101先行；13.104等待12.104/06.104，13.105等待两单元完整回归，13.106等待两单元独立审。依赖表以本域tasks为准。
- 被依赖方：12/06设计门消费本域能力边界；F1–F4消费本域规范合并、验证选择与独立审结果。

## 验收

每个公开行为有正式入口正负锚，每个报告字段有真实来源和消费者；缺输入/错结果不能靠摘要补齐。旧要求、配置/模式、原始症状逐条完成才签发最终矩阵，未生效必需外部保护仍属未完成。规划文本合规不等于产品完成。
