## 二、会话级协调者

- [ ] 2.1 协调者下沉：checkpoint 由每会话按其上下文（压缩/输入轮变化/会话关闭）请求，切面只读取并写入本会话的派生切片 —— 验证（三锚待冻结）：正锚＝两会话交错时切面只含触发会话切片；负锚＝跨会话读取残留必红
- [ ] 2.2 恢复路径：读最近 checkpoint 后只对本会话尾部重跑 g(x)，回放期关闭 observation 副作用 —— 验证（三锚待冻结）：正锚＝重启后无重复投递/无重复驱动；负锚＝回放期触发一次 settle 必红
- [ ] 2.3 最新载体读取：仍经 journal 逆扫 `NewestOfType` 取全局最新，只答身份、不拷贝不排序 —— 验证（三锚待冻结）：沿用 `TestNewestOfTypeReadsTheCommitOrderAndCopiesNoIndex`（原记录名 `TestNewestOfTypeSpansPartitionsAndCopiesNoIndex`，测试改名后按新名回写：memory/ledger/segment_store_test.go:440）；负锚＝改回整索引拷贝排序时分配上界测试必红

## 三、`Stateful` 收编消费者读态

- [ ] 3.1 reducer 接入：每个消费者以 g(x) 纯派生面提供其读态，切面只陈述派生结果 —— 验证（三锚待冻结）：正锚＝同一事实在运行期与恢复期派生相等；负锚＝切面内 flush/commit 必红
- [ ] 3.2 emitter 与 seedFact：observation 驱动者由声明提供，`seedFact` 复用 g(x) 派生而不另起路径 —— 验证（三锚待冻结）：正锚＝恢复后派生与运行期逐条相等；负锚＝恢复期额外派生一遍必红
- [ ] 3.3 无新挂点：新消费者只注册切片即获得切面与恢复，框架不为单个消费者新增专用挂点或端口 —— 验证（三锚待冻结）：负锚＝出现按消费者名分派的专用路径必红；消费者锚＝新消费者经正式装配入口接入

## 四、Material 契约收敛

- [ ] 4.1 统一声明：`Material` 承载材料身份，时机与失败语义为策略字段；分派按策略执行 —— 验证（三锚待冻结）：正锚＝同材料两种失败语义各按声明执行；负锚＝由端口名推断策略必红
- [ ] 4.2 迁移兼容：既有六端口作为兼容读法保留到迁移完成，任一既有面的失败行为不变 —— 验证（三锚待冻结）：正锚＝迁移前后既有面失败语义测试逐条同结果；负锚＝静默改判必红
