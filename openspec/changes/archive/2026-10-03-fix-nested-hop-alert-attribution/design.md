# Design

## D1 病形：用"下一条答案"代表被测跳

被钉跳与告警轮跳都会各自产生一条 `System=="SUB-B-PROMPT"` 且 `ToolResults` 非空的答案；数组下标 `hopsBefore` 只能表达"顺序上的第一条"，而顺序不是被测属性。正确锚法是**身份**：发布前被 park 的那一轮有确定身份（它的 model 调用先于发布发生），其答案必须由该身份的完成事件唯一确定，而不是由"谁先到"确定。

## D2 锚法（实现期改写）：按答案来源标记归属，不按回合序号或到达顺序

原设想"给 record 加发起轮次标识"被实现期证伪：`model.Request`（trpc-agent-go v1.11.2）不携带调用身份，mock 边界拿不到稳定的回合 id。可用的身份载体是**答案本身的代际标记**：只有被钉链能在 G1 面上取到 C 的回答，而通知回合按契约必在**当时那一张面（G2）**上解析，其答案带 G2 标记——因此"B 收到的答案里出现一条旧代标记"只能是本次被钉跳产出的。断言改为该计数的**增量**（基线在发布前、被钉跳已被 park 时取），并保留 `countServed(G1) > entriesBefore` 这条本就正确的归属断言。

在途窗口的钉法同步改造：原谓词"存在一条 `SUB-B-PROMPT*` 且 Tools 非空的 record"可被**前一回合**的同类记录满足（record 先于 gate 检查落账），与上一档否决的形状同源；改用 `parkedNow("SUB-B-PROMPT") >= 1` 直接观测确有调用停在闸上。

## D3 为什么不是产品缺陷，以及灵敏度的度量口径

契约要求"派生前继承发起调用租约 ⇒ 被钉跳在 G1 面执行"与"通知回合在当时那一张面上解析"同时成立；失败样本里被钉跳的 G1 serve 确实产生了，只是不被按下标取的那条属于它。

灵敏度用变异检验度量：把 `agent/session.go` 的执行视图选择整体失效（恒用出生代配置）后，本用例 **15/15 红**，复原后 **0/15**——断言对"面选择失效"是敏感的。如实标注该检验的边界：它是整体失效变异，不是"被钉跳被改道到 G2"的外科手术式模拟（本用例里出生代配置与 G1 标记重合，改道样本无法与之区分），故不主张该实验证明了改道路径可检。
## D4 验收与 CI 固化路径

fail-before：`GOMAXPROCS=1 -count=25` 现有实现约 3 红（含修复前提交对照）。修复后要求 `GOMAXPROCS=1 -count=25` 连续三批零红、默认 GOMAXPROCS 与 `-race` 全绿。达到该条件后，`GOMAXPROCS=1 go test . -short` 才具备入门禁的资格（此前因三枚 offenders 被明确搁置：重入执行视图、回滚在途编排、本条）。


## D5 落地结果：`GOMAXPROCS=1` 根包进入 CI

修复前该条件必红（3/25、2/25、1/25），修复后定向 75 次全绿、整包 `-short` 连跑三次全绿（≈57s/次）。据此把 `GOMAXPROCS=1 go test . -short -count=1` 作为 test job 的独立步骤入门禁——这不是新增预算，而是把"归属不得靠到达顺序成立"这条判据变成机器可执行。
