# 常驻可靠性协议闭环重建

## Why

当前工作树已增加可靠信箱、固定准备材料、显式重放和同代资源管理，但输入提交失败仍可进入模型及确认路径，缓存仍参与提交判定，完成与清理协议未接通；旧计划的完成勾选不能代表端到端验收。本变更从当前未提交实现出发，补齐可验证的阶段转换和恢复依据，替代而不是续写 `fix-resident-reliability-boundaries`。

## What Changes

- **计划替代**：旧变更仅保留为已废弃的历史证据，不继续 apply、不按完成归档、不同步其 delta。现有源码保留作为实施起点，新任务不继承任何旧勾选；实施完成时本次链路的过时代码、兼容包装和过渡分支必须删除。
- 按闭环组织工作：基线与反例 → 存储提交/重放 → 输入准备/执行门 → 完成/恢复/清理 → 资源与呈现边界 → 组合验收 → 性能与交付证据。每阶段以行为证据准出，不按新增接口或文件数验收。
- 接收端保留完整来源与消息、精确整数身份和固定槽位；对重命名后同步失败保留不确定结果，不回退序号覆盖原件。准备载荷损坏、身份错配明确阻断，禁止重新盖章补救。
- 普通新增与内部恢复共享一个存储提交核心、使用不同策略；恢复从原文、索引、段信息及墓碑核对，缓存只作加速。补写、删除、压实发布与逻辑计数采用一致分区协调，失败时不猜测计数。
- **BREAKING（消费边界）**：一次有限拉取冻结一轮输入，A+B 为一轮，执行期间 C 留下一轮；保留原始接收集合和逐槽处置。全部选中输入提交成功后才调用模型，瞬时失败同批退避，确定冲突停止自动处理。
- 用当前调用及确切输入事件身份识别已提交的合并回显，取消整轮 user 消息跳过和失败后重新写合并事实的补偿路径。
- 完成结果先冻结并耐久保存，再以固定身份提交不进入上下文的处理回执，最后确认清理。启动直接核对未确认项，已完成项只补提交/清理；未确认输入事实与回执的保护在遗忘工作启动前恢复。
- 关闭入口统一同步；在途调用、生产者、引擎和存储按依赖顺序退出。无法证明旧代停止时，由原所有者保留资源和写锁，不依靠失去引用的句柄维持安全。
- 恢复提示只在实际模型提交边界消费；正常投影、在线恢复、冷启动使用一致的内部事件排除规则。
- **BREAKING（最新状态唯一运行）**：用户已允许丢弃过渡不兼容的旧运行数据。运行期只支持当前 inbox/准备/完成格式和最新接线，不保留旧协议读取、别名、历史确认或回退分支；切换时可在停止所有者并取得写权后，按明确受管目录清单清理不兼容数据并重新初始化，不要求排空迁移。正常当前格式的损坏/I/O仍走保留与报错，不以清理旧数据掩盖新缺陷。
- 修正测试替身、组合接线和证据记录；测量包装器不得伪造屏障能力。语义稳定后重跑完整离线矩阵，旧原始报告保留但不再用于耐久性能比较。
- **异步任务寿命（并入本变更，不起新档）**：以单一 TTL 回收器取代并复用 `task_job_deadline`、取消 `task_stale_after` 观测态——命令 spawn 定有限 TTL（可带 `ttl` 参数，否则配置默认，缺省 10min，无禁用哨兵），到期经 `Cancel()` 终止底层进程→failed 终态→reap→移出看板，覆盖全部 active 态（含此前不受年龄墙约束的 suspect 盲区）与全部寿命类（含 resident/interactive，常驻由模型自设 TTL 或重入续命）；`resume/send` 刷新 TTL、`peek` 不刷新；看板呈现剩余寿命并删除“需确认”式误导裁决邀请。`quiet_timeout`/fake-dead 保留为正交静默探测。
- **结算通知票据化折叠（并入本变更）**：批量退役折叠为单条汇总事件（N→1），`[task settled]` 结算 external_input 以有界可召回票据进入投影并可被压缩折叠，消除结构性不可回收死重；仅界定通知产生形态与可折叠性，不改通用压缩/回放算法与估值器（chars/token 建模仍另案）。

## Capabilities

### New Capabilities

- `async-task-lifetime`：异步任务单一 TTL 回收器（到期强杀、重入刷新、看板呈现寿命、取代 job_deadline/stale_after）与结算通知票据化折叠；复用现有任务层、看板与投影，不新增子系统。

其余复用现有信箱、事实存储、投影、资源管理和本地验证体系。

### Modified Capabilities

- `persistent-event-loop`：固定批次、完整接收、写前准备、提交门、精确回显、逐槽完成、直接恢复核对与可重试清理。
- `event-segment-store`：公共拒重与内部核对分离、非缓存提交判定、修复锁序、可靠计数、未确认恢复材料保护及能力保真。
- `event-sourced-projection`：可投影事实与内部记录分离、未完成输入重放的可见性，以及实际提交边界的一次性恢复提示。
- `runtime-resource-ownership`：同代完整依赖所有权、并发关闭结果共享、构造失败与启动保护登记、停止未确认时禁止新代。
- `resident-release-evidence`：按完整故障场景验收、精确测试故障注入、阶段证据及同语义性能基线。
- `async-tool-event-fix`：替换旧中途消费条款，在冻结批次消费时归一化角色，保留原始消息。

## Impact

- 基线：`HEAD=a16fdce90fec4395131d5f1410ff3d23f0d912cb` 加提案时工作树；已核对 29 个跟踪源码/测试文件变更及 2 个未跟踪测试文件，不能仅凭 HEAD 重现当前实现。旧计划与新提案目录不计入这些源码数量。
- 主要落点：`agent/`、`agent/reliability/`、`plugin/`、`event/`、`memory/` 及其装饰链，组合根与资源管理，`tests/`、`tests/offline_bench/`、`examples/wechat-bot/` 及现有架构/操作文档。
- 不新增依赖、消息中间件、第二套永久历史、全局事务或全历史去重表；保持事件主存储格式、分区权限、可选能力默认态。窄恢复/保留能力不扩张主存储接口，未启用可靠模式的自定义后端不被强制提供恢复能力。
- 不承诺模型、工具副作用或渠道发送 exactly-once；除结算通知的产生形态与可折叠性外，不扩展通用压缩算法、估值器 chars/token 建模、模型训练或生产部署。清理旧数据仅用于过渡，不是压缩优化，也不计为压缩率改善；日志快照与基准原始证据不在清理范围。
- **localfile 后端范围界定（本轮裁决）**：`LocalFileKV`（`type: "localfile"`）仅是**验证本可靠性协议跨进程语义的最小临时后端**，不提供生产级耐久性、安全或长期可用/可维护保障。它已回退为最小模型（内存 map + tmp/rename 原子快照，`Sync()` 为落盘屏障；无 fsync/掉电保证、无 WAL/compaction/损坏隔离/延迟刷盘机/故障注入钩子）。本变更**不对 localfile 做大范围保护性优化**；生产耐久与 fsync 两模式认证、掉电、长时耐久基准均**推迟至接线 rustviking 等专用存储引擎的后续阶段**。上层 `FileSegmentStore` 提交/重放/计数/租约等为后端无关能力，不因此缩减。
- 本次只创建替代工件、废弃旧执行计划并校验文档；不实施源码修复，不运行付费模型、真实渠道、生产升级、提交/推送或自动完成归档。
