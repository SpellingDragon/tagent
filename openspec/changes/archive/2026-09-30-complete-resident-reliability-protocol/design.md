# 常驻可靠性协议闭环设计

## Context

- 本计划替代 `fix-resident-reliability-boundaries`；旧勾选、注释中的“全绿”及摘要不是验收证据。现有未提交源码保留，不回退到旧提交重做。
- 提案时 HEAD 为 `a16fdce90fec4395131d5f1410ff3d23f0d912cb`，有 29 个已跟踪源码/测试文件变更及 2 个未跟踪测试文件。项目目录内实际 Go 为 1.24.1、darwin/arm64；脱离模块运行得到的默认工具链版本不能代替它。

| 资源已同代登记 | 共享引擎、一次性租约、同路径协调 | 完整实例关闭同步、停止失败时真实持有资源 |
| 提示已移出历史输入 | 临时请求材料方向 | 真正调用模型之前不能消费 |

### 深入分析发现的新问题

**问题场景**：旧细化方案计划在会话追加钩子中标记输入，再让持久化插件识别该标记。
**问题根源**：实际使用的框架 v1.10.0 先调用事件插件，再追加会话；该钩子晚于持久化。框架还会记录插件错误而继续，因此不能依赖插件返回错误阻断模型。
**影响范围**：精确回显、输入失败门、真实组合测试。采用下文“写入前识别 + 调用前提交门”，不沿用旧钩子设计。

**问题场景**：信箱重命名成功后目录同步失败，或者相邻的大整数身份参与 JSON 比较。
**问题根源**：当前失败分支回退接收序号，下一写可能覆盖原件；通用 JSON 解码为浮点数会丢失整数精度。
**影响范围**：接收、准备、完成的幂等比较与崩溃恢复。下文统一规定不确定写入与精确编解码。

## Goals / Non-Goals

**Goals**
- 已接收、已提交、已处理、结果已耐久、已清理五阶段互不冒充；外部送达另算。
- 一个有限批次、一个执行所有者、一个信箱恢复所有者；输入和结果都有可核对身份。
- 全文历史仍只有事实链；信箱只承载未确认材料，投影/计数/保留索引均可重建。
- 每一任务均验证至其消费终点；先防错误确认，再补恢复和关闭，最后测性能。

**Non-Goals**
- 不重写框架 ReAct、工具调度或压缩算法，不新增数据库、全局事务、永久提交标记及全历史去重表。
- 不保证模型、工具副作用或渠道发送 exactly-once；完成结果耐久前的执行可能重做。
- 不新增多聊天调度，不改变来源优先级、业务 Metadata 合并及权限；固定批次同时适用 volatile/durable。
- 不默认开启可靠模式、embedding 或治理；不扩大正常历史 TTL。
- 不操作生产数据、部署、付费模型、真实渠道或 Git 提交/推送；72h 长跑属于另行授权的发布门。

## Decisions

### 1. 一个协议所有者，按阶段结果驱动

在 agent 包内新增小型协议文件族（批次/输入提交/完成恢复），从 `event_loop.go`、`lifecycle.go`、`context_manager.go` 提取对应职责；不引入通用工作流框架。事件循环只调度，reliability 叶包只负责文件状态和屏障，memory 只负责事实及恢复能力，plugin 只负责框架事件存储与派生视图。

批次保存原始接收项、有序消息槽、selected/skipped 及原因、冻结事实、已成功投影集合、调用结果和待确认集合。准备/提交返回结构化结果及 error，不再以 bool、日志或第一条输入代表整批。错误明确分为可重试 I/O、不确定屏障结果、确定格式/身份冲突、取消；未知结果枚举按失败处理。

| 阶段 | 前进证据 | 失败行为 |
|---|---|---|
| 接收 | 完整快照及文件/目录屏障成功 | 不报告 accepted；不确定项保留并暂停该信箱接收至核对 |
| 准备 | 整批各 envelope 的准备材料均耐久 | 不写本批任何事实、不调用模型 |
| 输入提交 | 所有 selected 的 canonical 事实确认成功 | 原批次原身份重试，不调用模型、不取下一批 |
| 执行 | 一次业务 turn 的明确终态 | 取消保持未完成；模型/框架确定失败记 failed |
| 完成固化 | 每 envelope 的完整 completion 耐久 | 同进程保留已得结果，只重试结果写入，不重跑模型 |
| 回执提交 | 固定 key 的 canonical receipt 经重放核验与屏障 | 只重试回执，不重新执行 |
| 确认清理 | 删除及目录同步成功 | 保留清理账目和保护，重试清理 |

瞬时持久化错误采用 100/200/400ms、400ms 封顶、可取消的等待；不采用模型重试的有限次数作为存储失败清理条件。失败日志限频，diagnostics 暴露阶段、request ID、重试次数、末次错误和未确认量。确定冲突隔离原 envelope、停止该 agent 自动消费并报告，不继续后续批次制造输入缺口；不伪造业务 failed。

**理由/替代**：不采用各层单独补偿和“失败让插件再写合并输入”，后者改变身份与事实粒度。阶段可多于旧代码，但每一阶段只有一个 owner 和一种前进证据。

### 2. 完整快照与不可变准备材料

保留 inbox-v2 目录和 version=2。接收层验证允许状态、request ID、固定槽、source JSON 对象、消息非 nil、必要身份与时间；有效空消息可接收，但不把图片/音频等非文本载荷误判为空。所有已解码 JSON 动态数值使用精确数表示；64 位事件 key 不经 float64 比较。

prepare 增加显式 `prepared_version=1` 标记，放在 envelope 内，不创建 v3 或兼容读取分支。一次重写冻结整个 envelope 的 receipt key、所有槽位的完整 canonical fact；未执行的槽同样可有准备事实，但不提交。无准备材料的 pending 本就是当前协议的合法初始状态；已有 prepared/completion/receipted 却不满足当前格式的过渡数据不做迁移读取，切换时可按决策10清理并重新初始化。当前格式的损坏/身份矛盾仍保留隔离并阻断，禁止重新生成 key。

canonical fact 含完整规范化 Message（使用现有 Response 载荷及必要工具字段）、正文/摘要、源语义时间、固定分区、源事件 ID/request ID/slot、原始来源与业务 Metadata 的精确 JSON 快照。来源快照作为一个命名空间字段保存，不将任意业务键铺到受信控制键；键名集中到 event 包。业务送达仍消费原来源规则，不把内部路径和控制标记带出。

首次归因在准备前完成：当前批次来源/业务 Metadata 按现有规则解析，session/bundle 等在首次准备时冻结；重试不读取新的时间、配置或归因重盖。恢复只核对不可变身份、来源和完整载荷，不用新版本摘要算法重算比较。规范化只改副本，原始 system role 不变，模型侧仍按外部输入处理。

所有写原语共用三态结果：未发布失败、发布后屏障不确定、已耐久。序号分配后永不回退，允许空洞；重命名后目录同步失败保留文件和身份，登记未决容量，不能以同序号覆写。相同 prepare/completion 重试也必须完成所欠屏障，不能因文件内容相同提前成功。临时文件使用唯一名，启动只处理确属该信箱的残件并留痕。

**理由/替代**：保留一种 v2 协议及明确准备版本，不猜迁移已丢失信息；精确类型解码/规范化比较取代通用浮点 JSON 比较。接收错误不承诺“从未发生写入”，不确定结果明确暴露。

### 3. 存储提交核心：证据独立于缓存

普通新增与内部重放调用同一提交核心，区别仅为策略：普通新增遇现有身份返回 duplicate；内部恢复允许相同 canonical 内容补齐。主 MemoryStore 接口不扩张；保留窄重放能力，新增可递归校验的恢复能力声明及 key 保留租约。包装器必须检查 inner 的真实能力，不能只凭外层方法集过门。

提交在分区 mutation 锁内完成：校验 key/分区/事实身份 → 查持久墓碑 → 精确查 idx/evt/必要 meta → 补写 → 后端屏障 → 发布缓存和计数。读取 I/O、损坏载荷、不同内容与合法遗忘均为明确错误。非零错误不返回可用 canonical fact。

- idx 存在：核对其真实槽和槽内身份；evt 缺失时在该槽补齐；meta 不论 seq 是否零都验证，已有层级/封口不无条件重置，必要时间边界只能保守扩展。
- idx 缺失：恢复路径扫描 key 放置时间窗及该分区已登记段；同 key 原槽复用，双层相同记录按既有高层优先规则选择，不写第二原文；不同内容冲突。原窗 meta 也缺失时仍查原窗，不仅依靠段目录。
- 全部存在且内容一致：仍执行屏障，返回 already；缓存冷热不影响结果。
- 无现有记录且无墓碑：在新槽提交，返回 new；存在不完整记录返回 repaired。二者均不是“应当计数 +1”的直接指令。
- 公共新写正常路径不扫描全历史；较贵定位只在内部恢复、窗口首次恢复或不确定修复执行。

每分区维护 count/known。正常新提交且 known 时 +1；重复核验 +0。可能影响持久状态的失败将该分区标 unknown；恢复屏障成功后在同一协调范围重算该分区的完整、可发现、未墓碑、去重 canonical 集合，成功才恢复 known。部分扫描报错不能返回精确数；unknown 暂停该分区容量淘汰，不放宽 TTL 或影响无关分区。

删除、墓碑发布、封口及压实最终发布/清理均接入同一分区 mutation 锁，重算使用同一可见性定义。先采用分区级串行协调实现正确性；跨分区并行。锁序为资源路径协调 → 短 registry 账目锁（不做 I/O）；存储层为分区 mutation → 段状态 → 底层 KV/墓碑，旁路 callback 在 mutation 锁释放后执行，禁止反向获取。压实搬迁不改变逻辑计数。

容量提示改读取已知绝对分区计数，不再把 repaired/重复事件视为新增增量。索引以 key 幂等更新；feedback 属尽力旁路，只在本批首次成功处理新输入时发起，不能被当成确认凭据，不承诺其跨崩溃恰好一次。

**理由/替代**：拒绝以 LRU、永久提交表或每次新写全库扫描判断成功。存储事实关系负责正确性；缓存和派生计数负责性能。

### 4. 冻结批次与写入前的精确回显识别

一次 Pull 最多 32 个 envelope，立即冻结原始集合。原集合不被 meditation 过滤覆盖；处置在其上另行计算，保持既有来源优先级与 Metadata 后者覆盖规则。无有效 selected 时直接生成全 skipped 结果，不写输入事实、不调用模型。有效非文本载荷必须留在事实与实际请求中，不能因驱动文本为空跳过。

准备整个批次成功后按接收序提交 selected；所有成功后才建立执行凭据并进入框架。可靠模式所有外部输入都经信箱，不保留 volatile/durable 混合旁路。volatile 保留原非耐久承诺及插件写入路径，但采用同一冻结调度边界；不把此改动扩大为 volatile 持久事务。

精确回显使用调用级 typed ctx，不写 StateDelta 控制键：每次 runner 尝试生成唯一 request token，通过框架 RunOptions 传入；凭据持预期 agent/session、合并 Message、该批已提交 keys。MemoryPlugin 在任何 key 分配/写入之前，核对 request token、根 invocation（无 parent）、事件 InvocationID、author=user 和规范化消息；首次匹配绑定该确切 Event.ID。只有同一调用的该 Event.ID 可跳过重复存储，其他 user、子调用、assistant/tool 均走正常路径。同业务 turn 重试创建新尝试 token，重用同批事实；凭据随调用结束释放，无全局或“第一条信封”状态。

若预期回显未绑定、字段不匹配或插件记录错误，调用级凭据置为拒绝，模型提交边界检查该状态并中止。不能只返回插件错误：实际框架会记录错误后继续。会话追加钩子只做既有投递，不承担写前标记。

投影消费返回的 canonical fact，不使用当前事件重新派生摘要/角色/时间。批次进入执行前幂等补齐选中事实的引用，包括恢复时未被 snapshot/tail 包含的旧 key；已存在引用不重复，普通已完成历史不因重放重新展开。本批记录已投影集合，后续模型重试/压缩不重复插入；不引入全历史 seen 表或独立快照。无法取得必要输入事实时拒绝执行而非注入空上下文提示掩盖失败。

**理由/替代**：不用会话追加后的标记、不按整轮角色跳过、不靠相同文本永久去重。该调用链顺序必须由真实框架管线测试锁定。

### 5. 完成事实与可重试清理

执行返回结构化 attempt/turn 结果，分别观察启动错误、响应内错误、正常流结束、取消和现有退化重试；保留原传输重试上限与退避，不新增业务 turn。最终正常完成记 completed，确定模型/框架失败或重试耗尽记 failed；无终态的关闭取消不生成 completion。完整失败是处理结果，不是送达证明。

completion_version=1，字段包括 request ID、固定 receipt key、首次生成的完成时间、batch_result（completed/failed）、有界错误摘要、有序 slots；每槽含 slot/source ID、processed 或 skipped，processed 对应精确 fact key，skipped 有稳定原因。结果内同时冻结完整 receipt FullEvent（含首次归因）；重启不得用当前时间重建回执。所有槽恰有一个处置，且 processed 的事实已核验。

提交次序：冻结内存结果 → RecordCompletion（原文件耐久）→ ReplayEvent（固定 receipt key/完整回执）→ RecordReceipt → Ack。任一步失败在同进程只重试该阶段；即便 completion 首次写失败也不能重新运行已结束模型。崩溃且未留下耐久 completion 时允许重做，明确外部副作用可能重复。

RecordReceipt 必须要求合法 completion 与已核验回执凭据；删除旧只凭 request ID/描述字符串确认的路径。receipt 不进入普通投影、召回和 embedding，正常提交、在线 spill 回补、冷启动三条路径使用 event 包单一投影策略（接受当前类型及必要元数据，不反向依赖 memory）。当前内部记录的排除是业务规则；只为已淘汰历史快照/旧标记而存在的排除分支随决策10删除。

清理账目在 unlink 前登记 `{path, request_id, retained_keys, phase}`；unlink 成功但 dir sync 失败保留它，不减容量、不释放保留。重试遇文件不存在仍 sync 目录，成功后只释放一次。重复确认已清理项幂等；未知路径不能减少账目。nextClaimable 不偷偷删除 receipted 文件，统一交给恢复/清理所有者。

冷启动先完成信箱目录屏障和只读清点。文件存在则按 completion/receipt 核对后续清理；文件不存在且目录屏障成功则已无需保护。不得用不存在文件的路径重建无凭据确认。

**理由/替代**：保存具体终态而非“执行过”的标志；保留小型未完成清理账目，不新增永久确认库。一次回执写成功绝不抵消输入提交失败。

### 6. 恢复材料保护、启动次序与生命周期对齐

仅保护 receipt 不足以保证任意长的未完成输入可重放，因此保护集合包含尚未确认 envelope 的 prepared fact keys 和 receipt key；普通 mem_spill 的待重放 keys 也属于其自身恢复 owner。保留是从现有恢复文件派生的 key 租约，不持久化第二张保留表；空间与 outstanding 材料成正比，不随全部历史增长。

- fresh prepare：先登记 key 保留，再写准备文件，再提交事实；不确定写保留租约至核对，失败不提前释放。
- 在保护期内 TTL/容量/内容降分辨率/墓碑最终清理不能移除或改写所需原文；允许无损压实搬迁。显式删除返回 protected 冲突，由操作者先处置恢复材料，不静默绕开。
- 启动：组合根按实际共享 store 汇总当前配置各 inbox/spill 目录 → 取得写权、打开 backend、恢复墓碑与计数（不启动遗忘者）→ 精确清点材料并登记租约 → 直接核对 completion/receipt → 重建普通投影及本次待处理引用 → 接线引擎/回调 → 启动扫描器及接收。执行壳复用常驻能力，不重复登记。
- 已运行 store 新增共享 owner 时先取得恢复登记屏障，暂停该 store 遗忘发布直到新目录登记/核对完成；已被合法删除的历史拒绝复活，不能靠补写假装恢复。某一目录无法读取时不开放该 store 的遗忘/新接收，报告阻塞。
- Ack 的目录同步成功才释放该 envelope 的全部租约；普通历史按原类型 TTL，receipt 按原 30 天年龄窗口，不重新盖时间延长寿命。进程停机不等于 Ack：共享 store 仍存活时未确认保护须保留在资源 owner，不能随 agent 关闭释放。
- 墓碑存在时重放明确返回 forgotten/conflict。保护保证受支持的 outstanding 自动重放不与合法 GC 竞跑；恢复材料已清除、墓碑已物理回收后的任意手工历史重放不属于自动恢复承诺，不为它新增永久墓碑或去重库。

恢复逐 outstanding envelope 精确查询固定 receipt key，不从投影扫描收集“已完成 IDs”。查询 I/O 阻断该项；不匹配隔离停机；有 completion 无 receipt 只补回执；两者匹配只清理；仅有 prepared 则重试原输入。没有 completion 却已有 receipt、receipted 但缺匹配结果等矛盾状态拒绝自动处理。

**理由/替代**：从未确认材料重建有限保护，复用存储生命周期；拒绝“扫描器先启动，稍后补 pin”和“关 agent 即释放 pin”的时序假设。保持历史真源和正常遗忘策略不变。

### 7. 同代所有权补齐到完整实例

保留当前资源 registry、一次性租约和 per-key 协调，不另建引擎生命周期表。Start/Stop/Close 共用明确状态（new/running/stopping/closed）及完成信号：首次调用执行关闭，其余等待同一个结果；WaitGroup 登记先于可并发停止的发布，异常退出也更新状态并恰关一次输出。

关闭顺序为：拒绝新接收/新调用 → 停消息生产者 → 取消并等待所有在途常驻及 one-shot/子调用 → 关闭 runner/执行代 → 释放根资源租约；最后租约再停扫描/压实 → 停并等待 engine → flush/close backend → 释放写锁。轨迹记录器在 runner 停止后 flush；已注册资源不能在普通 closers 和资源 owner 两处重复关闭。借用执行壳不取得共享资源释放权。

无法确认 worker/backend 停止时，registry 保留 poisoned entry（含 store/engine/锁文件强引用与失败结果），同路径 acquire 明确失败，不把“故意丢失句柄引用”当成持锁机制。已证实停止而最终 flush 失败仍返回错误，不宣称耐久成功。构造每成功获得资源即登记逆序回收，覆盖屏障/能力/引擎接线失败；无法安全回收同样保持 poisoned。

**理由/替代**：一次性释放只解决引用计数，不代替完整关闭；拒绝按 active 布尔跳过等待，也不靠重新构造组件掩盖 owner 错误。

### 8. 实际请求边界、恢复提示与热更

在 agent 内提供小型模型提交装饰器，状态通过当前调用 ctx 指向常驻恢复状态；冷启动和热重建的模型装配共用它，压缩摘要模型不注入。其职责仅为：检查当前调用执行凭据/取消状态 → 复制请求消息切片 → 在全部装配回调之后追加待显示恢复提示 → 原子消费提示并立即调用被包装模型。实际调用边界定义为进入被包装模型方法，不宣称网络送达或模型理解；进入后 provider 失败不要求重发。

同时保留 Model/IterModel 的真实可选能力：支持 iterator 的底层使用 iterator 适配器，不支持的不伪造能力；惰性 iterator 在实际开始迭代时才检查/消费。Info、关闭所有权、流及错误原样透传，不新起后台 goroutine。并发调用对同一恢复状态最多一次消费，取消/短路且尚未调用底层不消费。

常驻、volatile、one-shot、执行器热更都验证该边界。提示不经过输入事实存储、不进入投影/回执/重启历史，diagnostics 的恢复状态持续可查；full/正常空库不追加提示。无法通过实际框架能力测试时停止本阶段，不退回装配阶段提前消费。

**理由/替代**：最后一个 BeforeModel 回调仍可能被框架后续短路，不等于实际调用；选择已有模型接口的薄边界，不重写 runner。

### 9. 证据驱动的阶段准出

tasks 中所有复选框初始未完成。每项完成证据包含：当前基线反例（应失败但尚未运行时记待复现）、修改前后断言、实际命令/退出码、完整日志位置、源文件→单元/组合/消费者测试映射。复合任务的所有条件成立才勾选；不以删除断言或改为错误契约来“修复测试”。

测试替身同时截获普通写入与显式重放，可按输入/receipt/屏障独立故障注入。组合测试使用同一实际 agent/context、localfile、真实 runner/插件和 mock 模型/渠道；用 channel/屏障控制 A+B 已进入执行、C 后到，不以 sleep 保证顺序。进程测试通过子进程 failpoint 直接退出，不经 Close，父进程独立 reopen 对账。

关键窗口：接收临时写/rename/dirsync、claim、prepare、任意一条输入事实、模型返回、completion、receipt、unlink、dirsync。核对 accepted ID/源消息槽/原文/身份/投影/实际请求/处理结果/模拟投递及存活计数，不将缓存读回替代独立重启。根模块和 wechat-bot 独立模块分别 build/vet/short；受影响包全部定向 race，未知失败保留未决，不能因下一次绿而称 flaky。

基准包装器用明确含 Sync 的底层类型并透传分区枚举与错误，不提供 no-op fallback。**localfile 已回退为验证用最小后端（无 fsync/WAL），本变更不对它做生产耐久认证**：验收仅通过单事件无 Close 子进程读回＋Sync spy 在 flush-only 语义下证明提交屏障真实原子落盘、新进程可读到原文/索引；完整的 1k/10k/100k × fsync on/off × 并发耐久矩阵及 fsync-on 模式认证**推迟至接线 rustviking 等专用存储引擎的后续阶段**。报告仍记 commit+dirty diff、实际工具链/OS/文件系统/配置、Sync 次数与完成状态，Go 内存不称 OS RSS，保留旧 JSON 并撤销跨屏障语义比较。正确性组合门必须先全绿；它不依赖被移除的耐久机（上层提交/重放/计数/租约为后端无关能力）。

**理由/替代**：验证单位从“函数有测试”改为“故障场景能收敛”；CLI 工件齐全仅表示可开始实施，不是实现验收。

### 10. 最新运行态唯一入口与过渡数据重置

本次涉及的接收、准备、提交、确认、恢复、投影、资源关闭及组合接线在交付时只保留当前实现。建立淘汰清单，逐项删旧协议解析、旧控制键别名、旧确认接口、仅用于兼容的发布包装、缓存/普通写弱回退、重复owner、历史快照补丁及其仅证明旧行为的测试；所有真实调用方更新到当前契约。保留正常volatile模式、当前版本I/O恢复和当前内部记录规则，它们是产品能力，不是旧版兼容。

运行期只验证当前版本结构，不实现按旧版本分发的迁移器。过渡时不兼容的数据可直接重置，不以排空为前置：实施时先列出精确canonical受管路径及依赖关系，停止相关所有者并取得独占写权，再清理受影响的旧运行状态。信箱、未完成结果、相关事实存储和派生索引必须按一致恢复单元处理；不能只删部分依据留下指向已删历史的引用。能验证仍符合当前契约的事实可保留，无需为兼容增加分支。

清理清单排除源码、配置、凭据、文档、远端日志快照及基准原始证据；不得宽泛删除整个workspace。路径未知、包含非受管内容、仍有存活writer或操作目标为未授权远端/生产环境时停止并说明，不能用本裁决推导任意路径删除权。当前格式数据损坏、目录不可读、普通I/O失败不触发自动重置。

准出包括静态淘汰清单零遗留与动态启动测试：全新状态启动、兼容的当前状态重启、不兼容状态经显式重置后的启动均只进入最新协议；旧目录/旧标记不被读取、不触发旧分支。用最新版本写入的新数据仍必须通过全部耐久/恢复验收，不能靠清空数据通过故障测试。

**理由/替代**：用户已接受过渡数据损失，故选择一次性重置而非长期维护兼容读取；不将过渡工具和策略带进每次正常启动。

### 11. 单一 TTL 回收器取代重叠年龄墙与 suspect 盲区

现三套年龄机制彼此割裂且留盲区：`task_job_deadline`（默认关，仅 gate `alive_detached/stale`+`detachedAt≠0`+LifetimeJob）、`task_stale_after`（1h 仅观测不杀）、以及 `suspect`（running→静默、从未 detach）不受任一墙约束。实证：远端 09-17 快照 `56bf24c3`（`restart-tagent.sh` 换装作业）以 suspect 态滞留看板 21h→23h，配了 8h deadline 也不放行，逼模型逐回合“维持原判…不处理”空转十余次。

统一为一个 TTL 回收器：命令 spawn 定有限 ttl（入参 `ttl`，否则配置默认=复用并更名的原 job-deadline 槽，缺省 10min）；无 0/负/无限禁用哨兵，回收器恒开。到期动作=owner `detector.Cancel()` 杀底层进程/会话→failed 终态→reap→移出看板，复用既有退役通路（finalizeRetired/SettleFailed），不新增第二清理所有者。准入 MUST 覆盖全部 active 态与全部寿命类，特别把 suspect/未 detach 纳入，堵死盲区。寿命归模型：resident/interactive 不享豁免，需常驻者设大 ttl 或经 `resume/send` 重入续命；`peek` 只读 MUST NOT 刷新。一次性无会话命令锚点恒为 spawn，正常 settle 即老化移除、TTL 不放行。

**理由/替代**：不并存 TTL+job_deadline+stale_after 三墙（增熵、语义重叠、留缝）；取消“resident 永不自杀”不变量因其正是本次病灶，责任改由显式 ttl 承担，契合“最新态唯一、无弱回退”。

### 12. 看板呈现寿命与结算通知票据化折叠

看板 MUST 每行给出 TTL/预计回收时刻（或剩余寿命），并删除 `⚠…需确认` 这类诱发模型反复仲裁的非终态邀请；到期/终态不再渲染。看板仍每回合重算、注入尾部、不落库、不参与压缩。这把“该不该收”的判据交给呈现面，模型看一次即定，终结逐回合空转与由此产生的 assistant_output 历史污染。

结算通知折叠：`[task settled]` 类 external_input 是压缩 floor 抬到 96–99%、回收率衰减至 1–4.5% 的结构性死重（远端 24h 基线回执独立佐证）。批量退役 MUST 合并为单条汇总事件（N→1，已实现 `newBatchRetiredSummaryEvent`，需确保覆盖所有退役来源）；每条结算 external_input MUST 以有界票据（事件键 + 受限预览，全量体按票据在事实链可召回）进入投影，且压缩 MUST 能将其折叠回收——纠正“折叠不覆盖 external_input”。这只界定通知产生形态与可折叠性，不改 SmartCompress 通用算法与估值器；chars/token 建模与 estimator 仍另案。

**理由/替代**：不新增第二套投影或永久提交标记；票据化复用现有事件键与 spill 机制，只补齐折叠覆盖面。

### 13. 提交核心耦合簇：§2.2+§2.3+§2.4 不可拆，oracle 由规格钉死

Code review #1 暴露的冷缓存/重启双计数，正解不是“先做 §2.4”，而是 **§2.2+§2.3+§2.4 作为一个提交核心簇一起落**。理由（据 `event-segment-store` 规格逐案核验）：

- **计数真源 = 完整记录**（原文+索引身份一致、排除墓碑、去重）；「缓存/replay 分类/引擎回调均不能作为计数真源」（spec L5/L7/L19）——直接否定现 `completeOrphanCommit` 的 `s.cache.Get` LRU-oracle。
- 若**仅**把判据换为“完整记录→`AlreadyCommitted`(+0)”：case C′（`finishCommit` 写 idx 后、`Sync` 前/计数前崩溃→盘上 idx+evt 齐但未计数）会被误判 +0 → **进程内永久少计**（重启 rebuild 前）。当前代码靠 cache-miss→repair→+1 兜住 C′，换 oracle 即丢此保障。
- 规格对 C′ 的正解是「不确定提交经成功屏障后 **MUST 在一致分区协调范围重算该分区**」（spec L7）——而“协调范围”就是 §2.2 的分区 mutation 锁。**故 §2.4 的正确分类前置依赖 §2.2，§2.3 三类补齐（idx有/evt缺、evt有/idx缺、meta缺）是同簇。**
- 三者共享同一提交/对账路径与同一组测试（barrier/orphan/rebuild）；拆开会留下 C′ 少计或并发窗口，违反 line 251「依赖不满足则暂停该阶段并回报，不增强回退」。

**定序**：2.2（分区 mutation 锁 + 出锁回调 + 分区重扫对账助手）→ 2.3（三类补齐复用原槽/原窗）→ 2.4（去缓存、按完整记录分类 + C′ 走协调域重扫 + 墓碑不复活）。设计已由 spec 钉死（M 锁序 + 完整记录 oracle + 受影响分区重扫），**非开放项**；实施前唯一须确认的是**授权承担这一全计划最大/最高风险单元**（触及异步 compactor 发布与投影 F4 不变量）。

### 14. 跨代键地板与确定性冲突隔离（§8.5 三十轮重启终门逮住的产品缺陷补记）

雪花事件键秒粒度时间戳 + 进程内序号使同秒重启的两代进程必然撞键：冻结键 replay 永久 CONFLICT，未确认信封陷入活锁——违背"重启后所有输入四态可归类"的核心不变量。三层收口（均为本设计既有机件的补全，非新协议）：

1. **键地板（RaiseSnowflakeFloor）**：持久观察到的最高事件键反向 seed 进程内单调守卫，单向抬升、同秒序号耗尽进位——恢复的代只会在历史之上发号。构造时序注记：seed 挂在 RebuildLiveCounts/冷启动全量扫描（wiring 必经路径）顺路完成，零额外 I/O。
2. **确定性冲突归类**：`persistBusEventCommitted` 把存储裁决分两类——CONFLICT（同键异内容）/FORGOTTEN 为**确定性**（重跑必然同样失败），瞬态 I/O 为**可重试**。旧 bool 契约把两者混为一谈，是活锁的直接成因。
3. **协议隔离层**：确定性冲突走 quarantine（信封隔离、claim 释放、错误上报），与"当前格式损坏保留证据"同构；可重试仍走退避。隔离≠丢弃：材料保留在 quarantine 供人工处置。

未采用的替代方案：改键位布局（pid 加大/毫秒粒度）或持久化序号——都触碰冻结键的磁盘格式不变量（prepared fact 的 key 已耐久），代价与迁移风险大于收益；同秒双活 writer 场景不在本能力范围（单 writer 由 runtime-resource-ownership 的 flock 前提覆盖）。充分解（位布局级）仍归 rustviking 阶段一并裁决。

### 压缩问题的证据更新与范围

上一轮记“9月83条gzip原包尚缺”。本轮经 Agent Mail 已取到该包（`att-traj2h.gz`，83 条/batch 187–269/09-17 16:43–18:43）并据实核验：看板逐回合重渲染未回收的 suspect 任务（`56bf24c3`，21h→23h），模型逐回合计十余次“维持原判…不处理”；远端同期 24h 基线回执独立确认压缩回收率由 27.8% 衰减至 1–4.5%、floor 升至 96–99%，归因为“换装/zombie/退役的 `[task settled]` 合并 external_input 结构性不可回收”。两者同根：结算死重与失效任务噪声。

本次因此纳入：TTL 单一回收器消除失效任务反复呈现（决策11），看板呈现寿命删除误导裁决（决策12），结算通知票据化折叠消除结构死重（决策12）。仍不承诺触及估值器 chars/token 偏差（历史大上下文 est/real 中位 0.846）与通用压缩算法——那部分另案；清理不兼容旧数据致上下文变小也不计为压缩修复。前后效果须同配置、同输入、同链对照。

| 长期未确认材料占用空间 | 只保护 outstanding keys，容量满明确拒绝；不偷偷 TTL 清理未完成输入 |
| shared store 启动保护协调复杂 | 组合根统一目录清点及启动屏障，late attach 单独测，不靠注册顺序碰巧 |
| 内部回显依赖框架事件顺序 | 已核对当前 v1.10.0；真实管线钉测守护，升级失败即阻断 |
| 模型包装器隐藏可选能力 | 双适配器保留实际 iterator 能力、覆盖热更/取消/流式测试 |
| 不兼容过渡数据丢失 | 用户已授权重置；先核验受管路径与一致恢复单元，不保留旧读取分支，证据和配置不清理 |
| 到期强杀误杀真·长任务 | 命令须带足够 ttl 或较大 quiet_timeout；TTL 与静默探测正交；正常完成先 settle 不放行 |
| 取消 resident 永不 auto-kill 不变量 | 用户裁决寿命归模型自设；需常驻设大 ttl 或重入续命；工具描述与文档同步教导 ttl 语义 |

### 架构不变量与运行时五轴

| 维度 | 约束 |
|---|---|
| 真源/执行权/默认态 | 唯一历史为事实链；信箱只 outstanding；任务寿命真源=唯一 TTL reaper（持执行权杀进程），看板只读呈现不持执行权；外部操作仍经宿主授权，可选默认不变 |
| 到达消费者 | 源消息→冻结事实→提交→可见投影→实际请求→原路由→模拟发送/扣留；receipt 不证明送达 |
| 不可见边界 | 空/非文本/过滤/损坏/取消/短路均显式；不能只验证数据写进文件 |
| 热路径 | 不在 BeforeModel 扫信箱；普通写不扫全历史；恢复扫描仅受影响分区，保护表无历史积累 |
| 重启 | 空内存恢复固定身份、结果、保护及清理状态，不使用旧缓存/旧投影 |
| 构造/关闭 | 保护登记早于遗忘、依赖齐备早于生产者；关闭等待消费者，失败仍保有 owner |
