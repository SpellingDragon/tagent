          d.retained = append(d.retained, notice)   ← 注入删这行
          d.mu.Unlock()

      }
      缺陷语义：通知在 follow-up turn in flight 期间到达时被丢弃而非保留。
新锚：settle_turn.go — G6b 后 retained/firing 机制整体删除（grep firing|retained 0 命中），
      "保留"的实现=mailbox 账面 + 观察 wake + drain 回读自愈循环。注入改为断掉 busy 通知
      的全部保留路径（4 补丁一组，同应用同复原）：
      P1 ObserveCommit：pump driving（busy）时吞掉 wake（不入 wakeCh）；
      P2 SettleDriver struct 加 busy 字段；
      P3 drain() 置 busy=true（defer 清零）——"pump busy"=正在驱动本轮；
      P4 drain() 自愈回读截断（`if !worked { return }`→`_ = worked; return`），
         一轮驱动过即回，不再回读账面。（第一版 P4 反转退出条件为
         `if worked { return }`，空轮永不返回成死自旋，-race 下挂死被判
         not_killed(timeout)；改为无条件单轮返回后同语义无自旋，实测 killed。）
等价理由：缺陷语义完全同构——"通知在 follow-up turn in flight 期间到达，被丢弃而非保留"。
      旧保留机制=busy 时入 retained 等 firing 完再放；新保留机制=通知入 mailbox 账 +
      观察 wake + drain worked 回读。注入恰好断掉两条保留路径（wake 被吞、回读停止），
      busy 通知留在账面无人消费=丢。杀伤路径：B 在 A parked 期间 settle → wake 被吞 →
      A 结束后单轮回读不发生 → requestB 永不出现 → continuationWaitForRequest 30s 超时
      红在 "no request carried the notice material"。负锚 busy_notice_not_dropped 不变。
      （旧单补丁"删 retained append"在新架构无直接等价单点——retained 面已删除；
      注入形态随之重构为多补丁组是机制降解后的必然，缺陷主张本身一字未动。）
