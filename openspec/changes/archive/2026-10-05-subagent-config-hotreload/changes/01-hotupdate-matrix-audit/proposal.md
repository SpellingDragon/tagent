# Proposal: 01 热更矩阵审计与契约化（hotupdate-matrix-audit）

## Why

一级 D1 走查已定谳大格局（fp 代际面 + 源拉取面双通道已归一），但**逐维度的消费点证据**尚未系统化：哪些维度"机制在而契约测缺"（回归保护空窗）、摘要 knob 的配置位置与通道归属（域 02 的唯一前置事实）仍待实证。审计是全族的地基——"源里有但消费点没读=假热更"这一红线须以矩阵+测试钉死。

## What Changes

- 产出**维度×通道×消费点×证据**矩阵（矩阵即 spec：入 config-hot-reload delta，维度枚举含 prompt/tools/模型 ID/provider/端点/上下文预算/keepRecent/双 TTL/**摘要策略**/生成参数/路由）。
- 为"机制在而契约测缺"的维度补消费点契约测（`OrgBudgetLine` 式断言先例）。
- 实证摘要 knob：其配置在 schema 何处、今日经哪条通道（或两不沾）、热变更今日的实际行为——产出域 02 需要的接口常数（字段名+解析点+消费点）。
- 生成参数与路由两项"不做"的实证注脚（fp 覆盖证据各一条，供否决区追溯）。

## 边界与依赖

- **依赖**：无实现依赖；仅读代码+写测试。
- **被依赖方**：域 02 依赖本域产出的摘要归属结论（接口常数：字段名、解析点、消费点——以矩阵行+spec delta 形式交付）。
- **接口面**：矩阵 spec delta（config-hot-reload ADDED 需求）；不新增任何 API。
- **禁止事项**：不改生产代码（测试除外）；不触碰三禁区；不预支域 02/03 的实现。
