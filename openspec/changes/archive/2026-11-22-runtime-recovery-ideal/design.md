# Design：按语义单元收敛现有候选

## D1 权威、目标与证据状态

本轮用户要求是重写计划，先审查错误前提和过度实现，再确保执行遵循到位并干净收工；不是授权立刻改产品或发布。当前源码候选为 `7b0cde162627ad37f1d364bbf3508b3bd0518431`，真实 PR 基线为 `90fecc56698a5f87399794350a43cddaa880a97f`。开始实施时重核两者及工作树，不能把当前 SHA 或临时目录当永久环境。

权威顺序：用户已确认的行为目标与本轮范围 → 可核实的协议/生产行为 → 通过设计门的选择 → 测试/规则/旧台账。规则用来发现偏离，不替代设计推导；旧注释、已勾选、实现者汇报、局部绿和本计划中的候选修法都不能自证正确。

| 证据等级 | 本轮含义 | 可做什么 |
|---|---|---|
| 已确认的目标 | 用户明确要求的不变量和行为 | 保留；缩减须明确决定及后果 |
| 代码反例候选 | 已读路径可构造失败，但尚未运行相应交错 | 建最小反证，不先派修复 |
| 已复现缺陷 | 正式入口、非空前提、期望/实际、原始退出码和源码绑定齐备 | 进入设计比较 |
| 设计建议 | 减少结构的候选方向 | 与保留方案同尺比较，不默认采纳 |
| 已驳回怀疑 | 前提已被当前源码或实验推翻 | 记录反证，不为它新增机制 |
| 历史凭据 | 旧提交或已消失制品的结果 | 追溯用，不能给当前候选放行 |

### 定义完成判据（P0–P8）

本节是判据源：`golden/runtime/dod_predicates.json` 的 `criteria_source` 从这些条目读判据集，registry 只负责把每条判据绑定到量测。判据条目丢失即判据失守（`check_dod_coverage.py` 具名拒绝），条目文字承接自重整前的判据源，标题与 registry 的 `criterion` 逐条对齐。

- **P0 三挂点动态拓展（核心，golden）**：所有特性经三挂点/插件注册表动态挂载，装配根不认识特性名（无具体类型硬编码）；plugins: 声明真消费；动态拓展性立为 golden 不变量＋门禁（硬编码即红）。
- **P1 单一真相**：链唯一真相，一身份一不可变事实，SHALL NOT 删/改已提交事实；逻辑链恒完整、恒可按身份重放。
- **P2 单一 g(x)**：运行与恢复使用同一状态应用规则，保持事实提交顺序及身份语义；无检查点时从零恢复，有检查点时按该消费者已陈述的状态恢复尾部。投影摘要不替其他消费者担保已处理进度，不新增恢复专用的第二派生逻辑。
- **P3 全部托管**：所有可恢复态经 Stateful 切片托管；任务、审批和压缩各自声明未完工作及按身份读取的历史，不把全历史复制进当前态，也不删除历史决定换取有界。
- **P4 恢复成本与增长归因**：量测boot解码事件、索引读取与常驻规模、任务加载及墙钟，消除已结历史引起的重复重建和全状态复制。已裁定保留的完整帧校验按O(日志字节)独立计量；确需历史查询的成本归索取者并显式声明。总墙钟和长期运行仍有真实验证，不以某项计数为零声称全部启动有界，也不把未归因增长自动归入已接受成本；09.R2先校准计量并构造回归反例，不静默放宽1.3×判据。
- **P5 契约一致**：主 spec 与代码同向，legacy 条款清零，golden 同步。
- **P6 无死代码**：死生产者删、未接线脚手架接线或删、废弃 spec 退役。
- **P7 模型自主消费**：中段过程呈现为可召回 event_key 票据（[evt_KEY|type]），模型经 recall_get 自主取全文，框架不喂摘要；老段摘要是模型产出（压缩消费插件）。
- **P8 压缩可配置**：摘要预算可配置（非硬编码 2048），压缩消费是动态插件，摘要请求经租约＋声明采样参数。

## D3 依赖与阶段

- 第一道入口 `13.101`：确认原问题/能力边界、当前候选与环境、旧项承接和最小场景；未通过时只允许必要只读取证。
- `12.101`、`06.101`、`13.102` 是反证/设计输入，可在明确隔离的测试产物与读取边界下并行。先跑最小可证伪路径，不因计划大而先铺通用框架。
- `12.102` 与 `06.102` 消费两侧取证及 `13.102`，分别冻结选择；共享提交位置/格式/原文身份要同一条签发记录，无双方各写一版。
- `12.103`、`06.103` 依赖两侧设计门；写面相交或构建读取相交时串行，不把“图无依赖”当并发许可。
- `12.104`/`06.104` 收口领域与产物；`13.104` 再收口插件/公开能力；`12.105` 交付真实恢复分支，`06.105` 签收后验证完整行为与成本。
- `12.106`、`06.106` 独立审通过，与 `13.105` 的规格/旧项对账会合到 `13.106`，再进 F1–F4。

波次只是汇报分组；本项目采用同一候选工作树集成，前置是指定叶有同候选通过证据并经独立核销，不是等本PR先归档或先合入main。跨变更不允许互等归档，真实共同前置在13.101/13.104列明。

## D4 设计选择与实施签发

每个设计门至少比较“保持现状并限制声明”“最小修正”“删除/合并一层”；只有既有方案无法兑现目标时再比较更换实现/成熟库。比较表逐项列独立业务消费者、全部结构角色、提交/失败/恢复语义、状态与字节副本、配置/格式迁移、实际成本、测试与运维负担、可反转探针。行数和方法上限不是选择依据；缓存不因存在就判第二真相；新机制要使全链路更简单，而非只让当前一门转绿。

### 实施签发记录（当前均未签）

实现叶派发前，由编排者在其 owning design 的签发区填完：候选源码指纹；已证缺陷/已驳回项；所选方案与否决理由；精确生产/测试/文档/门文件；接口/持久字段/能力与迁移变化；所有真实消费者；正/负/消费者测试全名、命令、预期命中数；相邻回归；权限与数据边界；独立设计审结论；回滚/反转触发。缺一项则实施叶blocked。候选文件列表不是空白授权，新增文件或配置改动需先补记录，不能在代理写完后用“编译强制”一概追认。

行为不变量不随选型改变。反例不能成立时关闭的是那条怀疑，不是用户目标；保留原实现也要给理由与实际消费证据。任何缩减目标、放宽安全保证或新增外部依赖/付费/权限，需要真实取舍说明；必要且可推导的本地步骤由编排者推进，不让用户形式表决。

## D5 验证层次与干净终点

1. 取证叶：允许缺陷红，要求控制前提可达、失败落主题、基线/候选与路径明确；零匹配、编译错或夹具早退不算反证。
2. 实施叶：三锚非零实际执行，故障/正常/恢复/降级/并发相关路径齐；代码、规格、门与夹具级联不留到无拥有者的“下一单”。独立审可以反驳方案。
3. 单元关闭：本单元到期的实现、验证与独立审无未处理的正确性、安全、未归因增长或需求承接项。后置事项仅限预先指定的F2完整矩阵、F3最终独立审、F4实际CI/外部保护/交付，逐项保留待核销状态；不能把已到期缺陷改标后置。单元完成不等于全部目标完成。
4. 最终候选：所有实现、注释、测试、契约、验证器和CI本地文件先冻结；F2采集同候选完整结果，F3独立审查且frontier为空；任一覆盖字节变化使受影响证据失效，不能手填摘要背书旧结果。

性能需冷编译、冷开档、热态分列。安全线性项单独量且说明必要性，未归因boot/total和查询历史成本仍是阻断；计数平坦、窗口小、局部负例被杀均不代替总目标。保留原1.3×的判决记录，不能先改宽或把boot移出判决；若测量定义本身需纠正，先给同一安全/性能性质的等价证明与独立审，不追认结果。

全部目标、旧项、模式与未来迁移须在F1逐条有结论。动态反例和“是否更简单”的结构审缺一不可；语法validate通过只代表规划结构合法。

## D6 历史与规格合并

历史快照与原历史账是输入，不是当前派发合同。旧[x]保留原样；新叶不得借旧勾选完成。CARRYOVER每个旧任务有唯一主承接，跨域协作可以多个但关闭责任唯一；历史要求若已不适用，要有用户目标/协议/替代行为的证据，不能仅用旧符号零命中。

子域delta并非CLI自动归档输入。13.105要核真实CLI版本、根specs读取范围和同能力Requirement合并语义，冻结显式合并清单；在隔离合成change里验证合法合并、冲突标题与缺重命名源，不修改冻结archive。正式F4不得 `--skip-specs`/`--no-validate`。本轮只改进行中计划及其验收增量，不改主spec以追认实现。
