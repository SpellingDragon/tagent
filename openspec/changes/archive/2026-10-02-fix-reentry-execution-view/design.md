# Design

## D1 arms 的归属：解析结果携带视图，而非调用方各自决定

`ResolveReentryDelegation` 的两条分支各自选出**一张面上的 wrapper**；而 `session.go` 判定执行视图的唯一依据是"上下文里的租约是否属于这个子 agent 的 cm"。因此 arms 目标声明代这一步 MUST 紧跟解析、且与解析同源——放在调用方（`Call`）内部而重入路径另写一遍，正是本次缺陷的形状：两条路径共用 wrapper，却只有一条 arms。

helper 化后，"绕过 `Call` 的路径必须自己 arms"这一隐式约束变成单点可见，第四条路径再犯时会在同一处暴露。

## D2 两份租约并存而非替换

属主面租约承担 D6「派生前获取」的引用记账（并驱动退役排空），子代声明租约承担执行视图选择。二者语义不同，重入路径**同时持有两份**、各自释放一份；上下文里后写入的子代租约为 `execLeaseFromContext` 所见的最新值，故视图选择生效，而属主记账不受影响。

被否方案：把属主租约换成子代租约（丢记账，退役义务归不了零）；或让 `session.go` 在租约不属本 cm 时改读 `w.declared`（把视图选择推到执行侧，与"发布时已定"的不变量相冲）。

## D3 拒绝时机在模型调用之前

`acquireDeclared` 对已收敛代返回 `ErrExecClosed`。重入据此在 producer 内、`runAndCollect` 之前返回错误：不产生模型调用、不改任务链，与 §九「所选代无目标则拒绝且不改任务链」的既有判据同形。

## D4 测试必须让断言只被重入满足

原用例的 `newBefore` 在 relaunch 之后采样，把并发告警轮的 serve 吞进基线；且 `startReentryChain` 只等一次 serve、不等任务落账，使同键单飞（`spawnKey = agentName + ":" + request`，重入沿用同键）与告警轮互相取消。终态做法：setup 任务等到终态 → 发布新代 → 等到常驻循环静默（无在途模型调用）→ 再 relaunch，此时 `SUB-C-G2` 的任何增量只能来自重入本身。

不采用"把 `waitFor` 的 20s 调大"：被等待事件在失败日志中出现 0 次，调大只把 20.02s 变成 60.06s 的同一失败，并把契约违反继续压在 flaky 标签下。
