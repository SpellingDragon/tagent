## ADDED Requirements

### Requirement: 代码注释形态白名单

Go 源文件中的注释 SHALL 只存在两种形态：package/声明的 go doc 契约注释，与指向长期文档的单行索引。编译器/工具指令与一行式 `TODO(owner):` 作为机械语法豁免，豁免集合 SHALL 显式穷举于扫描器规则表。代码中 MUST NOT 存在设计理由、实现机制叙述、迭代过程记录或历史对比类注释。

#### Scenario: 实现叙述被识别并迁出

- **WHEN** 某声明的注释描述「先做 A 再在 X 锁内完成 B」或「之所以选 A 排除 B」
- **THEN** 该内容判为实现叙述/设计理由，MUST 迁入 `docs/wiki/`（机制）或 `openspec/specs/`（契约）后从代码删除，仅可留一行索引指回

#### Scenario: 章节横幅不属于任何声明

- **WHEN** 一段注释以分隔线或裸标题划分文件内部区域，且与其后声明之间被空行隔开（因此不属任何 doc 槽位，也不被 go doc 渲染）
- **THEN** 该注释 SHALL 删除；若标题指的是某声明的职责，MUST 改为该声明的 doc 注释开头，MUST NOT 以「说明文件结构」为由留在体内

#### Scenario: 契约信息不得因清理而丢失

- **WHEN** 一条注释承载单位、nil/零值语义、失败语义、并发安全性或调用方义务
- **THEN** 它属于 go doc 契约，SHALL 保留（可改写为名起始的规范形态）；MUST NOT 以「减少注释」为由删除

### Requirement: go doc 注释的契约边界

doc 注释 SHALL 以所依附标识符名开头，内容限于该 API 的契约：是什么、输入输出与单位、前置/后置条件、nil/零值/空集语义、失败与幂等语义、并发安全性、调用方义务、有效范围与不保证事项。判定准则：换一种实现方式该句仍成立即为契约。

#### Scenario: 每个包与导出符号有文档

- **WHEN** 扫描器遍历两模块全部包与导出符号
- **THEN** 每个包 SHALL 有 package 注释、每个导出符号 SHALL 有 doc 注释；缺失即门禁失败

### Requirement: 文档索引语法与目标限制

代码内文档索引 SHALL 使用固定语法 `// 契约: <路径>[#锚点]` 或 `// 规格: <路径>`，一行一个锚点，且 MUST NOT 承载解释。允许目标仅 `docs/**`（终裁：初稿曾并列 `openspec/specs/**`，因门实现 `index-root` 只认 `docs/` 且与 design 冲突而剔除——specs 承载已接受的需求，代码契约由 go doc 自持）；MUST NOT 指向 `openspec/specs/**`、`openspec/changes/**`（含归档）或任何过程工件。

注释正文 MUST NOT 出现**外部文档坐标**——变更名（含已归档变更）与计划内坐标（`design line N`、`N.M①` 之类的阶段/验收标准编号、`Red→green`、`Fail-before` 一类过程叙述）。这类引用与"不得指向变更工件路径"是同一条契约的两种写法：读者在代码里看到 `resident-continuity-r2-r4 3.8` 时，无任何长期文档可解析它，等价于把注释的语义外包给一份会被清理的过程工件。判据由 `external-coord-ref` 强制，变更名集合从 `openspec/changes/` 与其 `archive/` 运行时枚举（不维护硬编码名单）；索引行豁免，因为路径是它的合法载荷。

#### Scenario: 注释引用变更名被判为外部坐标

- **WHEN** 注释正文出现某个（含已归档）变更名或 `design line 169` 这类计划坐标
- **THEN** 该注释 MUST 被要求改写为自足的句子，或把所指内容落进 `docs/wiki/` 后改留一行索引

#### Scenario: 索引行中的路径不算引用

- **WHEN** 路径或锚点出现在 `// 契约:`／`// 规格:` 索引行内
- **THEN** 该位置 MUST NOT 触发外部坐标判定（路径是索引的合法载荷）

#### Scenario: 多行测试注释里的索引行独立成行

- **WHEN** 一条测试 doc 采用"意图行＋并列要点"的多行形态，同时需要指向机制文档
- **THEN** 索引 MUST 独占一行、形如 `// 契约: <路径>[#锚点]`，MUST NOT 写成 `- ` 并列要点的一员：索引语法按整行匹配，带要点前缀即不再被识别，其中的路径会退化为未索引引用；该形态与"要点须以 `- ` 起"并不冲突（索引行按索引规则判定）

#### Scenario: 指向过程工件的引用被拒绝

代码注释 SHALL NOT 以变更过程文档为真源：`docs/wiki/` 下的文档与各 `README.md` 是机制与用法的唯一真源，`openspec/specs/` 只承载已接受的需求。注释指向设计说明时 SHALL 指向前者之一。该禁令按**内容**判定，不因注释排版位置而豁免——游离注释（不在 doc 槽内）同样受内容规则约束，否则修正排版会把引用洗白。

- **WHEN** 注释引用形如 `openspec/changes/<name>/...` 或含变更条目号/轮次/日期
- **THEN** 扫描器判违规；该知识若仍有效 MUST 先落入 wiki/specs，再由代码以索引指向

### Requirement: 索引必须落到具体章节

指向长文档的索引 SHALL 携带章节锚点，且该锚点 SHALL 在目标文档中解析得到（显式 `<a id="…">` 或含该词的标题）。判据：读者按索引跳转后 MUST NOT 需要自行在长文档里搜索。若目标文档超过 200 行而未带锚点，即为违规。反向承诺同样成立：被索引指向的契约描述 MUST 在文档中真实存在，并以与代码一致的用词可被检索到。

#### Scenario: 大文档的裸路径索引被拒绝

- **WHEN** 代码写 `// 契约: docs/wiki/x/x.md` 而该文档有上千行
- **THEN** 扫描器判 `index-anchor-required`；作者 MUST 把索引改为 `#锚点` 形式

#### Scenario: 锚点悬空被拒绝

- **WHEN** 索引带 `#some-anchor` 但目标文档中既无同名 `<a id>` 也无含该词的标题
- **THEN** 扫描器判 `index-anchor-unknown`，该批不得通过；若描述确实缺失，MUST 先在文档写清该契约再加锚点

#### Scenario: 目标小节不存在时先补文档并可拆分路径

- **WHEN** 注释所承载的契约在 `docs/wiki/**` 与 `README` 中没有对应小节
- **THEN** 该批 SHALL 先新建长期文档、或按 `docs/wiki/<域>/<机制>.md` 拆分出承载该机制的一篇，登记 wiki 索引后再改注释
- **AND** SHALL NOT 以省略索引、改指 `openspec/changes/**`、或把内容塞进不相关长文的方式跳过
- **AND** 先删注释后补文档 SHALL 判为缺陷：它使已完成的包重新成为未完成（回炉）

#### Scenario: 按行删除注释不得吞掉语句

- **WHEN** 自动脚本按行删除注释
- **THEN** 仅当该行全部为注释时才可整行删除；带尾注的语句行 SHALL 只剥离注释部分
- **AND** 结果 SHALL 由等价门判定 code identical，以证明删除未改变代码

### Requirement: 测试文件的注释政策

测试文件的 doc 槽位 SHALL 只包含一行意图句、可选的并列要点列表（每行以 `- ` 起始），以及文档索引；MUST NOT 包含机制叙述、踩坑记录或用例论证。**折行是被刻意的形态而非违例**：一条契约含多个并列判据时，写成一行星号式长行（曾出现 823 rune 的单行）比分行更难读，因此规范以"行"为排版单位、以"句"为内容单位——散文式续行（非列表标记的第二行）说明论证该去断言消息或 `docs/wiki/`，仍是违例。单行长度 SHALL 有上限（`test-doc-line-too-long`），超限 MUST 拆为要点列表或迁往文档，MUST NOT 靠加长单行容纳。索引行承载路径，MUST NOT 计入长度上限。期望与判据 SHALL 优先由测试名、表驱动用例名与断言消息承载（它们是代码，不是注释）。测试文件的划分与标识命名不属于本契约，由 `openspec/specs/architecture-guardrails`「测试文件族与职责同位」「测试标识不承载迭代编号」约束（同一事实单处，不双重立法）。

#### Scenario: 并列要点允许折成列表

- **WHEN** 一个测试的 doc 由一行意图句加若干 `- ` 要点行构成
- **THEN** 该形态 MUST 通过形状检查，MUST NOT 因"多于一行"被判违例

#### Scenario: 超长单行不得用于容纳段落

- **WHEN** 意图行或任一要点行超过长度上限
- **THEN** 该行 MUST 被要求拆为要点列表或把细节迁入 `docs/wiki/` 并留索引，MUST NOT 通过把整段塞进一行来通过检查

#### Scenario: 用例论证移入断言消息

- **WHEN** 测试体内注释说明「此处期望 X，因为 Y」
- **THEN** 期望 X 移入断言消息字符串，Y 若为长期判据则迁 wiki/specs，测试体注释删除

### Requirement: 注释剥离等价证明

每次注释清扫 SHALL 通过机器证明只改动注释：以基线提交为参照，逐文件剥离全部注释 token 并规范化打印后，与当前版本 MUST 逐字节相同。任一文件出现非注释差异即整批失败并回退。

#### Scenario: 借道改码被拦截

- **WHEN** 清理批次中某文件同时调整了语句、命名或空行以外的格式
- **THEN** 等价门报不一致并指出文件，该批 MUST 回退，重开为「纯注释」与「行为改动」两次独立变更

### Requirement: 注释政策扫描与豁免台账

项目 SHALL 提供扫描器判定：非 doc 槽位注释、命中设计/迭代叙述特征、路径引用不符索引语法、指向过程工件、package/导出符号缺文档。扫描器 MUST 以内容形态为判据（长度不判定合规），违规数 SHALL 为 0 方可准出；每条豁免 MUST 登记规则与理由。

#### Scenario: 新增豁免需显式登记

- **WHEN** 某注释形态需要扫描器豁免
- **THEN** 豁免规则与理由 MUST 进入规则表与批次台账并可审阅，MUST NOT 通过放宽正则或就地注释「例外」实现

### Requirement: 生成式 API 文档与新鲜度

项目 SHALL 从代码注释生成完整 go doc 文档并入库（每包一份＋索引），生成物 MUST NOT 手工编辑。CI SHALL 重跑生成并比较：存在差异即失败，保证文档与代码注释同源同步。

#### Scenario: 注释变更后文档漂移被检出

- **WHEN** 提交修改了注释但未重跑生成
- **THEN** 新鲜度门检出 `docs/api/` 与生成结果差异并失败，要求补齐生成物

### Requirement: 残留判据只收无歧义词，且英文词必须整词匹配

变更残留检测的英文词表 MUST **只收录不会与现在时描述混淆的词**，并且一律按整词匹配。`used to` MUST NOT 作为残留标记：它无法与"被用于/用于"的目的语在词法上区分（`key used to pass external context`、`identity used to mark …`），把它当残留会迫使作者把正确的散文改成绕口表述。同理，任何英文词都 MUST NOT 以子串形式命中（`refused to`、`still-used tool` 曾因此误报）。

已知代价并被接受：少量真正的英文"过去习惯"句会漏报，需由 `previously`、`no longer`、`formerly`、`已移除`、`不再` 等无歧义词承担，或在人工通读时发现。

#### Scenario: 目的语不被判为残留

- **WHEN** 文档注释写 `ExternalContextKey is the RuntimeState key used to pass external context`
- **THEN** 残留检测不得报告该注释

#### Scenario: 子串命中不算残留

- **WHEN** 文档注释含 `refused to adopt` 或 `still-used tool closers`
- **THEN** 残留检测不得报告该注释

#### Scenario: 无歧义词仍然拦截

- **WHEN** 文档注释含 `previously`、`no longer`、`已移除` 或 `旧实现`
- **THEN** 残留检测必须报告该注释，并在结论中给出命中的词

### Requirement: 棘轮只能在其基线记录的扫描面上使用

扫描集合 SHALL 只在一处定义（`scripts/lint.sh` 的 `POLICY_DIRS`），并 SHALL 被写进基线文件本身。规则计数按规则聚合，因此少扫一份树会让**每一条**规则的总数一起下降，与"某批清理真的降低了违例"在数值上不可区分——门必须在读数之前就拒绝这种扫描，而不是等人去发现差值对不上。

#### Scenario: 用小于基线记录的扫描面读数被拒绝

- **WHEN** 以缺少基线所记录目录的集合运行棘轮（读或写）
- **THEN** 门必须以非零码失败，并在报错里报出两侧集合，指明应经 `bash scripts/lint.sh` 使用
- **AND** 基线文件 MUST NOT 被改写

#### Scenario: 记录了却仍漏扫的嵌套模块被拒绝

- **WHEN** 基线记录的集合本身就漏掉树中一个带 `go.mod` 的目录
- **THEN** 覆盖核对必须失败并点名该模块——扫描器跳过嵌套模块，这些文件因此完全不在门内

#### Scenario: 重叠的扫描目录不被接受

- **WHEN** 同一模块内的父目录与其子目录同时被列为扫描根
- **THEN** 门必须拒绝：文件被计两次会抬高每条规则的总数，制造虚假的"新增违例"

#### Scenario: 只测量不裁决的子集扫描仍可运行

- **WHEN** 批量工具需要比较两份快照，或只看某一个包
- **THEN** `-no-baseline` 报告该范围的计数，既不读也不写棘轮，因而不会把局部读数误当成全局裁决
