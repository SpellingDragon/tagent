# 代码注释面收敛：仅存 go doc 与文档索引

## Why

项目 557 个 Go 文件承载 **22,501 行注释**（生产 12,507／测试 9,462），其中绝大多数不是 API 文档，而是设计论证、机制流程叙述与迭代过程记录（决策编号、变更条目号、日期、「旧 X 已移除」「之所以…」「教训」式叙述）。后果有三：**同一知识存在两处真源**（代码注释 vs `docs/wiki` 与 `openspec/specs`），且会单边腐化互相矛盾；**注释随迭代失真**，读者无法判断哪句仍然成立；**`go doc` 输出被非契约内容淹没**，无法作为项目 API 文档呈现。项目刚完成架构收敛（同构事件管线、执行代与热更候选事务）并把 wiki 重写为纯现态文档，正是把代码注释收敛到同一纪律的时机——**代码不记录任何设计与逻辑说明**。

## What Changes

- **确立注释白名单政策**：Go 源文件中的注释只允许两种形式——
  1. **go doc 注释**：package 与声明的文档注释，内容限于该 API 的契约（是什么、输入输出、单位与边界、前置/后置条件、失败语义、并发安全性、调用方义务）；
  2. **文档索引**：单行指针，指向长期文档锚点（终裁：仅 `docs/**`；初稿曾含 `openspec/specs/**`，因与门实现/design 冲突被剔除，见 tasks.md §379.4）。
  机械语法行（`//go:build`、`//go:embed`、`//go:generate`、`//nolint`、cgo 指令）作为编译器/工具输入保留；一行式 `TODO(owner): <可执行项>` 允许但不得承载说明。**设计理由、机制叙述、迭代过程、历史对比一律不得留在代码中。**
- **逐模块、逐文件清扫全部 557 文件**：函数体内注释一律删除或迁出；声明注释逐条改写为契约范围；测试文件的锚点设计叙述同理收敛（只保留一行式测试意图与文档索引）。
- **测试文件族按职责收敛（同职责多工况并入一文件）**：当前 401 个测试文件对 156 个生产文件（根包 70/16、`agent/` 109/28、`tool/action` 31/7、`agent/task` 20/3），同一职责的工况被平铺成多文件；收敛为「一职责一测试文件」，工况以子测试（表驱动）表达。其中 **28 个文件名与 49 个函数名 carrying 变更任务号/批次号**（`d2_..d14_`、`m3_`、`w1_`、`org_m34_`、`TestD52_*`、`TestMonitor33_*`）——文件名与标识符本身就是迭代标记，一并改为职责语义名并同步全部引用。
- **合并不改覆盖（机器证明）**：生产文件零变化、测试清单合并前后一一对应、每函数断言数不降、`-race` 全绿；共享 fixture/helper 归一时同名或近重复者须显式裁决留因，禁止静默择一。端到端贯穿链保持单一落点，不拆成各包局部测后以分别通过充当整链通过。
- **知识承接先于删除**：每条被删注释三判——已覆盖→删／有长期价值→先并入 wiki 对应章或 specs 契约、再删／瞬态→删。不为凑清理丢失知识，也不得换个措辞把设计说明留在代码里。
- **机械化保障**（新能力 `code-documentation`）：
  - 零行为证明：每文件**注释剥离后源码逐字节相同**，逐批必过（这是「只动注释」的机器证据，不靠自陈）；
  - 注释政策扫描器：以 `go/ast` 判定注释槽位与内容形态（体内注释、指向迭代工件的指针、迭代标记正则）→ 接 CI；
  - 完整 go doc 生成物：`docs/api/` 按包生成 `go doc -all` 视图＋索引，含覆盖门（每包有 package 注释、每个导出符号有文档注释）与新鲜度检查（重跑生成物无差异）。
- **不做**：不改任何行为、API 签名、命名或文件划分；不重写 wiki 现态内容之外的文档结构；不引入第二套文档源或新 DSL；不清除 `docs/.dev/`（非代码历史归档）；不删除 `openspec/`（含归档 change——它们是过程记录，本就不在代码内）。

无 **BREAKING**：不动公开 API，仅注释与新增生成物/脚本。

## Capabilities

### New Capabilities

- `code-documentation`：代码注释形态白名单、声明注释的契约边界、文档索引格式约束、生成式 API 文档（`docs/api/`）与三类机器门禁（注释剥离等价、政策扫描、覆盖与新鲜度）。

### Modified Capabilities

- `architecture-guardrails`：新增「测试文件族与职责同位」「测试标识不承载迭代编号」两条，把既有**变更局部性准绳**延伸到底部测试面（合并的覆盖不变量、端到端链不拆散、标识去任务编号）。

**刻意不把注释政策写进护栏**：注释与文档分工的唯一真源是 `code-documentation`；同一契约双写两处正是本次要消灭的病症。测试**注释形态**归前者，测试**文件划分与标识命名**归后者，两面不重叠。

## Impact

- **受影响代码**：全部 `*.go`，156 生产 + 401 测试文件，跨两模块（根模块与 `examples/wechat-bot`）。
- **新增工具与产物**：`scripts/`（注释剥离校验、政策扫描、go doc 生成）；`docs/api/`（生成物，入库）；`.github/workflows/ci.yml` 接入三道新门。
- **文档承接**：`docs/wiki/`（agent / platform / tool / event / memory 等篇）需要按批补入注释中独有价值的内容；`openspec/specs/` 承接 SHALL 级判据。
- **批次顺序约束**：每批「先补文档，后删注释」——现存注释里有若干**尚未落入任何长期文档**的运行判据（换代与状态重建的边界、热更各门的先后理由、TTL 单轴理由、投递对账终止判据、退役三条件），先删后补即造成知识丢失。
- **主要风险**：①过度删除——把契约必要信息（单位、nil 语义、调用义务）当叙述删掉，导致 API 使用者误用；防线是逐批人工抽查 + `go doc` 可读性复看；②借道重写——清理时顺手改代码，破坏零行为证明；防线是注释剥离等价门为硬门；③扫描器规则误报抑制真实违规；防线是规则白名单显式化、批次台账记录每例豁免理由。
- **新增风险（测试合并）**：①helper 归一导致某侧 fixture 语义被丢；②断言被无意弱化或删除；③CI 与文档中的测试名过滤器失效；④端到端链被拆散。防线：合并不变量脚本（清单双射＋断言计数）为硬门、映射表入台账、旧标识引用残留 grep 必须为 0、贯穿链落点清单先审后动。
- **验证**：root 与 wechat-bot 三门（build/vet/test `-short`）、受影响包 `-race`、政策扫描零违规、合并不变量门零差异、`docs/api` 覆盖与新鲜度门通过、逐批抽查记录。
