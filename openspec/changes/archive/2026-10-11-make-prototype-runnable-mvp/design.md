## Context

本轮以 prototype 当前七个 Go 文件为基线，不恢复被用户移除的生产目录。现状可编译但不构成 MVP：DefaultRun 丢掉首条输入且只执行一次；循环内向无缓冲总线发送会阻塞；模型中间输出与任务 ACK 混作新输入；exampleComposition 不会真正调用工具。state 已集中部分数据，但 face.Allow 与 governance.rules 重复，冥想来源被构造器固定为 user，任务派发还可能同步阻塞事件消费者。

用户选择可运行 mock MVP，允许为此最小修改 agent.go。设计以行为闭环与清晰职责为准，不复制生产框架。

## Goals / Non-Goals

**Goals:**
- 真实运行原型的 Input → Run → OnEvents → ModelCompletion → 工具 → 结果 → Reply，支持协作式取消。
- state 是生效配置、治理记录、任务实例和反思水位的唯一运行时持有者；config 不暗藏另一份当前配置。
- 用同一种 BaseTAgent 组合父子调用，使用可重复的 mock 模型、工具和人工裁决。
- 所有文件说明职责、未实现能力与实际接线点；README 和测试共同标明能力边界。

**Non-Goals:**
- 不接真实 provider、微信、tmux、MCP、磁盘数据库、OTel、Git 发布或训练系统。
- 不做多租户服务器、同实例多会话路由、durable inbox、任务恢复/续行、自动回滚、多代物理资源回收。
- 不新增通用 Runtime/Engine/Service 接口体系，不修改根依赖，不承诺历史生产规格的全部行为。

## Decisions

### D1 保持函数式骨架，明确协作式生命周期

保留 BaseTAgent、Run/OnEvents/ModelCompletion/Compact 与工具函数注册的基本组织。为阻塞操作统一透传 context.Context，并允许模型、工具及最终回复通道返回错误；原型内部签名统一迁移，不增旧/新双 API。

Run(ctx) 是唯一循环入口，取消 ctx 后停止受理、取消本实例任务并等待合作的任务生产者停止，再返回。Input 在关闭后给出明确错误。实例重复启动应明确拒绝；不通过关闭仍有发送者的数据 channel 来结束流程。模型、工具与 Reply 回调以遵守 context 为契约，MVP 不强杀不合作的任意用户函数。

替代方案：只增加大 channel 缓冲仍可能在批量生成工具调用时自锁；保留不可取消函数再偷偷开启代理 goroutine 会使退出与实际生产者停止脱节，均不采用。

### D2 数据队列与唤醒分开，循环单写工作投影

在 agent.go 内使用小型互斥保护的 FIFO 数据队列和容量为 1 的唤醒 channel；保持在原 agent 内，不提取通用消息代理。生产者追加事件并发唤醒脉冲，不等待当前消费者重新进入 Pull。消费保留首事件并按队列顺序处理；停止后拒绝发布。

队列在 MVP 中是内存态、无容量治理，README 明示背压/持久受理未实现。不声称跨生产者并发发布具有业务全序，已经受理的 FIFO 顺序不被重排。

只由循环写 inputs，快照读取经受控方法；不在后台工具中修改投影。压缩在装配边界执行，不为每条超限事件向总线重复发送压缩指令。

### D3 区分事实、驱动事件与通知

用具名事件种类表达输入、工具调用、任务 ACK、任务终态、模型中间输出、最终答复；保留有意义的既有数值并补充所需种类，不靠正文关键词决定控制流。

输入与任务终态提供新模型材料；ACK 与模型中间输出只作记录/展示，不自行再次调用模型。模型无工具且内容非空时返回最终答复；空终答、模型错误、未知工具、工具错误/拒绝给出可见错误，不伪装成功，也不无限重试。

同一模型响应的工具调用按声明顺序派发；多任务的完成只更新其自身记录。若多个结果不同顺序到达，在全部本轮待定调用收齐后按派发顺序装配后续模型输入，避免调度时序改变模型上下文。后续模型确实读到工具结果后才产生示例的最终答复。

### D4 state 管当前关系，memory 管历史事实

runtimeState 只存一份有效 config、一个 taskManager、治理拒绝记录和冥想水位；删除 agent/session 与 call 中无独立用途的镜像字段、以及任务中已无读取方的执行函数字段。运行时共享状态与不可变调用归属分开。

publish 验证候选 Model/工具函数及压缩参数的有效性，复制可变映射后一次换入；非法配置保留旧面并返回错误。snapshot 一次读出完整配置。治理规则取自同一快照的 Allow，state 只额外保存判定记录，不维护第二份可变 rules。

本 MVP 的生效单位是一次事件处理/模型步骤：这次模型调用、它产出的工具选择与治理判断固定使用同一快照；已派发任务保留旧函数。任务结果触发新的回收步骤时可读取最新配置。README 显式区分此语义与生产的完整 ReAct turn/组织代际租约，不将两者混称。

publish 不重建 memory、inputs、taskManager 或调用接收方。锁只保护数据读取/变更，不包住模型、工具、Reply 或其他用户回调。

### D5 任务管理与治理解耦

state 负责治理判定和账本；task_manager 接受已经选定的工具与判定接缝，负责 id、状态、执行、终态及生产者生命周期。任务只使用发起时的 callState；ACK 不等于终态；终态至多结算一次。

任务错误与拒绝进入记录并发出结构化终态事件，原文结果不被更改。取消由父 context 传播至工具及子 agent。父任务管理器只登记对子 agent 的一次委派；子 agent 内部另有自己的任务表。MVP 不实现 resume、TTL 或存活探测。

替代方案：用集中全局任务表吸收父子任务会混淆所有权；将治理策略藏在任务函数闭包则无法统一观察和更新，均不采用。

### D6 内存事实与 mock 压缩真实接通

memory 支持并发安全的追加、按键召回和只读快照；记录保留原始内容及来源，不保存执行函数、Reply 回调或可变配置引用。已赋键的重放仅接受表内一致记录，不把任意非零键当成已提交事实。

memoryPlugin 在输入进入投影前记录事实，最终答复记录后再投影和投递。observePlugin 只观察，默认不污染示例输出。有限历史投影与完整内存事实分开；压缩只变投影。

mock 压缩可保留摘要标记、首尾票据及近期消息。票据只从系统生成的引用位置取得，不从正文中的伪造 [evt_x] 抽取；recall 对坏键和缺失键显式报告 miss。演示在真正发生压缩后调用已注册 recall，验证原文仍可取回。

同进程投影快照/恢复是演示能力，不宣称进程崩溃恢复、掉电耐久、因果链、TTL 或语义检索。

### D7 组合演示与特性边界

config.go 只保留配置与装配；把原来混杂且不运行的 exampleComposition 改成 prototype/example_test.go 中真正运行的 Example。新增 prototype/prototype_test.go 承载核心回归；确有必要时按领域拆为少量测试文件，不添加专用测试框架。

示例与测试的模型按收到的输入/工具结果给出确定输出，至少一次真正选择并执行 echo/子 agent/recall，不用固定最终字符串冒充这些链路。所有子循环均取消并等到 Run 返回；Reply 通道发送遵守 context。

手动 tick 作为 demo 触发器；meditation 的 pending/watermark 及状态转换放在 state。反思调用明确标记 Source=meditation，任务与最终事件继承它；新颖性检查排除该来源。只有处理完成的确认推进水位，失败或注入失败释放 pending 并保留旧水位；不增加真实 ticker/后台守护线程。观察目标通过显式注入 memory/recall 接线，不只向模型发送数字水位而不给读取手段。

评估/自进化保留明确标注的 mock judge → 显式 publish，不承诺训练、Git 提交或自动回滚。

### D8 文档与测试共同交付

每个 Go 文件（包括新测试/示例文件）头部用中文写明「职责」「未实现」「接线」，列出该文件实际涉及的扩展边界；不要给不存在的接口写已经接通的说明。

README 至少包含：模块定位、已实现/mock/未实现矩阵、Mermaid 组件图与一次请求时序图、七个文件职责与状态所有权表、标准库 mock 的实际执行命令、四条核心链路、退出/热更/持久性限制、未来 provider/tmux/MCP/存储/审批的接入位置。说明以 prototype 当前实现为准，wiki 仅链接为完整目标设计参考。

测试经真实 Run/Input/工具注册/Reply 入口取证；同步使用 channel 屏障而非 sleep 猜测。timeout 只是防测试挂死，不用于性能判定。所有新增用例重复 >=10 次并以 -race 验证。

## Risks / Trade-offs

- [内存队列和事实表无容量治理] → 明示仅开发/demo 规模；生产背压、TTL、落盘为未接线能力。
- [不合作的模型/工具/Reply 不响应取消] → 文档限定协作式 context，测试仅用可取消 mock，不伪称物理进程已停止。
- [一实例一调用作用域] → 父子及不同用户使用独立实例；不默默合并不同 Reply 的输入。
- [热更批次语义弱于生产租约] → 固定模型步骤及产出工具的视图，以行为测试证明；完整组织热更留在能力矩阵未实现列。
- [当前生产工作区大量删除] → 验证仅覆盖 prototype；不执行根全量测试、不恢复删除内容。

## Migration Plan

以当前未提交 prototype 为基线，单一 apply 子代理串行改写同一 Go 包，主代理复验。只新增本变更目录、prototype 下测试和 README；新增能力用独立 prototype-mvp 规格，不改生产主规格。保持可读骨架的名称和函数式组织，内部签名按 D1 一次迁移，不建立兼容包装层。不开启真实服务，不提交和归档。
