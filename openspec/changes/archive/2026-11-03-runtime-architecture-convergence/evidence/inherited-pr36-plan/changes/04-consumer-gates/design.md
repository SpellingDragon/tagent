## 技术要点

1. 从根包装配和实际 CLI/宿主入口纵向追踪对象创建、启动、调用、关闭；测试额外补接线不算生产消费者。
2. 对照 `.github/workflows`、gate scripts 与测试清单，区分产品失败、测试骨架错位、环境/预算问题；各自采用不同修复面。
3. 对时序敏感症状使用测试侧可控交错与重复运行；不得以 sleep 轮询或延长生产窗口证明正确。
4. 当前工作树证据只代表工作区时点；远端 CI、提交树与 merge 状态分别报告。

## 风险与回退

- 全量门禁运行时间长 → 先跑目标包快反馈，再后台跑长门；最终不得省略。
- 既有失败可能误归因于本批 → 必要时用干净基线复验同用例，按证据归属。
