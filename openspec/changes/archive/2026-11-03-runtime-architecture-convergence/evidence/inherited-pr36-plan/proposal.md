# PR36 核心概念与行为收敛

## Why

用户原始症状是：“系统设计不断膨胀，偏离核心框架设计，问题越改越多”。PR36 已统一部分执行主干，但回执、通知结清、实例身份与关闭语义仍需独立验证；若继续按症状叠加窗口、屏障和导出面，测试变绿也不能证明系统更简单或行为正确。

本变更以 PR 最新头 `dfdfa72e` 为审查基线，将既有方案全部降格为候选修法。先由独立领域审者经公共入口复现关键问题，再做破坏性概念收敛；行为症状与概念账任一未过，不得放行。

## What Changes

- 建立运行时症状与概念账双门：不假收束、不丢通知、不双驱动；核心概念白名单与导出公共面不得因修复净增长。
- 按回执与通知、实例与关闭、公共概念/API、生产消费者与 CI 四个关键域独立 grilling；每轮由编排者逐条裁定，不整批采纳。
- **BREAKING**：允许删除双轨 API、兼容字段和仅由修复自身制造的抽象；允许保留症状测试而重写实现，不要求保留现有补丁结构。
- 修复只落入已裁定的最小语义单元；CI 时序与产品语义分线，禁止为迎合测试而增加生产机制。
- 每批修复后由新的只读审者复扫受影响面及同机制路径；仅在显式“frontier 空”、公共入口证据与全量门禁齐全后完成。
- 不提交、不推送、不归档，不修改主工作区的未提交内容，不处理与本 PR 无关的存储、流式或训练计划。

## Capabilities

### New Capabilities

无。一级仅保留 `orchestration` 编排契约；领域行为规格下沉到二级子变更，新增能力前必须与既有规格查重。

### Modified Capabilities

由各领域审者依据当前代码与 `openspec/specs/` 实证后登记；未确认前不预设规格变更。

## Impact

- 基线工作树：`.quiesce`，提交 `dfdfa72e`；主工作区保持不动。
- 主要代码面：`runtime/agent`、`runtime/task`、`assembly`、相关公开 API、正式入口集成测试与 CI 门禁。
- 验收面：公共入口端到端症状、负向路径、生产消费者、概念账本、导出 API 差异及项目既有质量门。
- 已知的 PR `CONFLICTING` 状态单独登记为合并阻断项；不得用隐藏冲突或改写基线的方式宣称放行。
