# pr36-concept-convergence 编排文档

## 一、结论

抵达 DoD 的唯一路径是：最新 PR 头的独立公共入口拷问 → 逐条裁定并冻结三锚 → 按触碰集做概念净减修复 → 新审者复扫 → 双门与全量门禁；当前最大风险是把历史审查中的旧缺陷误当成 `dfdfa72e` 仍存在的事实，或为修局部竞态继续新增生产概念。

### 2.2 授权

- R1 审者：只读；可运行本地测试并在自己的 `/tmp` 目录写复现；禁止修改仓库、git index、依赖与配置，禁止 commit/checkout。
- 审者必须遵循 `grill-with-docs = grilling + domain-modeling`：使用 design tree 拷问并核对 `docs/GLOSSARY.md`，但事实自行查证，不直接向用户提问；只把真正需要裁定的决策带回。
- 每条发现须含严重度、`file:line`、公共入口或真实消费者证据、复现命令与原始退出码、概念影响、最小修复方向。没有证据的猜测单列为假设，不得进入修复队列。
- 修复统一采用 TDD：公共入口缝已由用户确认；一次一个红测试与一个最小实现，禁止先批量写想象行为的测试，重构留到独立审查。
- 修复单尚未授权具体文件；A1 裁定后在本文档补精确白名单与三锚，再派发。共享面与一级账目归编排者单写。
- 同一机制三次修复仍出新关键缺陷、需要新增独立公共概念、或需要 rebase/提交时，停线交用户裁定。

### 2.3 凭据

R1 五查：frontier 是否逐条有证据；是否使用公共入口；负向路径是否真实执行；测试是否非空转；结论是否区分实测、推断与未扫描面。

修复五查：勾选真实性、白名单产物、数字溯源、遗漏检测、生产消费者实测。每条修复必须保留修复前红与修复后绿；若基线已绿，用基线红或定向变异证明症状锚有效。

必须亲验：所有声称通过的命令原文与原始退出码、实际测试数、最终 `git status`、概念/API 增删数、PR 冲突状态。任何“通过”若来自管道，必须另行确认真实退出码。

## 三、明细

- 当前派发原子为两条同域审查叶；R1 只产发现与证据，不勾实现完成。
- 修复合单判据：同文件簇、同权威状态来源或同 spec scenario 的叶合单；跨域合单须白名单与触碰集均不相交。
- 预算：首轮四路只读；修复最多三路可写；长跑门禁后台执行但终态必须由编排者核验。
- 外部 provider、微信真发与远端 CI 不在本地证据面；不得写成已验证。PR `CONFLICTING` 单列为合并阻断，不与代码正确性混算。
