# 全事件消费完整性设计

## Context

基线为 `6cc441436c2aab15edcee34cf2561086232c8311`。用户观察到后台任务摘要之后还有额外确认；精确运行根因未复现。静态已见随动入口复制正文进入反馈与输入提交路径，以及驱动器全局忙碌分支。二者是待验证风险，不是已完成的根因诊断。

本轮只物化/回写规划。事件代码、正式测试、检查脚本、CI、主规格、历史归档、用户数据和原有未净子模块均不修改（04.1 合同与 checker 自测的计数同步除外）；既有实施勾选 9 叶保留，其余实施叶未勾选。源码事实与待裁定项见 [findings.md](findings.md)。

## Goals / Non-Goals

目标：覆盖现有全部事件机制，修复证实的业务缺陷；用正式装配的确定性短程、长程、故障变异证明不重复、不漏处理、不串责任；每 MR 必跑，现有基线不放宽。

非目标：正文过滤、内容相似度去重、重建通用总线或第二消费状态仓、恢复已删除机制、未经证据的公共 API、真实模型/微信测试、训练资格认证、掉电或 72h 发布证明、自动提交/推送/归档。

## Decisions

### D1 语义边界与事实保真

- 事件生产保留原生消息、角色、ContentParts、ToolCallID、来源、目标、实例及责任身份。通知身份沿用 `TaskID/Round/Kind/Seq`，事实引用不是通知身份。
- 插件按自身语义生成派生事实或观察：任务唤醒观察者提示既有消费者处理待办，不复制正文制造新用户请求；治理、冥想、压缩、替换不强制套用“只唤醒”。
- 同一通知、同一责任范围只有一个逻辑处理所有者；诊断、训练及历史读取可以合法再次读取同一事实。正文在请求中重现不作为重复消费证据。
- 先核验现有 mailbox 的接收、领取、消费及 task 提交/恢复接线；失败不提前确认、忙时保留义务、恢复不重做已确认动作。新增持久格式或 API 先裁定，不从旧规格名反推恢复旧 inbox。
- 原 invocation 延续与模型版本获取时点分开核对。在途决策及派生执行不漂移；“原 invocation 下一决策”和“新 turn 取当前代”的历史条款冲突由 00.3 裁定，不以新建调用身份绕过。
- observer 失败语义分层（`00.3` 的 `gate_rulings.OBSERVER_FAILURE_SEMANTICS`）：日志/遥测继续旁路，容许缺口；任务推进（含 `01.2` 消费确认、`01.8` 事实持久化、`01.10a`/`01.10b` 外部执行状态）保存可恢复义务，失败 SHALL NOT 被记作处理完成；插件具体业务动作按各自契约处理，不把全部 observer 改为阻塞；消费确认与发送确认分开，未知送达不伪报成功。

理由：运输、存储、业务消费和外部副作用分别存在失败窗口。被否方案：改事件类型、只推进 cursor、强制正文只出现一次、换入口即宣称恰好一次；这些方案没有完成逐身份消费者证明。

### D3 波次与无环调度

波次仅作汇报分组；解锁以依赖产物进入受控集成树并被核验为准，不等待整域，不表示授权合并远端 main。

| 波次 | 就绪工作 | 解锁结果 |
|---|---|---|
| W0 | 实施授权后 00.1、03.1；00.4 等 00.1；00.2 等 03.1 | 基线/复现证据可用于 00.3 |
| W1 | 00.3 后 01 热点链串行；02 各消费者；04.1/04.3 | 域产物交 01.5（根）与 01.6（微信），正式矩阵可准备 |
| W2 | 01.5 根装配、01.6 微信宿主装配、01.7 CLI 宿主装配、02 正式复验、03.2—03.9、04.2 真实 runner 验证 | 可进行变异和完整长程 |
| W3 | 03.10 校准、03.11 长程、04.4/04.5、05 作业及文档终验、F1—F3 | 本地确定性证据闭合；外部动作仍另授权 |

依赖分两种：`depends_on` 要求前置产物达到集成就绪；`verify_after` 要求本叶最终勾选前的集成复验完成。02 域需要根接线时可交付已核验的域产物供 01.5 集成、需微信宿主装配时交 01.6 集成，但保持未勾选；01.5/01.6 不等待 02 的最终勾选。01.5/01.6 之后回验 02/03 再勾叶（02.1—02.5、02.7 经 01.5，02.6 经 01.6），避免“02 要 01.5、01.5 又等 02 完成”的环；02.6→01.6 只是 `verify_after`，01.6 只依赖 01.4，方向单向无环。产物就绪不是新增完成状态仓，凭据记在 ORCHESTRATION 台账。

00.4 在隔离干净基线取证，不依赖 00.2 先后或跳过新测试。04.2 的最终真实验收依赖 01.5/01.6/01.7、03.2—03.9，而 03 的直接 go test 不依赖 runner 完成。05.3 可先写草稿，最终验收等 05.2。

### D4 写入归属与合并

精确候选文件及测试由各域 design/tasks 列明，[ORCHESTRATION.md](ORCHESTRATION.md) 按派发单登记。01 所有根热点由 P1 同一所有者串行处理；02 域只提交根接线需求，01.5 单写根装配、01.6 单写微信宿主装配、01.7 单写 CLI 宿主装配，三个测试文件互不同簇。

共享测试 `tests/integration/host/event_integrity_test.go` 与 `tests/integration/history/event_integrity_test.go` 各有唯一写者锁；微信 smoke 文件亦单写。锁只约束同时写入，不制造违反任务依赖的固定叶顺序。

同树并发要求 W/W、W/R 无交叉；测试包全部源文件及依赖包纳入读取集。宿主独立 go.mod 通过 replace 读取根源码，不构成隔离证明。交叉则合单、串行或隔离工作树，合入后复验。最多三份源码派单；一级账目编排者单写。Golden内容由编排者核准，04.1/04.3由编排者或其本单具名委派的唯一写者在golden-runtime锁下按核准内容写入，其余代理只交建议。

禁止自动 reset 用户索引、提高质量基线、顺手改原有子模块；超白名单、公共 API、持久格式或新依赖先报告。临时测试资源独立，运行产物通过显式 `--out` 或 CI runner 临时目录保存，不靠未核验的 gitignore。

### D5 三级验收与历史保全

叶级：原任务行正锚、负锚、消费者锚齐全，每轮具名 run/pass 与原始退出码可核验。阶段性组件证据不顶正式消费者；缺消费者的叶不勾选。

域级：每个 delta scenario 映射到具名测试或文档/检查证据；MODIFIED 保全原完整条款及未被授权改变的场景。真实根因、静态风险、未裁定分别记账。

变更级：E1—E8 全覆盖；已证实业务缺陷清零；短/长/变异与受影响回归实跑；旧 S01—S15、架构、文档/概念/注释门不退化；本地、真实服务、长期发布证据分层。

理由：纯自洽检查无法证明业务责任正确。被否方案：只写测试/检查器、复制输出改 Golden、目录移动归档、用有限等待代替排空证明。

### D6 发送不确定窗口

用户已选择：结果未知保留动作身份、未确认状态与错误，不自动重发、不伪报成功；显式重试保留原动作关联。已确认动作恢复不重做；不同显式 send、最终答复、附件及分片分别对账，不能机械限制成每通知一条微信。

理由：发送接口只返回 error，不能证明远端未收到。被否方案：无条件自动重试并宣称恰好一次、按文本吞消息、把消费完成当发送成功。渠道端幂等能力未验证，保持证明边界。

### D7 正式模拟、证据与成本

- 模型协议、微信及外部工具使用替身；内部从 Boot/公开 Run、微信应用装配或 CLI run 启动，不在测试里补挂遗漏的产品消费者。
- short 每 MR 十次独立 `-count=1 -race -json`，每次独立日志/run-id/退出码；单轮唯一 run/pass 不放宽。
- long 每 MR 六组合各一次：种子 1/7/42 × MaxTokens 256/32768，每组合四共享会话各 300 输入，共 1200；四会话轮流各 30 重启触发点，共 120 次真实重启，每次恢复全部会话。总计 7200 输入、720 重启；初次启动不计，不把一次重启乘四。
- positive/negative/consumer 是验收面，不把同一长程重新执行三遍充三个子测试。共用一次受测运行的真实观测，六组合总量不因断言组织放大。
- 输入身份、HTTP 运输次数、模型请求、审批控制、初始化消息及渠道分片分别计数。冥想保持启用，产品持久化强度不降低。
- 新增用例交付前至少十次稳定性验证；完整 long 的交付重复单列，不乘进每 MR 矩阵。预算先测：cold build、热运行、120 重启、race、存储增长、峰值资源；20m/45m/30m 只是候选上限，尚无实测。
- 共用既有 runner，新增 `event_integrity_scenarios.json` 合同，旧合同保留。合同逐项登记全部独立测试/子场景，整链聚合组不替代独立负锚；文档/检查叶不用虚构产品测试充数。
- 源树摘要覆盖受测第一方源码、必要未跟踪测试、fixture、合成配置、合同及各模块锁文件；运行配置摘要单列。变异保留基线摘要与补丁/overlay 摘要。指纹不是不可伪造性证明。
- 变异只对已确认缺陷启用，控制树先绿；原具名业务断言拒绝才算有效，编译失败、超时、无测试或失效变异使门失败。

## Risks / Trade-offs

| 风险 | 处置 |
|---|---|
| 旧规格含已替换术语或相互冲突 | 00.3 核对完整条款；语义待裁阻塞对应叶，不复活旧代码 |
| 确定性模拟被固定 final、测试补线或提前关闭污染 | 读实际请求选择脚本；观察正式入口；先收束生产者再核对义务，不能取消潜在重复来证明无重复 |
| 成本超过候选 CI 预算 | 测量后分片/复用编译，不削输入、重启、种子、窗口、冥想或 fsync；仍超再请求裁定 |
| runner/检查器扩展尚不存在 | 文档明确拟新增；旧 checker 不作为新图通过证据 |
| 真实模型、微信、掉电、72h 与训练制品未授权 | 保持独立待验，不影响已授权规划，不能称发布门全过 |

## Migration Plan

本轮不迁移或部署。未来实施保持旧机制和数据基线可回退；新增 API/格式先裁定，禁止原地改用户数据。取得归档授权后，单写合并嵌套 delta 到顶层 `specs/`，核对同名 requirement，再标准 archive 与主 spec 校验，不跳过同步。
