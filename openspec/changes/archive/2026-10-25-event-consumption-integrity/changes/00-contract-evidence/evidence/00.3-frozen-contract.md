# 00.3 契约冻结与裁定（摘要）

基线 `6cc441436c2aab15edcee34cf2561086232c8311`。输入：00.1 盘点、00.2 复现（两红证两轮可复现）、00.4 基线（三模块绿；deterministic 一项既有间歇漂移 `S11 parent_pipeline_after_order` 1/5，非本次引入）。结构化真源为 `00.3-frozen-contract.json`，本文件为摘要。

## 五轴（冻结口径）

1. **责任身份**：随动回合归属原会话责任范围（会址不变），携带 TaskID/通知身份因果；不合批、不改投（Handoff 除外并记录关联）。
2. **事实引用**：Event key 不代替通知身份；载荷原样保真；重复运输同键幂等，同身份异内容具名冲突。
3. **运输重试**：不改投、不重造通知、不补写无关联用户事实；运输次数与业务输入分别计数。
4. **逻辑消费**：同一通知材料在一次逻辑消费中**恰好一份新输入**（各路径合计恰 1）；忙时通知必须保留可恢复；领取不提前确认、位置不跨空洞、已确认不重做；历史重现不算重复。
5. **外部发送**：动作身份独立（send/答复/附件/分片均合法）；已确认不重发；结果未知保留未确认、不自动重发、不伪报成功；不承诺渠道端恰好一次。

## invocation 版本冲突裁定：resolved（语义收窄）

主规格内部两代术语并存（"归属原 invocation" vs "task_settled 触发的新顶层 turn 取当前代"）；基线 6cc4414 已实现为新 invocation + 正文 ready input，规格滞后。红证证明缺陷在材料双路与忙丢，与 invocation ID 字符串无关。裁定冻结义务不变量（会址归属 + 任务因果 + 单路材料 + 忙时保留 + 当前代版本），由 01 域 persistent-event-loop delta 承载，归档时同步主规格。被否：字面复用原 invocation ID（改动深、与演进冲突、诉求不涉及）。**该裁定为重大取向透明项：用户可推翻；推翻成本=重写 01 域 delta 并重开 01.3 方向，01.1 不受影响。**

- **G3** `InjectMessageWithSource` 为历史入口名；02.2 按当前 `Run.CommitToSession` 取证四道门；纯引用条款不改写，归档勘误。
