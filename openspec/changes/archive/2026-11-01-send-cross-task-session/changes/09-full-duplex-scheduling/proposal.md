# 09 full-duplex-scheduling：全双工消费调度（R7）

父变更：send-cross-task-session（依赖：02 消费面——实现依赖）。**首叶=断言实证**（design D13）：R7 断言本轮未实证，实证为假则本域降为"测量缺口"登记。

## Why

R7（⚠️ 待实证）：Task 层异步受理已存在，但"受理后仍等待所列调用结果；慢工具与跨来源合批的既有测量未通过"。`consumer-loop-convergence` 主 spec 已钉"消费循环 SHALL NOT 等待全部派发工具完成"——若断言成立，即实现对既有 spec 的欠账。

## What Changes

- 9.1 首叶实证：复跑既有"慢工具/跨来源合批"测量（dispatch 等待目标测试），确认断言真伪。
- 若真：消费循环收敛到既有条款——工具派发后不等结果、慢工具在跑时新输入按时进下一次决策、同会话多来源输入按预期合批、结果回到正确责任范围。
- 若假：登记"测量缺口"（既有测量未过=测试债而非行为债），排期另行裁定。

## 边界与依赖

- **依赖**：02（重入的消费面交互）。
- **被依赖方**：F 收尾。
- **接口面**：`runtime/agent/loop.go` 消费循环、dispatch 等待点。
- **禁止事项**：不改 Task 责任与会话决策占位约束（既有语义）；不实证不动工（R34）；不借机重构 loop。
