# Design: doc-truth-residuals

## 决策

1. **残项不混批**：P0（缺陷）与 P1（转录待裁）各自独立小批次；每项动手前须单独裁决，不因"都在本 change 里"而默认放行。
2. **仪器先行（P0-1/P0-2）**：merge-check 的两处判据缺陷与 23 条 Test 类 map 缺口先修——它们是其余一切对账读数的可信度基础（本 change 立项本身就是两轮评审用该仪器验出来的）。
3. **行为类修复单独立法**：P0-4（静默 0 条）与 P0-5（countingSpawner）若裁出行为改动，须在该项下补 spec delta 与先红后绿测，不借本 change 的收口名义直接改。
4. **无 spec delta 的项**（P0-3/P0-6/P0-7/P1 全部）以 tasks 台账承载，验收即该项自述的判据；唯一例外是 P0-1 的仪器判据，落一条 ADDED Requirement 于 `code-documentation`。
5. **上游债标注**：P0-6（origin/dev 0a31e46 的 compress 105 重名）属上游 CI 缺口，本仓侧只加"测试可编译"门，不替上游修因。（2026-09-30 复核修正：CI 已有编译步，缺口实为触发分支不含 dev，项已改名"CI dev 分支覆盖"。）
6. **评审转录先复核**（2026-09-30 立项当日新增）：归档评审的结论是**时点快照**，转录为任务前必须对当前 HEAD 核存在性——本 change 自身即例证：P0 七条复核后 3 条改判关闭（testsupport＝编译面≠链接面；静默 0 条＝安全默认态已文档化；countingSpawner＝已修复有钉测）、1 条改名。改判理由与证据坐标记录于 tasks 9–12，关闭项不删行、以划线＋改判留痕。
7. **台账的根因归因同样要复核，不只复核结论存在性**（任务 2 执行中新增）：一次 `comment-check` 报 CODE-CHANGED 被归档台账归因为"等价门的判定含空白敏感性"，并据此立了操作守则"遇 CODE-CHANGED 必须逐行看 diff 定性"。新旧仪器 A/B 复跑显示唯一差异恰来自该文件，真因是 `TypeSpec.Comment` 槽未清（一处工具缺陷），与空白敏感性无关——归因错了，守则就把工具缺陷洗成了操作负担，并使修复被推迟。⇒ 复核三层：**结论是否存在 → 归因是否成立 → 由归因导出的守则是否该保留**。

8. **主 specs 的吸收判定不用标题匹配**（任务 13 执行中新增）：一次"delta 是否已吸收"有三种互相独立的状态——ADDED 缺位、REMOVED 未撤、MODIFIED 正文漂移；只看标题会把第三种误判成"已吸收"，只看正文差异又会把"后续 change 的更新"误判成"未吸收"。判据取两路并查：正文级逐条比对 ＋ 时间序（主 spec 最后修改时间 vs 归档动作时间——三件 resident 归档**至今未跟踪**、相关主 spec 最后改于 09-10／09-27，故是未吸收而非被取代）。补立内容一律**以现行码面＋wiki 起草**，delta 原文只当索引；每条需求落笔前必须有码面坐标（函数／常量／调用点／守护测试），无坐标不写。反向同样成立：主 spec 若与码面矛盾（`async-task-execution` 的旧超龄条款），改写时只保留码面仍真者并指向 owning 能力。

9. **台账坐标：符号为主、行号为辅，且必须在本批编辑之后重取**（任务 6 执行中自证）：给 `tagent.go` 的 doc 插入 10 行后，我在同批台账里刚写的 `:775/778/781`、`:636-640` 全部下移 10 行而失效——行号是**本次编辑的产物**，不是被引用对象的属性；同批还有 `:387 区` 这种由偏移推算、未回文件核就写下的假坐标（真值 `:397`）。⇒ 规矩：**可 grep 的符号名是唯一稳定坐标**（`RegisterCloser(orgOwnerCloser{…})`、`changedMemoryAgents(…)`），行号只作辅注且须在编辑之后重新取值；凡未在同一屏输出里出现过的行号不得入台账。

10. **共享工作树下不得采信全局计数门，也不得 `-update-baseline`**（任务 8 执行中自证）：棘轮类门的语义是"整树计数"，两个任务同写一棵树时，任一方都可能把对方的违规读进自己的证据链，而"把基线收紧到实测值"这一常规收尾动作会**把外来违规洗成合法**——与本 change §14.1 记载的前科（用豁免面掩盖映射错误）同形。实测分钟尺度内 11→25 findings。⇒ 规矩：并发期间只按**自己改动面的文件**取证（逐文件扫违规＋`comment-check`＋编译面），基线**手工只降自己确证的两条**，不动别人条目；`lint rc=0` 此时不构成有效证据，报告须如实标注失效原因。
