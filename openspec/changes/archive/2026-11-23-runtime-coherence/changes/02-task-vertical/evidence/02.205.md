机理（静态对照 `HEAD` 与现行分支）：`HEAD` 的 `FactAlreadyPresent` 有**三条出口**——(1) 本进程已登记且链携带 → reduce；(2) 本进程已登记但链不携带 → 直接返回、不折叠（防并发同事实二次折叠）；(3) 本进程**未登记**（链持有而本进程从未落地，即不确定屏障）→ `carried=false` 落到 landing（登记＋折叠）。现行版本把 (2)(3) 合并为"一律 reduce 后返回"：

- 丢 (2) → 并发同一事实双提交各折叠一次（`[same-fact-once same-fact-once]`）。
- 丢 (3) → 不确定屏障后的重试既不折叠也不登记（`0 registration`）。

而 retry 三项需要的 reduce，针对的是**本进程曾落地、但其登记已被 `trimFacts` 随投影折叠释放**的事实（`seen=false`、`registered=false`）——在 `HEAD` 正好落进出口 (3)，故重放 landing、范围倒退。

结论：出口 (3) 的"链持有且本进程无登记"桶里今天混着**两个相反人群**——"曾落地后被 trim"（须 reduce）与"从未落地、屏障不确定"（须登记＋折叠）；仅凭 `r.facts` 成员资格无法区分，因为它正是被 `trimFacts` 抹掉的信号。修复需引入独立于 `trimFacts` 的判据（如本进程已应用身份的留存记录，或序列/覆盖态中能在改写后存活的信号），属**生产代码改动**（`assembly/facts.go`），不在本单写面，亦触碰 §五契约，故按派发停止条件停下上报，不自行改。

### 9.1 判据最终形态（落点 `assembly/facts.go:229-264`，`chainAlreadyPresented`）

一句话：**身份落在该链已呈现的材料之内（记录时刻 ≤ 已呈现段的最新时刻）⇒ 重复；落在其外或该链尚未呈现任何位置 ⇒ 落地**。

- 已呈现段 = `replayEntry.endedPrefix()` 界定的前缀（`endedAt` 之前全部 ＋ 闭段那个 output；开启在飞段的那条 input 属在飞），取前缀内各条目 `Time` 的最大值。`endedAt` 为空或指向已被折叠消费的条目时，`endedPrefix()` 按既有契约返回 `Len()`（全部已呈现），判据随之整段取界。
- 比较量是**记录时刻**而非投影位置：位置会被 fold 重写（`request.go:397-410` 既有注释），身份与时刻都不被重写。判据只读已注册序列（`r.replays`），不读 `r.facts`，故独立于 trim；不建第二登记集；每次判定 O(窗口内条目数)，不随历史增长。
- 三场景归位：并发（对手落地、本进程从未登记）走 `registered` 出口，一次折叠不重折；屏障（`carried=true`、无已注册序列 ⇒ 判据 false）落回登记＋折叠一次；retry（输出已闭段、登记随窗口释放 ⇒ 记录时刻早于整段 ⇒ 重复）走 `ReduceRepeat`，不重开轮次、不重述材料。
- 三出口的最终形态：①`registered && carried` → reduceRepeat；②`registered && !carried` → 直接返回（本进程已折叠过的并发同事实）；③`!registered && presented` → reduceRepeat（不登记）；④`!registered && !presented` → 落地（登记＋折叠）。`carried = false` 与 switch 后 `if carried {…}` 分支按 HEAD 原样保留（HEAD 中即不可达，保留即最小 diff）。

### 9.4 自决与偏离

1. 判据取"记录时刻"而非候选里的"链记录序"。`ledger.StoredEvent.Seq` 是**窗口内**槽位（`segment_store.go:24-28`：`Seq is the sequence slot the event takes inside that window`），跨窗口不可比；全局 commit 序未暴露给 `assembly`，取它须改 `memory/ledger`（写面外）。时刻与投影条目 `Time` 同源（`mappedEntryOf` 写 `Time: evt.Timestamp`），且 fold 生成的产品条目其 `Time` 取自被覆盖材料（`coveredMomentOf`/`process[0].Time`），不会把已呈现界的时刻抬到在飞材料之上。
