## 一、实现形态

1. **校验落点**：`FileSegmentStore.EachIndexNewestFirstFrom`（segment_store.go:1183-1214）。落位在 `commitOrderSeek` 断言之上、两个走查分支之外，引擎无关；`indexEntrySeek` 与 `eachIndexEntryNewestFirst` 未改。
2. **谓词形态**：走查包裹 `namingVisit`——每命名一条 index 条目即比对 `key == from`，落位为 `namedFrom`。走查结束（visit 返回 false 或走到最老端）后 `namedFrom==false` → 弃该 seek、改走 `eachIndexEntryNewestFirst`（自最新端重走）。不是「首候选＝key」：一条 order line 可含多键，正确谓词是「走查是否命名进入键」。
3. **答案安全性论证**：walk 自 `lineEnd` 向最老端前进；命名 `from` 当且仅当 `from` 自己的 commit line 落在 `[lineEnd, 0)` 区间内，故命名即证明该 commit 与其后（更老）全部条目都在走查面内，答案与全序走查的 `from` 后缀一致。早于真值的 word（含 0）必不命名 `from` → 被捕获；晚于真值只多付走查、答案不变。
4. **回退纯内存**：重走经 `eachIndexEntryNewestFirst`，不调 `OrderLineEnd`/`rebuildFrom`，不写索引文件、不修盘；`order.line` 编码语义与 `journalOrderLineUnknown`（unknown 非 0）立约不动，rebuild 机器（`orderLineOf`/`orderLineOnce`）零新触发。
5. `journal.go:86-97` 只在既有「missing/unknown/越界 → costs the walk its seek and never its answer」承诺句上补点名身份校验（「one that states some other byte is caught by the walk it places…」），无代码语义改动（`git diff` 该文件仅注释行）。
6. 正常路径行为不变：正确 seek 仍只走一遍（`namingVisit` 是同一次走查的包裹，不是探针 + 复走）；见 §三 M3。
