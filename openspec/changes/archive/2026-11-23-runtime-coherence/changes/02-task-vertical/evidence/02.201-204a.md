## 三、apply 收敛终态（02.204a）

- **共用函数**：`(*MemoryRegistry).applyFactLocked(entry *memoryTask, fact CommitRecord, stamp time.Time)`，`runtime/task/lifecycle.go:405`。
- **两调用点**：
  1. 在线：`applyCommitLocked` → `r.applyFactLocked(entry, record, r.now())`，`lifecycle.go:441`（提交点已判 `CommitCommitted`，分类由提交点产生，holder 不自判）。
  2. 恢复：`foldLocked` → `r.applyFactLocked(entry, fact, time.Time{})`，`restore.go:271`（链接不带时刻）。
- **单点写入证据**：`grep -n 'entry.status = ' runtime/task/*.go`（去测试）唯一命中 `lifecycle.go:409`，即在共用规则内——两套解释已无。
- **规则内容**（一份）：`replayedStatus` 定状态 → `markMovement(状态, stamp)` → status/revision/mutations → `handoffTargetOf` 交接 → `replayedRound` 轮次 → outbox 展开为投递义务＋`seq.Observe`＋轮次高水位 → 终态关执行义务。
- **规则外（按契约 §一“外置面”）**：移动戳由调用方给（在线 `r.now()`、链接零值）；`noteActivity` 活动脉冲留在 `applyCommitLocked`；重入的 `ObligationAwaitingTool`、`ttlAnchor`、`reported` 留在 `Reactivate`/`Resume`；`Admit` 的准入义务也留在原处。
- **调用点适配**：`Advance`/`Resume`/`Reactivate`/`RollbackReactivation`/`Handoff` 删去各自重复派生（`entry.round++`、终态关义务、`applyHandoff`），改由规则统一产出（`lifecycle.go`、`manager.go`、`reactivate.go` diff）。
- **唯一一处在线语义归并**：在线路径现在也 `seq.Observe` 已提交通知身份（此前只有恢复路径做）。效果＝已落账身份不再被 `IssueNotice` 二次发放；`Observe` 单调只抬高不回落，对既有调用点是无操作（预告身份本就由 `IssueNotice` 抬高），见下节锚全绿。
- **残余双份**：无。`foldLocked` 现只保留“首链接建 entry、身份冲突/断链拒绝、幂等 repeat 返回”，业务解释全在共用规则里。
