## 一、实现形态

1. `assemblyConfig.plugins`（单工厂）→ `assemblyConfig.pluginBuilders []func(*Run) ([]plugin.Instance, error)`（工厂序列）。**字段改名**：`check_plugin_mounting.py` R5a 按 append 目标尾标识判"具体成员挂载"，`plugins` 同时是 `Run.plugins []plugin.Instance` 的容器名，保留旧名会让 `c.plugins = append(c.plugins, build)` 被误判为挂载（实测 `ERROR: assembly/run.go:1556: R5a pipeline collection takes a concrete member 'build'`）；改名后 `mounts=0 errors=0`。语义不变，见 §六。
2. `WithPlugins`：赋值 → `append`，公共签名不变；nil builder 仍为"不贡献工厂"（改前 `WithPlugins(nil)` 是 no-op，见 §九-3）。
3. 执行序（`assemble`，run.go:599-608）：`pluginBuilders` 声明序 → 各工厂**恰好一次** → 产出并入**本地** `contributed`，全部成功后才 `r.plugins = contributed` → `mountBuiltinPlugins` 追加。Boot 侧：调用者工厂与代际注册先重放，Boot 自家 `hostPlugins` 工厂（host.go:698，原位置/目录序不变）随后。
4. 失败清理（§五）：第 k 个工厂失败 → `fmt.Errorf("tagent: build the run-level plugins of factory %d of %d: %w", …)`（具名位置＋`%w` 不吞原始错误）；已完成工厂产出实例只留在本地切片，**不进 `r.plugins`、不进任何绑定**；`Instance` 无生命周期接口，资源释放归产出工厂（合同原文），装配根不做第二次释放。
5. reload（§二乙）：`Reload` 全程不触碰 plugins，run 级集跨代存活；`WithPlugins` 文档把"换集需再 boot"从"未定义"升格为显式声明。零行为变化。
6. Boot 转交：`cfg.pluginBuilders` 与 `cfg.genRegistrations` 在 host.go:634-639 重放，先于 Boot 自建的 `telemetry/governance/memory/meditation/exec/faces` 注册；宿主自家注册的相对次序（meditation 先于 faces）不变。

## 三、负锚与 reload 乙语义锚

```sh
go test ./assembly -run '^TestFailedPluginFactoryReleasesCompletedFactories$' -race -count=5
# 隔离树 exit 0；主树 exit 0
go test ./assembly -run '^TestReloadKeepsContributedPluginsObservingCommits$' -race -count=5
# 隔离树 exit 0；主树 exit 0
```

- 负锚经**公开 `Boot`**：工厂 1 成功、工厂 2 失败（哨兵 error）、工厂 3 在失败之后。断言：Boot 必须返回错误（基线里 Boot 成功 = 贡献被丢弃，见 §二）、`errors.Is` 命中哨兵、错误文本含 `factory 2 of `（位置具名）、工厂 1/2 各跑 1 次、工厂 3 跑 0 次、失败工厂执行时 `len(run.plugins)==0`（已完成工厂产出未挂接）。
- reload 锚经**公开 `Boot`＋`Reload`＋`Run.Invoke`**：boot 一次驱动 → 观察计数 >0；改写 `replay_window: 40` 触发一档换代（`Publication.Published=true`）→ 再驱动；断言贡献实例观察计数增长、新观察的每条 fact 都能从 `CommittedEvent` 读回、工厂构建次数仍为 1（未重装）。
- 附加序锚 `TestBootPublishesContributedPluginsAheadOfItsOwn`（`-race -count=5` 双树 exit 0）：发布集头部按声明序是调用者两个实例、`len(plugins)≥3`（宿自家随后）、各工厂各 1 次。
