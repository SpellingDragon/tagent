### 1.2 注释写死的三件事

`judgeContributedSliceCoverage` 文档三条：全链回放对已覆盖持有者无害（reducer 按事实身份幂等，契约 §一/§五）；只对非内置生效，故稳态成本不变（内置面在稳态都被 cut 陈述，仅新贡献首次迁移付一次 O(历史)）；触发条件＝确有 cut 被恢复且已挂持有者未被其覆盖（无任何 cut 时走查本就整链）。文档末附 `契约:` 行指向 `docs/wiki/platform/platform-subsystems.md#framework-checkpoint`（该页 §六 已补同一条规则）。

### 1.3 与契约 §三 D4 的关系（自证过一遍）

内置集是协调者里的一份「切片名清单」，与 §三「不按切片名特判」表面冲突。判据是默认方向：集合外一律按「无法自行兜底」处理→全链回放（安全侧），新增消费者**不改此处即正确**；只有某消费者**新增**了自述兜底才需要把名字加进来，加不进来也只多付一次历史读，不影响正确性。真正的自证风险（协调者解析业务载荷、按切片名分歧义业务语义）没有发生：本判定只读切片名与注册表，不读任何 payload。

## 四 边界与未触面

- 触发面只覆盖**装配期已挂**的持有者（`WithStateSlice` 经 `assemblyConfig.stateSlices` 注册、框架自挂的 `RegisterStateSlice` 亦在册）。boot 之后才挂的消费者不经此处——其挂载发生在切已恢复之后，本判定不再有决策点；该形态当前无生产路径，且保留名（`restoredFallbackSlices`）由 `WithStateSlice` 在装配期具名拒绝，不允许借名冒充内置。
- 无任何 cut 的 boot 不置位：该路径本就整索引走查，贡献者的全链已由走查覆盖（`TestBootMountsAContributedStateSliceAndRestoresIt` 的首次 boot 即此形态）。
- 一次 cut 之后新增贡献 → 该 boot 付一次 O(历史) 读；随后本进程落的 cut 必然述其切片，稳态回到有界路径（`TestCoveredContributedSliceKeepsTheBoundedBoot` 钉住这一侧）。
- 未改进程内时间、未改持久格式、未新增公共接口、未改 `runtime/**`、`features/**`、`api/**`。
