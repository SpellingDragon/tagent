## 一、收敛形态与落点

改动前（F3 缺陷）：义务由两个在线调用点各自追加，恢复路径没有对应实现，同一链在线 `obligations=[awaiting-tool]`、恢复 `[]`。

| 面 | 改动前 | 改动后 |
|---|---|---|
| round | `replayedRound`（`restore.go:281`，含 `opensRound`） | 不变（本就是单点） |
| execution 义务 | `Resume`（`lifecycle.go:383` 旧）与 `Reactivate`（`reactivate.go:89` 旧）各自 `append` | `applyFactLocked`（`lifecycle.go:424-428`，键＝`opensRound(taskID, fact.MutationID)`）单点 |
| `Resume` / `Reactivate` | 各自追加义务 | 只提交记录；在线/恢复共用同一 apply |
| `Reactivate` 外围 | `ttlAnchor`、`reported` 就地写 | 保留在外围，补注释说明其为「时间戳/报告外置」：锚是活迁移的戳（链折叠读不到、也不据以推断），verdict 是不入链的报告 |

顺序取舍：`opensRound` 的追加放在 outbox 追加之后、终态收口之前（`lifecycle.go:413-429`）。真实 re-entry fact 非终态，该位置与改动前的切片位置逐位一致（在线行为不变，见 §二）；若链上出现终态与开轮前缀并存（非法生产者产物），终态收口仍胜，`closeExecutionObligation` 的「终态不欠 turn」不被绕过。此顺序派单未定，属本单自决，记于 §四。

`applyFactLocked` 文档同步改写：删去旧断言「execution obligation 留在规则之外」（F3 已证伪），改为三条真机理——开轮 fact 开义务、终态 fact 收义务、entry 创建开准入义务且 admit fact 不再开第二条（`restore.go:255-257` 与 `Register`（`lifecycle.go:261`）同形，恢复链以 admit 链接为首链，不重复）。

## 四、偏离与自决申报

1. **顺序自决**（派单未定）：`opensRound` 追加置于 outbox 之后、终态收口之前。依据：真实 re-entry 非终态⇒在线切片位置与改动前逐位相同（§二实测）；非法终态+开轮前缀时终态收口仍生效，不新造「终态欠 turn」。代价：终态收口与开轮追加的先后成为可读契约，已写入 `applyFactLocked` 文档。
2. **未迁移其他在线副作用**：核对后 online-only 副作用只有 `ttlAnchor`、`reported`（`reactivate.go:92-93`），按派单「时间戳外置契约已允」留外围并注释；`noteActivity` 属活动脉冲，本就在 `applyCommitLocked` 外围，未动。
3. **既有用例体抽函数**：`TestTaskOnlineAndRestoreApplyOneRule` 原直筒体逐字搬入 `twoSettledRoundsState`（仅签名层变化、断言零改），以便两条腿并列；`-run '^TestTaskOnlineAndRestoreApplyOneRule$'` 仍匹配，子测试照跑。
4. **红证用 `go test -overlay` 逆补丁**（非整树复制）：逆补丁落在 `/tmp/wingC-prefix`，主干零改动、可复跑，避免并发单在场时出现「主干瞬间红」。
