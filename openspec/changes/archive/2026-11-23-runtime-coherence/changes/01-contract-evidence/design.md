# Design · 01 契约与取证

## D1 取证方法

| 疑点 | 方法 | 判定 |
|---|---|---|
| Boot 不承接贡献 | 用公开 `Boot` ＋ `WithPlugins` 挂一个观察插件，经真实模型请求观察是否被调用；复用 `assembly/host_test.go` 既有装配夹具 | 插件未被调用＝已复现；被调用＝驳回 |
| 审批失败后状态分叉 | 在隔离副本注入回答写失败（复用 `approvalWriteSeam`），随后取 `SnapshotEvidence` 并重启；断言请求仍为未决且未放行 | 快照丢项或重启误放行＝已复现 |
| 已知键扫描 | 在既有 `TierFacts` 外侧计一次读取的键/值数，对比 `Get` 与 `Scan(key)` | 扫描族枚举＝已复现 |
| 索引零偏移 | 在隔离副本把 `order.line` 字改成零偏移并重开，调 `GetParent`，与全序走查对照 | 答案不同＝已复现；相同＝驳回或另因 |
| 任务双解释 | 对同一提交序列分别走在线与恢复，按可观察状态（状态、修订、轮次、义务、收据）对照；时钟不参与比较 | 不一致＝已复现 |
| 新消费者缺片 | 旧 checkpoint 不含新消费者切片，重启该消费者 | 空态启动＝已复现 |

反证不成立时保留探针与输出，写“已驳回”，不为维持方案强造红。

## D2 四契约的比较与选择

- 状态派生：选“每消费者一个有类型 apply”，否“全仓万能 Reduce”。理由：身份与事实归属是消费者专属，万能接口会把解释权摊给所有持有者且无法表达缺片。
- 覆盖：选“切片自述覆盖”，否“投影进度代表全部”。理由：新消费者无投影事实时会静默漏读。
- 存储：选“共享契约表达点读与扫描；复用既有 `Fetch{Key}`”，否“仅前缀扫描＋消费者断言”。理由：已知键被迫扫族，成本归错层。
- 装配：选“正式入口统一承接；工厂顺序固定、一次调用、失败清理”，否“再追加一个 `WithPlugins`”。理由：现行 option 是赋值语义，追加会覆盖。
- 材料：选“声明归一后驱动同一分派；保留六端口与兼容读法”，否“删端口/任意时机组合”。理由：安全时机是主规格与消费者依赖，删端口不等于简化。

## D3 停止条件

- 持久格式、公共接口签名或安全时机需要改变：停回设计门，列替代与全部消费者。
- 某疑点复现失败：关闭该疑点并保留反证，不扩为实施单。
- 契约与主规格冲突：以主规格原文为准，冲突条目标“暂缓/待裁”，不擅自改主规格。

## D4 签发区（01.102–01.104 实施前填写）

每契约须填：候选指纹；已证/已驳项；所选方案与否决理由；精确生产/测试/文档写面；接口/格式变化；全部真实消费者；三锚全名、命令与预期命中；相邻回归；权限与数据边界；独立设计审；回滚触发。
