# 设计：注意力三预算制（attention-budget-architecture）

## Context

远端 trajectory（2026-09-27，67 次调用实测）确立的事实基线：338K/409.6K=82.5% 水位、18:03 一次 compaction 回收 5.6%（刮 thinking/action×52、L3 仅 +4）、159 条 settle 常驻 483K（含 17 条 22K 旧 cap 历史债 ≈350K）、150/158 段为 Sx1 交错。发送侧 600 cap 与 settle 专属折叠路径（意图无视段龄）均已存在——缺的不是治理，是**退出的正确触发单位**。

### 被推翻论断清单（防跑偏资产，实施期间回看）

| 曾有论断 | 修正后事实 |
|---------|-----------|
| settle 与用户消息同为骨架、唯一出路 L3 | settle 有专属折叠路径（无视段龄意图），被「连跑 ≥2」前提架空 |
| 发送侧无体积治理 | 600 cap+spill 完备（9ee362a 起）；22K 为旧 cap（≈256K）时代历史债 |
| 30min 窗口无压缩 | 18:03 有一次；锯齿浅振幅恰是骨架层永不被深触的原因 |
| 遥测需要上下文层积压上限 | 宿主裁决：积压有界性由任务层 TTL reaper + batch-retire N→1 汇总保证，上下文层不设上限 |

## Goals / Non-Goals

**Goals:**
- 常驻上下文与运行时长解耦（~75-80K 稳态），注意力密度 >90%
- 遥测退出的确定性时点：已外显 ≈1 turn、内部性 N 轮、未消费不可丢
- 空转（自激振荡）可观测、可自愈（自动冻结，同构 disk block spawn）
- 存量与增量历史债有清出路径

**Non-Goals:**
- 不改骨架红线、durable 四态、事实链不可变、TTL 遗忘曲线、600 cap、SmartCompressor 定级表
- 不引入 LLM 决策压缩（消费状态为客观可推导事实）
- 不做 recall 预取、跨 agent 通道共享（YAGNI）
- 存量清债（运维动作，前置独立执行）

## Decisions

### 决策 1：消费状态为遥测退出的唯一语义单位（替代相邻连跑/预算深度）

**消费状态判定（客观推导，零 LLM）**：`已外显 := settle 的回收 turn 有 agent_output 且经 outputCh 投递宿主`；`内部性 := 回收 turn 完成但 output 未外显`；`未消费 := 无对应回收 turn`。实现挂点在 processTurn 既有的 turn 收尾纪律点（endTurn/finishDurableBatch 一族）——**只改投影**（红线 4 允许），事实链不动。foldSettleRuns 保留（风暴形态），与消费降级幂等共存。

**否决的替代**：按数量/体积设积压上限（宿主裁决 A+TTL 分层治理——任务层已保证有界性）；LLM 判断消费质量（违反确定性原则）。

### 决策 2：通道身份显式化——task_settled 脱离对话时间线

回收 turn 装配中 settle 以通知卡片（≤300 chars，复用 settleFoldRowMaxChars 票据行语义）呈现；failed 卡片打 ★（复用 extractCardLine 的 ★ 渲染，内容级约定零新代码）。看板成为任务状态的唯一呈现。**渲染纪律不变**：卡片归 user 侧、system 恒单条、assistant 恒真实。

### 决策 3：N=keepRecent 值同源引用（宿主裁决，零新旋钮）

内部性提醒轮数在实现上**引用 keepRecent 的解析值**（消费边界现读，§6.4 pull 模型同款），非独立配置——热更 keepRecent 时自动跟随。不设 per-type 配置。

### 决策 4：审计 L3 冻结与 disk block spawn 完全同构（宿主裁决 2a：自动执行）

复用 spawnGate 判定链新增触发源：Blocked 语义与 disk 退化一致（进行中任务不冻结、新 spawn 被拒、文案如实）。**保护性任务豁免白名单**：资源租约（retention guard）、mem_spill 重放、重试修复类在冻结期继续放行——耐久性防线不撤。L1 告警事件按未消费级完整投递（宿主必见全文理由）。占比指标与分级动作记录入事实链（可 recall）。

**否决的替代**：治理闸式人工审批（等待期代价有界但与"冻结能力=最高 critical"的对称论证被宿主裁决否决——空转的量化信号+豁免白名单足以支撑自动执行）。

### 决策 5：compaction 豁免未消费（伴生不变量）

L3 预算升级跳过含未消费 settle 的段（或先触发其消费）——防积压峰值触线时误归档。实现于 buildRetainedRefs/预算升级路径的段筛选。

### 决策 6：召回暂存同受投影生命周期管理

recall 取回的内容以暂存 ref 入投影，消费完按分级降级——递归闭环防召回洪水。暂存 ref 标记来源（recalled），不进骨架定级（按遥测通道降级规则走）。

### 决策 7：跨重启消费状态重建不新增持久化面

投影重建（WAL 回放）时按「settle 事件 → 其后回收 turn 的 output → outputCh 投递记录」序列重导出消费状态——投递记录已在事实链/outputCh 溢出落盘中。

## 实现红线（anti-drift）

| # | 漂移形态 | 防线 |
|---|---------|------|
| R1 | 为绿改测/弱化断言 | 验收基线锚定实测数字（338K→区间水位、驻留 1 turn） |
| R2 | 顺手重构压缩器/定级表 | Non-Goals 负面清单；diff 仅触声明的代码落点 |
| R3 | 给 N/上限加配置项 | 宿主裁决明令零新旋钮；值同源引用 |
| R4 | 冻结误伤耐久性 | 豁免白名单测试必须先行（保护性任务在冻结期可 spawn） |
| R5 | 消费降级违反「Compact 只改投影」 | 降级操作全部走投影 Replace 族；事实链只读 |
| R6 | 通道分离悄悄破坏 prefix-cache | 前 75% 验收含「稳定前缀区字节稳定性」测试 |
| R7 | 遇阻绕行/静默改道 | 停下记录冲突证据，上报裁决 |
| R8 | **「完成但未达预期」的结构病重演**（前序五因） | 4.3 实测回执为归档阻塞项；轨迹回放固化为 Go 回归（5.1）；回执超时 48h 升级提醒，不得静默沉淀 |

## 被推翻/修正论断（第二版 review 增补）

| 曾有论断 | 修正后事实 |
|---------|-----------|
| 稳态水位 75-80K 单值承诺 | **区间化**：L2 收敛生效 → 75-80K；未生效 → 锯齿态（act 间积累+act 清空，极端每 10s 心跳 × 3K chars ≈ 1M chars/h，均值随 spawn 频率）；本变更只修退出单位，未动进入形态（act 间平铺=容量门控语义保留） |
| 合成 fixture 足以验收 | 真实轨迹回放（159 条 settle）实测 disposition 命中 156/159（98%）、fold 降幅 97.2%——**回放必须固化为 Go 回归**（tasks 5.1），教训见下 |
| externalization 键形想当然 | msgs 层无 metadata（回放被迫保守 internal 口径即证据）；实现读 FullEvent.Metadata 路径正确，但真实键存在率须 4.3 抽验 ≥20 条 |

### 前序大变更失效五因（本计划的结构性教训，R8 据此而立）

①验收用合成形态非生产回放（9ee362a 连跑测试 vs 真实 Sx1）；②源头分析与修复设计因果断裂（限流只治批量退役源，折叠锚定连跑形态，自管循环无人对应）；③DoD 无效果门禁（34/34 归档而效果未验，offline_bench 是生成 fixture）；④观测窗与容量门控生效节奏错配（折叠只在触线瞬间生效，被动等触发必迟到）；⑤度量债不回灌任务系统（09-17 回执承诺复测，义务只活在邮件里）。**共同结构病：变更度量单位是能力交付，问题域需要效果增量。**

## Risks / Trade-offs

- **[消费判定的完备性假设（延迟理解）]** → 卡片+票据即被动提醒的紧凑形态；★ 承载失败痕迹进反思通道；N 轮短期提醒兜底跨轮引用
- **[自动冻结误判]** → 量化占比信号 + 豁免白名单 + 分级动作入事实链（可回溯审计）；L2 收敛先行，L3 仅在收敛无效后触发
- **[旧投影形态迁移]** → 执行代候选事务内完成（drain-free）；迁移失败 fail-closed 回旧代
- **[时序模式从状态层消失]** → 轨迹智能归冥想 digest（既有机制补统计口径），不进常驻层

## Migration Plan

前置：存量清债运维动作（独立执行）→ L1-L2（通道+降级，单一结构代）→ L3-L5（看板/审计/召回，第二结构代）→ 全量验证 → 按归档纪律 archive。每阶段独立可回滚（revert 单代）。
