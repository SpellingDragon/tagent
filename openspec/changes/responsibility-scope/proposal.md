# 责任范围收缩：统一停在责任，执行语义留在适配器

## 主题（第三方建议直译）

「缩小统一的范围：统一已接受工作的责任，保留各执行领域自己的语义」——task 统一边界停在四个问题：接受了什么工作？谁负责推进到明确结果？结果交给谁？哪一步仍未确认？tmux 退出判定/子 Agent 结束/远程恢复留给执行适配器。

## 五项与优先级（评审排序：去写权→训练外移→端口压平先行）

1. **去写权（先行）**：LogicalStatus 纯读数保留；StatusProgress 若不改变允许的操作→记录进度事实即可，删状态写权；Count/Blocked/Open 报告不自维护（从权威记录计算）。判据（评审原话）：**删掉这个状态后能否从已有记录无歧义地算回来？能，就优先删除它的写权。**
2. **训练语义外移（先行）**：Loop 的 Recorder 窄接口仍知 Episode/Decision/Attempt 训练形态——核心只留执行证据（实际请求/输入引用/工具调用/已归约结果/因果），训练模块自行组织 episode/样本/反馈。**必须保留：实际模型输入调用时固定（Snapshot），不靠事后猜测。**
3. **插件元模型压平（先行）**：Material×Product 若不用于真正的组合推导→删组合词汇，保留六具名端口窄接口（call→call/call→ruling/request→environment/fact→observation/fact→view/fact→compression）；六端口不因数量合并。
4. **热更新收紧（随后）**：三档明示——模型/提示词/工具声明走新代发布；存储根/持久化格式/底层资源所有权要求重启；固定配置走同一发布机制只发布一次。/reload 面收口。
5. **task 越界检查（验收贯穿）**：最终验收（评审原话）：接入新工具时适配器只需提供执行、取消及必要恢复证据；宿主无需另写通知补偿队列；核心无需新增一种生命周期状态。

## 必答一问

「五项完成后，接入一个新工具还需要宿主补偿或新生命周期状态吗？」——不会：验收测试（新工具适配器只给执行/取消/恢复证据即可跑通受理→结算→投递全链）+ 各项「删掉后无歧义算回来」的反事实判据绿。
