# 设计决策（待 grill 拷问后修订）

D1 去写权判据（评审原话转译）：每个独立写权状态过反事实检验「删掉后能否从已有记录无歧义算回来」——能→删写权改派生（LogicalStatus 纯读数先例）；不能（改变允许操作）→保留并写明依据。StatusProgress 候选删除；Count/Blocked/Open 报告改从权威记录现算。
D2 训练外移边界：核心保留执行证据=实际请求（调用时固定）、输入引用（EventID）、工具调用、已归约结果、因果关系；Episode/Decision/Attempt 的组织移到训练模块（Recorder 接口收窄为执行证据提交，训练侧自组样本）。禁止：删执行证据、事后从历史猜输入。
D3 端口压平判据：Material×Product 若仅作命名装饰（无按 Material 集合路由/组合推导）→删类型词汇，六端口各留具名窄接口与派发依据；EXTENSIONS.md 同步；六端口闭集不合并（评审：纯化应减少解释成本，端口不因数量合并）。
D4 热更新三档：新代发布（模型/提示词/工具声明）/要求重启（存储根、持久化格式、底层资源所有权）/一次发布（固定配置）——/reload 端点按三档收口（越档变更明确拒绝并具名）。
D5 task 越界检查法：遍历 runtime/task 对执行细节的引用（tmux/子 Agent/远程语义）——发现即列档（回卷到适配器或写明责任边界依据）。
D6 grill 循环（沿用用户指令）：grill→修复→grill 直到无新有效问题→派发；success-semantics 残留终判并入首轮 grill。
