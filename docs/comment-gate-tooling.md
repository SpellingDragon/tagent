# 注释门禁的工具面

本页承载 `scripts/codetools` 与 `scripts/comment_policy` 两个门禁可执行的机制判据。源码注释只留一行职责与指向本页的索引，理由写在这里。

<a id="usage"></a>
## 一、命令面

| 可执行 | 子命令 / 主要 flag | 产出 |
|---|---|---|
| `codetools strip` | `<file>...` | 去注释后的规范化代码（`go/printer` 输出），跨修订可比对 |
| `codetools decls` | `<file>...` | 每个顶层声明一行 JSON：是否 test/benchmark、去注释体哈希、断言调用数、`t.Parallel` 数 |
| `codetools comment-check` | `--base-root DIR --head-root DIR <file>...` | 逐文件证明"只改了注释" |
| `codetools merge-check` | `--base-root DIR --head-root DIR [--map FILE] [--explain FILE] <dir>...` | 证明并入批无损（体一致 + 断言数不降） |
| `comment_policy` | `[-baseline F] [-update-baseline] [-strict] [-no-baseline] [-v] [dir...]` | 注释形态棘轮 |

两条共同纪律：

- 路径一律是**模块相对路径**，必须在两个根下都存在（`comment-check`）或存在于 head 根（`merge-check`）；基线根由 shell 包装用 `git archive` 物化，不依赖工作树状态。
- 任何不可读或不可解析的输入都**以非零退出**——静默跳过绝不能伪装成通过。

<a id="equality-witness"></a>
## 二、等值见证的语义：什么算"只改了注释"

门禁比较的是**去掉注释之后的代码**，因此"什么被算进这份见证"就是判据本身。

### 清注释必须清干净

`clearComments` 丢掉文档注释而**保留编译器与工具指令**，使打印出的代码语义不变。指令（`//go:build`、`//go:embed`、`//go:noinline`、`//export`、`//line`、cgo 预处理行）不是文档：增删一条会改变构建行为，所以一个宣称"只改了注释"的门必须把它们留在被比较文本里。实现只读 `File.Comments`，因为那里装着文件里**每一个**注释组，包括附着在声明上的；树所能容纳的每一个注释槽都必须被清空，漏一个槽就等于允许一次未证的改动过关。

### 空行是格式，不是代码

`dropBlankLines` 删掉纯空白行，并去掉残留行的行尾空白。理由：删除一条注释合法地留下它占用的空位，那是**格式**而非代码；`gofmt` 洁净度由它自己的门负责，所以这份输出是"只改了注释"的等值见证，不是格式见证。

**带字符串字面量的行一律豁免**，包括原始字符串内部的空行：那些行是数据，修剪它们会让一处被改过的 fixture 冒充未改动的。

### 限定符遮蔽

`qualifierBlind` 把每一个包限定符前缀替换成固定标记。并入批允许**逐文件**统一某个 import 路径的别名，而一份包级文本映射表达不了这种"每文件一次"的决定——它会把同一个拼写改写成两种样子，凭空造出差异。遮蔽限定符之后，每个选择器名（因而每次调用的语义）仍然可比，而别名选择对见证不再可见。

遮蔽是**代码层面**的关注，止于字面量的边缘：fixture 里的一条点分路径不会被误遮蔽。

<a id="table-discipline"></a>
## 三、影子表与豁免表：一次只允许一份

`--map`（影子索引表）与 `--explain`（豁免条目）各自**只持有一份文件**，且属于被检查的那个包：

| 约束 | 后果 |
|---|---|
| 重复传同一个 flag | 用法错误，直接拒 |
| 某条豁免在本次运行中没有免除任何声明 | 拒绝该条目 |
| 表文件读不到 | 让调用失败，而不是当作空表加载 |

三条同源：一份被遮蔽的表、一条对任何东西都不生效的豁免、一份静默为空的表，都会让一次"读数通过"成为门禁从未真正挣到的通过。

表按构造是**每包一份**——跨包的表会把一个域的归一化规则套到另一个域的基线文本上，凭空制造违规。因此多包运行必须逐包各调一次 `merge-check`，各带自己那一对表。

<a id="ratchet-scope"></a>
## 四、comment_policy 的棘轮语义与作用域

`comment_policy` 检查的是白名单：文档注释只允许陈述契约，任何指向长寿命文档的指针必须使用索引形态（`契约:` / `规格:`）。

- **长度从不决定合规**：一条很长的契约注释合法，一段很短的设计叙述不合法，唯一裁判是内容形态。
- 查询棘轮的运行在任何计数高于基线时非零退出；`-v` 打印全部 finding 而不只是回归；`-strict` 额外要求**收敛终态**：finding 为零。
- 目录参数递归扫描，**跳过自带 `go.mod` 的子目录**。正因为如此，棘轮拒绝在一个把嵌套模块留在门外的集合上运行，也拒绝使用与写基线时不同的集合——否则基线里的数字与被检的树不是同一个对象。
- `-no-baseline` 是纯测量模式：不查棘轮，只报当下 finding。
- **作用域是仓库，不是工作树**：被 git 忽略的 Go 文件从计数中剔除。忽略的文件不存在于任何 checkout，携带其 finding 的基线记录的是一个任何克隆都无法复现的预算，而降档批次就会被拿只存在于单台工作树里的数字来度量。
  - 一个键可以指向目录：git 会把整棵被忽略的子树折叠为其目录路径，而它只在其中**没有任何被跟踪文件**时才这样做，因此目录键会排除其下一切。
  - 不在工作树内、或没有 git 时，集合为空、扫描覆盖磁盘上每个 Go 文件。
  - 除"没有忽略项"之外的任何查询失败都**上报而不是咽下**：一个坏掉的调用不得伪装成"什么都没被忽略"。
- `scripts/lint.sh` 持有权威目录集合，因此批次作者与 CI 扫的是同一棵树；读基线、降基线都必须经它，不要用临时 scope 直接调这个命令。

<a id="tracked-hygiene"></a>
## 五、追踪卫生门

`codetools tracked-hygiene` 守仓库的**索引**，四条判据各自具名拒绝：

| 拒绝原因 | 含义 |
|---|---|
| `runtime-artifact-tracked` | 路径名是运行产物（`.lock`/`.journal`/`.tmp`/`.spill`/`.prof`/`.test`/`.out`）：测试或进程在工作树写出的东西进了索引 |
| `empty-tracked-file` | 零字节文件被提交 |
| `tracked-path-missing` | 索引里有、工作树里没有 |
| `unregistered-top-level` | 出现未登记的顶层目录 |

一条路径命中多条规则时逐条都报（残骸目录同时是产物与未登记目录）。顶层目录集合以代码里的显式白名单为准，新增目录必须**同时**登记 README 布局说明：布局给人读，白名单给机器执行，二者必须同批变更。白名单初值由当时的索引快照生成——手打过一次，漏了两个目录，门第一天就红给自己看。

判定逻辑是对文件列表的**纯函数**（尺寸由注入的 `sizeOf` 提供），单测因此不需要 git 仓库；live 命令只是把 `git ls-files` 的结果喂进去。接入点是 `scripts/lint.sh`，本地与 CI 同一条命令。

<a id="dotted-refs"></a>
## 六、点号引用门

`codetools dotted-refs` 查的是**运行时会真去 import 的位置**：shell 里 `python -m <模块>` 的后续 token、yaml 里 `workflow:` 的值。判定：点号换斜杠后在仓库内存在对应 `.py`（或包的 `__init__.py`）即通过；否则必须命中显式外部允许表 `externalModuleAllowlist`（前缀匹配，每条须附用途说明，**空表才是健康态**）。

不做全文件点号扫描是有意的：`scheduler.type=local` 这类配置覆盖语法、文档行文里的包名都会被误伤。门的强度来自位置精确，不来自范围贪大。扫描面是 git 索引里的 `*.sh`/`*.yaml`/`*.yml`，排除 `openspec/`（规格会原文引用已退役路径作为记录）与 `archive/`、`_tmp_report`。

本门的出生背景：AReaL 在线训练桥退役时发现，`train_rl_config.yaml` 里的 `workflow: train.rl.tagent_adapter.*` 指向 AReaL 改名前的包布局——这类"看着对"的死配置，此前没有任何机器门能看见。

<a id="test-file-split"></a>
## 七、测试文件的域锚切分

巨型测试文件按域切分时，同位门定死了合法形状（三条事实）：

| 事实 | 后果 |
|---|---|
| 文件的域锚 = **第一条** `契约:`/`规格:` 行的值 | 想让文件代表某域，就把该域锚写在文件头（先于任何内部索引行） |
| 同 (目录, 包, build-tag, 锚) 出现 ≥2 个测试文件时，缺 `<stem>.go` 精确镜像者判碎片 | 域文件必须各占**唯一锚**；同锚的测试只能留在同一文件里 |
| 无任何顶层 `Test*` 的文件不参与计数 | 共享 stub/fixture/基准可另立 `*_support_test.go`（零 Test 声明 ⇒ 豁免），这通常是最大的一刀 |

推论：**被门挡住的拆分不是好拆分**——若某域的锚已被别的无镜像文件占用，正确动作是"收敛锚"（docs 侧合并小节）或放弃该次拆分，而不是给文件起一个假镜像名字。镜像比对故意不容糊（仅 `_real` 后缀在白名单内），否则改名压力会被溶解。

拆分必须无损：整函数搬运、断言与预算零改动，判据为 `go test . -list '.*'` 计数前后相等 + `check_test_merge.sh` 判 intact。

<a id="commit-scope"></a>
## 八、提交范围一致性门

`codetools commit-scope` 查的是**提交信息与实际改动范围是否相符**：标题以 `docs(` / `docs:` 开头的提交，若改动集里出现代码路径（`*.go`/`*.sh`/`*.yml`/`*.yaml`/`*.py`，`docs/`、`openspec/` 与 `*.md` 除外）即具名拒绝。

形状来自一次真实事故：`git mv` 在执行的那一刻就把重命名写进索引，随后不带 pathspec 的 `git commit` 会把它扫进下一个提交——无论那个提交本意是文档还是代码。于是一个标称 docs 的提交带着半套包迁移上了远端，全新检出不可编译。

规则只看标题承诺，不看改动多少：要关的是"把代码伪装成文档"这一类，不是文档量。默认检查 HEAD（`commit-scope [ref]` 可指定），历史扫描留给 CI 之外的批量核查。
