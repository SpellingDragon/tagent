tagent 存储：回放装载 · 时光回退 · Session Fork

单文件离线演示 —— 数据取自真实生产存储（examples/wechat-bot/.wechat-config/data，1.0MB）。存储形态：不可变事实链 + 按语义前缀分片快照 + 因果追加日志。

§1磁盘上有什么（真实实例）

分片标签 = key 第一个冒号前的前缀。同会话全部事件聚在同一分片、按时间序编址 —— 这是时光回退与 fork 友好的物理基础。

文件角色key 形态（实测样例）
kv/144/snapshot.json 364KB·462条会话 144 的事件链：全部事实正文，一条不删144:evt:1792928044000:1
kv/976/snapshot.json会话 976 的事件链（另一会话，独立成片）976:evt:<毫秒>:<序号>
kv/tagent%2Ftask%2Fv1%2Ffact/ 340KB·149条任务迁移记录（不覆盖写：admit / settle 各存一条）…v1/fact:task-1\0settle:task-1:1
kv/tagent%2Ftask%2Fv1%2Fconsume/消费回执（阻止重复投递的唯一凭据）…v1/consume:<席位>
kv/tagent%2Ftask%2Fv1%2Fspec/ · attempt/任务规约 / settle 尝试终态…v1/spec:task-…
kv/ref/ 74KB·164条引用登记（跨会话血缘，fork 后仍可溯源）ref:1-784fbbd7aa3b…
kv/blob/大对象正文blob:<id>
relations/relations.journal 追加日志因果链（WAL 形态）：谁引用谁，Append 返回即持久RelationRecord（JSON 行）
写入：一批 kvBatch 触碰哪几个分片，就把那几个 snapshot 写临时文件 → 原子 rename 换入。不存在半开状态；跨批无事务，正确性靠「先登记 owed、后消费回执」的顺序不变量。

§2重启怎么装载（点步进）

恢复 = 时光机开到 HEAD。同一条重放机制，把边界换到任意 key，就是时光回退。

§3时光回退：拖动光标，重放到边界

12 条 mini 链（1 会话 × 2 任务）。左轴 = 磁盘上按时间编址的事件/迁移/回执；右侧 = 「此刻重放投影」实时重算 —— 状态不是存的，是算的。

重放投影（as-of ）
链上原始事实（全部保留，折叠只发生在投影层）
事件（正文事实） 任务迁移（admit/settle） 消费回执 as-of 光标
给模型看的上下文 = 重放到边界后按当前预算重算（Full → Ticket → Summary）。presentation 不落盘 —— 所以「任意时刻 × 任意预算」的模型视图都可复现。

§4Session Fork：前缀即身份，复制前缀即分叉

会话 = key 前缀。fork = 把该前缀的分片在分叉点前复制成新前缀；血缘靠 ref: 登记与因果日志保留，两条链从此互不干扰地各自追加。

当前缺的是这层「fork 门面」（复制分片 + 改前缀 + 新会话地址登记）—— 物理布局已天然支持，属薄封装；分支后修正走前滚（新事实续写，如 replacement fact 先例），不改写历史。

§5友好度结论

场景现状依据
时光回退（as-of 读）天然友好能力在，接口缺事件按 evt:<ms>:<seq> 时间编址；迁移不覆盖；重放即投影。补一个「读到 key X 为止」的读面即成 API。
回到之前上下文天然友好正文链全量保留；三龄段折叠只动投影层；按预算重算 → 任意时刻×预算可复现。
Session Fork布局友好门面缺分片=会话前缀聚簇（144/976 实证）；复制前缀即复制链；跨链血缘在 ref: 片 + relations.journal。
回滚重跑（branch/rewrite）范式外链不可变，修正=前滚。git 式改写历史需单独立案，是范式变更非补丁。
