# 组件级评估套件（evals）

`evals` 是**组件级行为评估**的执行体：`go test ./evals/` 用 mock 即可跑并进 CI；需要真实 LLM 的项是 opt-in（与 `tests/` 同样的跳过约定）。它的定位是**用断言把"记忆命脉"和"工具面路由"钉住**，而不是衡量模型聪明程度。

<a id="ticket-recall"></a>
## 票据可召回率（零幻觉契约）

构造事件 → 用 `FormatEventKey` 生成压缩卡片上出现的召回票据 → `ParseEventKey` → 取回原文并断言完整。这是**全量往返**而非抽样：任何一张票据取不回原文，评估就红。理由票据是模型唯一能"自己写出来"的寻址手段——它一旦不可靠，症状是"自信地召回错内容"，比崩溃更坏。

<a id="bad-case"></a>
## 畸形票据必须显式拒绝

非 hex、空串、纯空白、带前缀冒号等畸形票据一律返回错误，**绝不返回空结果**。空结果会让上游把它当成"这个键没有历史"继续推理，即把一次解析失败伪装成一条事实（历史教训的资产化）。

一个例外是刻意保留的宽容：**`0x` 前缀是票据的合法回显形式**（模型常这样复述），必须正常解析——它作为特性被回归守护，不是巧合。

<a id="op-whitelist"></a>
## 工具面路由白名单（漂移即红）

`refine` 的 `op` 只接受白名单内的操作；不在名单内（例如已随发布道退役的旧操作名）必须被显式拒绝。合法操作在异常环境下也要**如实报错而不是静默成功**（例如非 git 工作区下的台账读取会明确失败）。这一条守护的是"工具面契约不发生漂移"，无需真实模型即可判定。

<a id="handoff-contract"></a>
## handoff 四段契约的存在性

子 agent 的提示词必须包含 handoff 四段（任务／上下文摘要／交付物／验收标准）。这里做**存在性断言**：任何一段被删掉，评估立刻红——契约漂移的守护不该依赖模型调用。

<a id="fuzz-seed"></a>
## 模糊测试的用法与崩溃样本回放

键格式解析这类"输入形状不可信"的函数用 fuzzer 覆盖：以 `go test -run FuzzX -fuzz FuzzX -fuzztime=<预算>` 定向跑。**崩溃样本会被自动持久化到 `testdata/fuzz/FuzzX/<hash>`**，此后普通 `go test` 会把它当种子用例回放——一次发现的坏输入因此永久成为回归，而不依赖有人记得再跑一轮模糊。新增解析器时应同时留下种子目录；**不得**为了让测试变绿而删除已生成的崩溃样本（那是真实缺陷的证据）。

<a id="design-notes"></a>
## 两条设计取舍

- **不需要 LLM 就能判红**：上述四类断言都可在 mock 下运行，因此能进 CI；把"是否可信"与"模型是否聪明"分开。
- **套件清单与执行体分离**：`evals/suites/*.yaml` 与 `evals/cases/` 描述场景，`evals/evals_test.go` 承载执行体；两边不对齐时以断言失败暴露，而不是靠注释同步。
