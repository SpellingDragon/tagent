# 转世通报（保险链自替换后的首轮自我告知）

<a id="overview"></a>
## 一、这个机制解决什么

自替换换装（保险链换新进程）之后，新进程对"我是谁、上一世正在做什么、上一世断在哪"毫无记忆——档案在磁盘上，但没有任何东西把它送回模型的上下文。转世通报做一件事：**新进程启动时，把上一世的最后现场组织成一条消息注入自己的事件流**，让 agent 的第一轮就看见：自己被换装过、当时在做什么、上一轮的断点在哪。

它是**一次性启动钩子**：整个进程生命周期只投一次；它**绝不允许让机器人起不来**——任何一步失败都只记日志并降级。

<a id="detection"></a>
## 二、检测：以"换装标记文件的新鲜度"为准

| 规则 | 为什么 |
|---|---|
| 换装标记由保险链**在派生新进程之前**写好；新进程只看它是否存在且足够新鲜 | 若把"重启完成"文件当信号：它由健康门在派生**之后**才写、且总带一个活着的 PID（新进程的 PID 就是自己），按 PID 判定是我们会输的竞态 |
| 新鲜度用标记文件自身的修改时间窗判定 | 标记内容解析失败**只降级通报正文，绝不降级检测**——存在即可判定，判据不该依赖可选细节 |
| 启动后**轮询等待**标记出现（有预算上限），而不是固定 sleep 一次 | 固定 sleep 会静默错过慢写入者；错过一次等于整世失忆且无人报错 |
| 冷启动脚本从不产生该标记 | 因此冷启动不会假阳性，无需额外区分状态 |
| 相对路径以二进制所在位置为基准解析 | 不同启动器的工作目录会漂移，锚在 cwd 上会找错文件 |

<a id="notice-shape"></a>
## 三、通报正文的三段结构与令牌纪律

1. **元数据段**：换装时留下的键值档案（按 key 排序输出，保证同一档案渲染出同一文本）。
2. **尾现场块**：从事实存储取该 agent 分区内**最新的若干条事件**，按时间倒序，每条只写票据、类型、摘要与时刻。
3. **断点判定**：见下节。

令牌纪律（通报是要进模型上下文的，不是日志）：只取有限条数；每条摘要**截断**；**绝不带事件全文**——全文可由票据水合，进通报只会挤占上下文。

取尾事件必须**显式带上该 agent 名字派生的分区**：分区存储里不带分区条件的查询会扫零个分区并"静默返回空"——那会让通报的现场块永远显示"无事件"，而这不是事实。分区推导必须与装配层同源，否则读写落到不同命名空间。

**降级不得静默**：档案缺失、查询失败、事件为空，三种情况各自在正文里显式写出降级原因，并同时记日志。宁可把"我不知道"写在脸上，也不要用一份看起来完整的通报掩盖数据缺失。

<a id="breakpoint"></a>
## 四、断点判定：只判"是否中断于回合中途"

事件按新到旧取回，因此**最新一条**就是上一世的最后动作：它是思考中或工具调用中且**没有收尾输出**，判为"上一轮中断于此"；若最后一条已是收尾输出，判为"回合已闭环、无未兑现迹象"。

判定文本必须带上行动要求：**续作前先核验该时刻的承诺是否已兑现**（对照事实链与系统实态），不得凭通报默认成功。这是这段文本存在的唯一理由——否则通报只是叙事，不改变行为。

<a id="delivery"></a>
## 五、投递：必须走专用注入源

通报经**专用来源**注入，而不是复用其它内部来源：投递门对内部来源有扣留策略，复用会让通报"写了却看不见"。该来源在消息链路上被路由到用户会话——**通报的目的就是被看见**。

<a id="consumption"></a>
## 六、消费标记与重复代价

注入后把标记文件重命名以记录"已消费"。重命名失败**只告警且不致命**：代价是下一世可能重复收到一次通报；在这里崩溃的代价大得多。两害相权取可观测的重复，不取不可观测的失忆或宕机。

## 已知缺口与演进方向

- 新鲜度窗、事件条数与摘要截断长度都是**经验值**，未做过召回质量与令牌成本的实测标定。
- 通报只在启动时投递一次；若首轮被其它消息抢先消费完上下文，本世可能读不到它——尚无补偿路径。
