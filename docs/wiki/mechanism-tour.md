# 十分钟机制导览

> 目标：十分钟读完，对"事件怎么生产、插件挂在哪、模型怎么收发、异步任务怎么续跑"有完整心智模型。各节括号内是深读入口。

## 1. 一条链：唯一真相

系统只有一份权威记录——**事实链**。每个事实（用户消息、模型输出、工具结果、通知、压缩请求、冥想注入）经**单一入口** `commitFactChecked`（facts.go）提交：存储层先落盘、活账本后登记；拒收即报错（绝不"成功但没存住"）；同键同内容幂等、同键异内容具名冲突。

一次提交，三处同时知晓：查询表（关键词检索）、向量管线（语义检索）、映射序列（该会话的投影，供下轮请求回放）。**其余一切读面（缓存、投影、折叠、呈现）都是从这条链派生的，崩溃后从链精确重建。**

## 2. 三个挂点

| 挂点 | 语义 | 深读 |
|---|---|---|
| **事件 x**（生产） | 不可变事实落链，带来源戳 | [agent/event-flow.md](agent/event-flow.md) |
| **插件 f(x)**（管线） | 请求路径上的可追溯映射 | [plugin/plugin-architecture.md](plugin/plugin-architecture.md) |
| **消费 g(x)**（读链） | 一消费多事件、增量读 | [memory/memory-architecture.md](memory/memory-architecture.md) |

## 3. 插件：六个端口，按"时机 × 失败语义"分三类

插件不问"相位"，只声明**端口**（api/plugin/material.go 闭合表，装配期校验）。真正要理解的是端口所在的**时机类**——它决定失败时谁被拖住：

| 时机类 | 端口 | 能做什么 | 失败时 |
|---|---|---|---|
| **副作用前**（写路径，阻塞调用） | `call→call`、`call→ruling` | 纠正调用 / 分级裁决（治理门在此拦调用） | 拦住调用（fail-closed） |
| **提交后**（旁路，不阻塞任何事） | `fact→observation` | 监控一切已提交事实（遥测/训练采集/折叠/续跑/热换） | 观察者记缺口继续；**驱动者保义务**（SettleDriver 失败≠账销） |
| **读取时**（派生面，幂等可重建） | `fact→view`、`fact→compression` | 按渠道呈现 / 发起压缩（产物是新事实，原文不删） | 视图丢失上报 / 压缩欠账 |

一句话记住边界：**调用可以在执行前被拦截转换；事实提交后对插件只读——转换永远作用于派生品（视图/投影/压缩产物），永不作用于事实本身。**（request→environment 是特殊的一位：给请求装配注入环境材料。）

## 4. 模型怎么收消息（一次请求的装配）

`requestBoundary`（request.go）按稳定序装配：

```
[固定前缀] 提示词 + 技能正文（缓存友好：稳定的放前面）
[投影历史] 该会话已结束的部分——每次现算呈现：
           全文→票据→摘要 逐级降级；通知类永不被预算丢掉（保底身份卡）；
           出口前补回调用配对（tool_call_id），压缩后/冷启动后协议仍合法
[就绪输入] 本次新消息 + 未呈现过的通知（按事实身份定边界，折叠重写也不怕）
```

在飞调用的中途结果走**轮内回流**（Backflow）：直接注入当前决策下一轮，不另起回合。

## 5. 模型怎么发消息（输出→投递）

```
assistant 输出 → 作为事实提交（提交失败=回合失败）
→ 从"已提交事实"找待发正文（不信内存副本）
→ 投递审核（可挂起→持久待审批表；批准恰一次补投；拒绝具名作废）
→ 渠道送达；失败自动转为持久补投义务（重启后仍欠）
```

## 6. 异步任务：受理与结算分离，mailbox 是唯一唤醒账

受理立即返回**最小回执**（`{callID taskID accepted kind}`——只是"收到了"）。结算旅程：

```
执行完成 → 终态通知：TrackDelivery → 入 mailbox → Claim
        → 回流（在飞的当轮直接消化）→ 消费回执最后落（顺序不可倒，重启不重投）
发起回合已结束 → mailbox 账上有未消费项
        → SettleDriver 只发一个 wake（不记第二本账）
        → pump 读账 → 先落 durable attempt（防重启双驱）→ 驱动续跑 → 销账
        → 回调失败：条目留在账上等下次唤醒
```

跨重启恰好再驱动一次（真进程 SIGKILL 测试钉住）。

## 7. 冥想：事件驱动，没有定时器

冥想（features/evolution/meditation/driver.go）是纯观察者：观察到"有交互在等"的新事实、且距上次反思过了节奏下限、且上次反思已被消费——才起一个独立反思回合。产出作为新输入推主循环；跨会话写入只经 `deliver_summary` 工具（模型显式决策，机制绝不静默代笔）。**没有新事件，就永远不触发。**

## 8. 消费面就是流处理器

若你熟悉流式编程，消费面正是那张对照表：

| 流式概念 | 本系统 |
|---|---|
| source 流 | 事实链（单一入口） |
| map/降级 | 投影呈现（全文→票据→摘要） |
| window/聚合 | 三龄段折叠（AgeFold）、压缩 |
| 查询/投影 | recall 语义检索、训练导出 |
| 带游标的独立消费者 | 增量读（身份定界、NoticeFeed 游标） |

重型流处理都住在消费面（带自有可重启状态）；插件层故意薄——各管一段窄面。

## 9. 四条不变量（全部有"故意弄坏会红"的测试钉住）

1. 已提交事实，重启前后语义相同；
2. 任何模型请求，压缩/恢复后仍协议合法；
3. 每项已接受的任务与交付责任，要么有完成证据、要么有可恢复的未结状态；
4. 每份可变状态有唯一所有者，他人经声明接口访问。
