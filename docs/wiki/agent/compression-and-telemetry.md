# 上下文压缩、会话投影与自身遥测

本页承载 `agent/compress` 一侧的判据：预算不足时**保留什么、丢掉什么**如何可核查，投影折叠为何不能重复，以及"内部状态要不要外显"由什么决定。三件事的共同点是失效都不报错——只会**悄悄丢内容**、**重复注入同一条事实**，或**长期沉默无人察觉**。

<a id="condensed-card-guard"></a>
## 一、综述卡片必须机器校验，票据不得凭空出现

压缩产出的一行综述卡片在采纳前逐项比对被折叠掉的输入行，判据三条：

| 判据 | 为什么 |
|---|---|
| 输出票据 ⊆ 输入票据 | 伪造的票据会进入 compaction 载荷，**污染其后每一次召回**（召回出来的"原文"根本不存在） |
| 头、尾与每个 ★ 高亮行的票据都必须存活 | 它们是导航锚点与长期反思结论，丢了就等于把"去哪找"抹掉 |
| 输入含票据而输出一个都没有 ⇒ 拒绝 | 这是票据全丢，不能被当成"压缩得很彻底" |

两条边界：输入本身不含可解析票据（散文类样本）时**不拒绝**——守卫只约束真实票据；整个校验零 LLM 调用、零存储读取，因此可以在每次产出上无条件跑。

<a id="projection-fold"></a>
## 二、会话投影是"可回放折叠"，不是历史缓冲

装配上下文读的是投影，事件全量另存于记忆存储。三条约束：

- **带键事件幂等追加**：同一 `EventKey` 第二次追加被跳过并告警——重复投影会让同一条事实出现在上下文两次；无键（`EventKey==0`）不参与去重，总是追加；
- **重建按当前引用整表重算**去重键集，因此被折叠掉的键会随之离开键集，键集大小只随重建有界（若沿用旧集合，它只增不减）；
- **读取返回拷贝**：装配侧改写结果不会影响投影内部状态；
- **无锚点链回退时先过滤、后全量复原**：完整分页重放必须先滤掉非投影记录，再把全部有效事件复原进上下文——MUST NOT 施加数量截断（丢掉最旧有效事件是数据丢失，不是内存治理；中间内存靠分页扫描约束）。过滤在前是硬顺序：若先取一批再过滤，登记与内部回执记录会把真实历史挤出去——名义上"重建了最近窗口"，实际只剩回执。

排除"哪些记录不进投影"的判定只有**一个来源**（事件类型注册表提供的谓词），与正常提交、冷启动重建共用同一处。各处自带类型枚举，就会漏排内部回执，把回执注进投影，破坏"投影＝事实链可回放折叠"这条不变量。

<a id="telemetry-ladder"></a>

## 三、自身遥测的可见性是分档升降的，不是一刀切

内部状态要不要外显为宿主可见的提示，由滑动窗口样本决定：窗口时长、负例占比阈值、最少样本数、每档驻留时间都是命名常量。两端要防的风险分别是"**看一眼就永久外显**"（噪声淹没宿主）与"**长期沉默无人察觉**"（降级一直发生却没人知道）。

统计口径本身要收窄：只计入**自管谱系**（冥想、任务退役、未知来源）——这些产出不是用户发起的交互；判据与投递门使用**同一份**负例清单，两处各写一份必然分叉。

<a id="output-overflow"></a>
## 四、工具结果超限：内联留摘要，全文转储并留票据

超限时不是截断丢弃，而是**内联留可读摘要 ＋ 全文转储为文件 ＋ 票据可找回原文**。两条约束：

- **内联上限与 token 预算解耦**：按 `MaxTokens/2*4` 一类的公式派生，会在 128K 预算下算出约 256K 字符——那是一个无人负责的公式后果，不是策略；
- **转储绝不阻塞主循环、绝不静默丢弃**：消费者停滞时也要落盘并留票据，与结算大结果转储同构。

声明侧对未超限结果透传；`nil` 结果与结构体结果都必须有确定行为，不能靠"看起来是空"来推断。

<a id="self-state-digest"></a>
## 五、自我状态摘要：呈现必须有界，且被裁掉的数量要显式报出

冥想触发时前置注入的自我状态摘要是**反思的输入**，覆盖面是单一形态（机制判据见 [agent 引擎篇 §2.14](./agent-architecture.md#meditation-curator)，本页只承载"呈现"这一条）：主体是**观察面概况**——判据窗口、引用页与水合计数、逐分区的"非自管／自管与未知"分谱系计数，以及最近一条非自管活动摘要；观察面缺省＝自身分区时这份概况就是**自体近况**，自身任务层健康（按状态计数＋需关注项简摘）降为可选段，距上次冥想执行时长恒含（判据窗口以执行水位为头）。概况段直接由那次新鲜度判据攒下的证据渲染，**不为摘要再扫一遍事实链**（两次扫描会给同一判据交出两份可能不同的证据）。

三条界约束对任何观察面同时成立：需关注任务与列出的观察分区都**最多固定条数**，超出折叠成"另有 N 条／N 个未列出"，被裁掉的数量必须以"共 N"显式报出而不是静默省略；描述与摘要**按 rune 截断**（按字节截断会切坏中文）；聚合按**固定顺序**计数，避免同一份状态每次渲染顺序不同。全程**零 LLM、纯函数、不阻塞**——摘要是交给模型的证据，不是又一次推理。

没有控制器时，任务段**缺席**，而不是产出一个空壳段落——空壳会让模型以为"看过且无事"。冥想 agent 通常自带空任务层，同一条降级规则让它照常渲染分区概况，不因"自己没有任务"而整段消失。

<a id="hot-bundle-atomicity"></a>
## 六、热参必须一次读全，不能逐字段取

压缩边界要用的那组数值（触发线、内层目标、以及与之配套的一项开关）**必须由一次读取整体取出**，因此外层触发线与内层压缩目标一定来自同一代。逐字段各自读取会跨代撕裂：先读到新代的触发线、后读到旧代的目标值，预算判定就落在一对从没同时存在过的参数上——这种错不会报错，只会让压缩"看着不该发生却发生了"或反之。取不到有效值（零或非法）时回落到构造期的值：一个还没有任何记录的属主也必须算得出合理预算，不能因缺值而不出预算。

<a id="summary-deadline"></a>
## 七、同步摘要必须有共享时限，晚到的答案不得回写投影

一轮真折叠里有两处低频 LLM 叠加（卡片浓缩与滚动叙事）。它们的判据不是"要快"，而是**折叠不能为一次挂起的摘要付两遍代价**：

| 判据 | 内容 | 佐证 |
|---|---|---|
| 一个时限覆盖整轮 | 同一轮折叠的**所有**摘要调用共用一个带 deadline 的子 context，因此"每调用各计一次超时"这种把一轮拖成 N 倍预算的形态不成立 | `context_compressor.go:summaryCtx` |
| 缺省有源 | 未注入或注入非正值一律取包内常量单源（`DefaultSummaryTimeout`，5s），**没有"无时限"这个选项**；配置面不复述这个数字 | `effectiveSummaryTimeout`、`defaults.go:DefaultSummaryTimeout` |
| 父 ctx 取消即停 | 取消必须让当轮摘要立即失败而不是挂起；折叠本身仍要完成（走既有纯工程降级：卡片下沉为票据计数、旧叙事保留） | `Compress` |
| 迟到即丢 | 超时后晚到的模型文本**丢弃**，绝不回写投影——晚到的综述会让"已折叠"这件事在事后被改写 | 摘要结果只在 `summaryCtx` 有效时被采纳 |
| 不重试、不异步 | 摘要失败就是降级，不是重试的理由，也不是交给后台补写的理由 | `buildRetainedRefs` |

配置面 `summary_timeout_seconds`（`config.AgentConfig`）的边界与包内语义同源：`0` 表示"用包默认"而不是"关掉"，负值是具名校验错误（`ErrSummaryTimeoutNegative`）。正值**不设配置上限**（曾有 120s 上限，2026-10-10 部署侧大输入综述三连超时实证后移除：小窗口对 40 万 token 级输入根本不可完成，时限沦为永久降级开关；上限拦住的不是风险而是合法显式选择）——真实兜底双重存在：时限一到即走机械折叠兜底、回合照常推进，provider 的 `request_timeout_seconds` 才是硬终态。

它与本页第六节的五个热参**不是一组**：这项时限进的是 per-agent **结构指纹**里的压缩族（`org.agentSubset.Compress`），属于"重建才生效"的构造期数值，不是第四条热通道。把它塞进热组会让一次不重建执行面的数值轮转悄悄改掉一个构造期就装死的 deadline——那正是第六节要防的跨代撕裂的反面：**同一族数值必须走同一条生效路径**。

## 已知缺口与演进方向

- 守卫拒绝时只返回理由文本，缺一个"哪条票据丢了"的可枚举输出，排查要靠人读日志；
- 投影键集有界依赖整表重算，重建成本随活跃引用数线性，尚无实测上限；
- 遥测阶梯的占比与驻留参数缺跨场景标定（高频短回合与长驻留任务的节奏差别很大）。
