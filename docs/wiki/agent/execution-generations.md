# 执行器代际、租约与生命周期收敛

本页承载 `agent` 根包里最容易在重构中丢掉的一类判据：**一个回合到底在哪个执行器上跑、那个执行器什么时候可以回收、以及关闭时必须向调用方诚实到什么程度**。这三件事的共同失效模式都不报错，而是"配置静默不生效""旧绑定复活""数据被并发写入打断"。

<a id="generation-not-fingerprint"></a>
## 一、发布身份是代际序号，不是内容指纹

同一套行为被重新发布成**新的一份**时，必须被视为新一代：如果按内容指纹去重，热更新"重发同一形状"就会被判为无变化，参数因此静默不生效。反过来，**同一代的重复发布不得算作新一代**——否则回收判定会把一份仍在被引用的执行器当成退役对象。

两条由此可判定的性质：

- 候选构造**不触碰在线执行器**，也不留下未回收的退役代；
- 重发布同一张面时行为保持，不因"看起来没变"而跳过发布。

<a id="lease-holds-reference"></a>
## 二、租约是引用的唯一载体

引用只在**租约存续期间**有效：一次回合持有一个租约，跨回合的长期闭包（任务、重入）**不得借用发起方的租约**，必须按子调用另取一份。由此：

| 情形 | 期望 |
|---|---|
| 已收敛关闭的代 | **拒绝**新引用，并给出明确拒绝理由，不复活它当时的绑定，也不静默改投 |
| 已退役但仍被持有的代 | 派生的子调用仍可落在它上面（引用计数决定回收，不因"标了退役"就断） |
| 解析源里已摘掉的名字（模拟后续代移除） | 同一请求必须转为**拒绝**，而不是回落到某个仍然可用的名字 |
| 借来的壳（未持有真实引用） | 不得被当作有效执行器使用 |

回收判定的唯一输入是"引用是否全部落账"，因此诊断面（在途回合、未收敛的退役代）必须能一次性回答这个问题，而不是让人去数日志。已退役引用的泄漏有明确的告警阈值——只标注、不自动干预：自动清理会掩盖真正的引用泄漏位置。

<a id="lifecycle-convergence"></a>
## 三、关闭：必须收敛，且诚实优先于干净

关闭序列按注册顺序执行各 closer；某个 closer 报错**不得中断**其余 closer，错误要汇总上抛。并发的第二次与第 N 次关闭**返回第一次的结果**（同一次关闭只发生一次）。

收敛的**退场必须当场通知等待面**：释放事件的消费不能只靠下一次流量。执行代自身的退出由 release 的 drained 敲点负责；仅经声明保持级联回收的子代不会再经过 release，故 finishReclaim 自身必须敲醒属主 org 的排空检查。pass 进行期间到达的唤醒由单飞合并（carry-over 复检），既不丢事件也不产生逐事件 goroutine——退役协议要求排空在同一个 drain 内收敛，不等待新 turn。

最关键的一条是未收敛的处理：**当某个写入者可能还活着时，`Close` 必须报错并保持持有底层存储**，绝不能在该写入者未确认停止期间退出存储。租约要显式持有——收尾尾巴可能运行在回收协程上，此时"看起来关完了"正是数据损坏的前夜。**"报错＋仍然持有"是诚实结果，"干净返回"是假象。**

<a id="turn-local-execution-face"></a>
## 四、回合本地状态与执行面的边界

一个回合内钉住执行面的时机是**进入回合时一次性冻结**，此后整个回合（含重试）都用同一张面；热更新只影响后续新回合。回合本地状态（触发源、调用元数据、借用计数）必须**每回合自己盖章**，不从上一回合继承；已清空的角色字段在属主换代后不得从上一份回落回来——回落会留下旧绑定。

需要外发的事件必须在**进入总线那一刻**就定稿归属：归属靠什么定位真源，就只能在那个时刻确定；晚到补写等于让读者按不存在的键去找。
路由表同时是**交付账本的屏障**：按调用 id 记 `pending = spawned − delivered`。它刻意只有这两件事——绑定表与账本屏障——管线收敛之后不再承担别的职责；结算目的地是被查出来的，不是从事件内容推断出来的。

路由表因此是**按调用绑定的总线句柄**：每个调用在自己的关联句柄下绑自己的总线，投递只发到该句柄的总线。并发调用同一被调方时，每个循环回收到的事件都必须是自己那份（按来源标记判定），其屏障独立到达静默——既不接收外来结算，也不共享计数器，更不早静默或永不静默。

冻结的时机是**开始执行**的那一刻，不是入队也不是发起：一次在途调用跨过一次发布，仍跑它开始时的那一代，新代不得把它偷走；发布之后才开始执行的排队输入，取的是它执行时那一代。后台生产者同理——被任务层收养的那次运行持有它开始的那一代直到落地，父回合届时可以只带着回执结束，其后由结算抬起的回合才用新一代的声明。两条边界：发布自身抬起的提示回合按当代面委派是合法的，因此"新代一次都没跑"不是合法判据，归属才是；已发布的一代可以 Offer 一个委派，模型不调用则被 Offer 的与未被 Offer 的一个都不执行——路由声明的是可用性，不是执行。

钉住动作只有一个入口：`BeginTurn` 先跑已装配的 org-config 检查（与运维钩子 `CheckOrgReload` 同一条入口，因此不存在第二条生效路径），再把当时在跑的 executor 交给回合去钉。它必须在输入批次冻结之后、传输重试循环之外调用，一个业务 turn 只登记恰好一次，且登记在它自己的代际上——计数由各代的 in-flight 引用持有，不存在第二份聚合计数。子 agent 调用不走这里：它们的实例、executor 与委派树是在发布它们的那一代内部构造的。

登记的次序是判据的一半：in-flight 引用必须在 executor 被交出去**之前**完成登记，否则一次发布与其 retire-sweep 恰好落在"交出 executor"与"进入 run body"之间的缝隙里，就会把本回合即将运行的那个 runner 关掉。返回的 release 必须在回合结束时运行——事件的持久循环把它折进每回合清理，与 `endTurnSpan` 并列。

发布本身会额外抬起一个通知回合（注入文本以 `[system-alert]` 起头），它在**当时那一张面**上解析，因而可能在新代上再次发起委派。所以"旧代在途期间新目标不得执行"这一类验收只能断言**先后顺序**，不能断言新目标从不运行——写成"从不运行"会在正确的实现上失败。同一处判据的另一半：模型在一次响应里不调用工具时，新旧两个目标都不得被唤起，委派只随真实工具调用发生。

<a id="turn-outcome"></a>
## 五、回合结果必须归约为三态，且取消不得吞掉已认领的输入

一次回合的结局只有**完成／失败／取消**三态，归约入口唯一，调用方不得各自解释错误：响应报错⇒失败；事件流正常排水完毕⇒完成；流中途被取消⇒取消。

取消这一态有配套硬要求：**已经认领的输入不得 ack**。否则"取消了"会变成"这批输入被悄悄消化掉"，下一轮既不会重放也无人知晓丢了东西（断点必须保留）。

<a id="published-wrapper-immutable"></a>
## 六、已发布对象不得在构造期被改写

执行面的装配遵循两条：

- **执行面只来自被执行器本身**，绝不回落到任何其他已发布的快照——否则被新配置清掉的角色字段会"看起来还在"（回落会把已清空的字段退回上一份）；
- **状态面（记忆插件、会话服务、投影）始终取自当前上下文管理器**：换执行器不搬运共享状态。

委派包装器住在属主的工具表里，被常驻管理器、每个候选管理器与每次调用私有管理器**共享**。因此**构造期不得往已发布的包装器里写调用域数据**（投影属于一次调用，不是属于一个包装器）：那既是对已发布对象的副作用，也让同一个 agent 的并发调用互相读到对方的投影。调用域数据经流程上下文传递；包装器绑定的唯一发布时机是冷启动那一次。历史上这条规则被"顺手接上"过一次，代价就是并发互相污染。

跨实例的投影接线只在构造期发生一次：`SetToolParentProjection` 把 agent 的 SessionProjection 挂到工具列表里的每一个 AgentToolWrapper 上，使 LLM 未传 event_keys 时仍能自动注入。工具列表在 `agent.New` 之后装的是 `OutputLimitTool(*AgentToolWrapper)`，因此这次接线必须刺穿透明装饰链（`collectAgentToolWrappers`），而不是断言裸类型——否则投影永远到不了子 agent 的 wrapper，自动注入形同虚设。这是该绑定唯一的生产发布点，且发生在 agent 仍在构造、尚未服务之时；按 ContextManager 逐个重绑的旧路径已被移除：在途调用不向共享工具发布任何东西，它自己的投影随上下文携带。

<a id="single-linearization-body"></a>
## 七、发布入口只允许一个线性化主体

两个发布入口——单属主发布与暂存代激活——必须共用同一切换主体。二者曾各持一份切换代码，并在同一个判定点上漂移：重新发布"当前已在跑的那一个"时，一份推进记录中的生效面、另一份静默跳过。

线性化主体记录新的生效面、把运行新 runner 的那一代装为 active，并返回应当退役的绑定；调用方**必须在放开 executor 锁之后**才去退役它，慢速 runner 的 Close 绝不在锁内发生。org 路径会传入一个已经接线好的绑定（声明持有、面快照），因为该绑定必须先存在并被接线、才允许任何 owner 让它可见；单属主发布没有这个前置，传 nil，绑定在此处从刚记录的面快照得到。

重新发布同一个 executor 对象**故意不算新的一代**：一个 runner 对象只得到一次 close，因此多余的发布（回滚落回同一张面、调用方重交当前候选）不得为它造出第二个身份。记录中的面仍然前进——绑定保持它被**构造**时所用的那张面，推进"被记录的东西"从不改写这一代实际路由的内容。

判据：任何会改变生效面的动作只有一个实现点，入口之间的差异体现在参数，而不是代码副本。要判断新增入口是否合规，只看它是否复用了这同一个主体。

<a id="hot-source-pull-authority"></a>
## 八、热参的权威是参数源，不是推送

热参的权威是参数源本身，而不是某处原子的上一次写入。消费边界（预算线、阈值、压缩入口）每一次都要解析完整的数值组；仅轮转参数源、不做任何推送，也必须在下一读取生效。

零读数意味着"记录没有意见"，此时由构造期的值应答——因此一次零读数不可能把在用的周期归零。派生出来的边界值（如工具输出上限）不进热面：把所有派生数字折进指纹正是判据所排除的做法。

<a id="generation-wiring-window"></a>
## 九、一次发布内的接线窗口：先全量暂存，再统一激活

`WireOrgGeneration` 承担一次 org 发布的**代际级接线**。它的时机是被判据钉住的：本次发布的**每一个** owner 都已暂存下一代、且**任何一个**都尚未激活——否则总有某条执行路径会观察到一个半接线的代际。

- **INCOMING**：每张暂存面上的 wrapper 被打上它所声明的**暂存子绑定**，声明代同时对该绑定持有一次 hold。于是一次经由该 wrapper 的调用，其子目标是从声明代自己的执行视图解析的——既不是子的"当前"面，也不是某个被捕获的实例。
- **OUTGOING（追溯）**：上一代的 wrapper 本应在它们各自暂存时接线，唯一例外是冷启动 owner——它的绑定是惰性创建的、从未被接线。这些 wrapper 现在按**仍然 active 的子绑定**补打标记。

<a id="reentry-resolution"></a>
## 十、存量任务重放（relaunch）解析用哪张面

存量子任务经 `relaunch_task` 重放时，选哪张执行面取决于"是否有仍在途的发起调用"，四种情形互斥、各有唯一答案：

- **有发起者**（持租约的在途调用）：按发起者**声明的那一代**解析。即使新一代已停止路由该目标，仍持旧代租约的发起者不因新代删除目标而丢失其合法旧代绑定；该绑定能存活，是因为声明保持让被钉那一代的子仍可达。这条只在"确实发生了一次删除目标的发布"时非空洞——无换代时两条解析分支同答，证不了读的是哪张面。
- **无发起者、属主环路静默**：从**该属主的常驻 owner 面**解析（实例常驻且未关闭），绝不从入口的面。
- **新一代停止路由该目标**：具名拒绝、附版本理由（编排代际的选择），既不重跑被移除目标、也不静默改用替身；拒绝作为答案返回，不是传输错误。
- **新一代改了该目标（仍被路由）**：无发起者的重入经**新发布面**到达新目标——未变的父也随发布推进执行视图。

解析只回答"哪个目标"，运行还须回答"在哪张执行视图上跑"。二者必须同源：重入在把属主面租约交给子 agent 之前，MUST arms **所解析那张面所声明的子绑定**——与一次正常 `Call` 走同一条 arms 路径。少了这一步，子 agent 看到的租约属于它的属主（`belongsToOwnerOf` 不成立），于是静默回落出生代配置：重入对外返回成功文案，实际跑的却是已退役的提示词、模型与工具，而运维以为当前编排在生效。属主面租约与子代声明租约**并存**，各自持有一份引用、各自释放：前者承担"派生前获取"的记账（退役排空靠它归零），后者只承担视图选择。

入口级（任务落在入口自己的 board）是同一条规则的另一端：目标被发布移除时按版本拒绝且不新建执行；目标仍被路由时经新发布面重入——缺常驻 owner 接线的候选会 fail-closed，这正是"候选构建必须把新属主接上 owner 面"要证伪的接线。跨进程重启后，重入在**当前面**解析：每段 boot 交给它自己的进程，只有真实进程启动才算证据，正负两腿各用独立持久根（负腿从崩溃状态本身重启，而非已被正腿结算过的 board）。

<a id="model-reference-pinning"></a>
## 十一、模型引用解析在"被选中的那一代"，不在"此刻的注册表"

`model_override` 让一次委派换掉服务的模型，但它填的是**引用名**，不是实例。引用必须在**本次调用被选中时的那一张执行面**上解析——否则同一次调用里校验时读到的实例与装配时用到的实例可能不是同一个，而在途调用还会被后续发布悄悄改道。

| 判据 | 内容 | 佐证 |
|---|---|---|
| 快照而非活表 | `ModelRefSnapshot` 是**一个执行视图**的只读引用集：构造那一刻注册表发布的所有名字 ＋ 该视图自己的模型挂在 `agent:<name>`（`ReservedModelRef`）之下；建好后永不写入，随持有它的代际一起消亡 | `tool_agent.go:ModelRefSnapshot`、`NewModelRefSnapshot` |
| 一个解析点 | `resolveModelReference` 是引用变成实例的**唯一**去处：只读被交来的冻结视图，绝不回生活注册表。因此"参数校验点答哪一个实例"与"装配真正用哪一个实例"必然同源 | `resolveModelReference` |
| 缺失即拒，不回落 | 视图里没有的名字是一次 miss，**绝不回落到某个仍然可用的模型**；校验点与装配点两处同答 | `ModelRefSnapshot.Resolve` |
| 钉定只有一个窗口 | `PinModelReferences` 只接受**已暂存、尚未激活**的那一代：已安装的代保持它发布时用过的快照（要换就发布新一代）；已丢弃的候选直接拒绝——不往一份已不存在的执行视图里写东西 | `exec_lease.go:PinModelReferences` |
| nil 快照是拒绝不是兜底 | 传 nil 被拒，而不是"运行时按当时注册表解析"——那第二次回读正是这个钉定要消除的缺陷本身 | `PinModelReferences` |
| 保留名冲突按名拒绝 | 注册表已用**另一个实例**占住 `agent:<name>` 时按名拒绝；因为这个构造只读注册表，失败的候选让进程级表原样不动：既不改指也不删它拒绝采纳的那条 | `NewModelRefSnapshot` |
| 换代可见但不劫持 | 后续新调用钉更新的代、读那张快照，于是晚一点的重新注册对晚一点的调用可见；已在跑的调用永不被重新路由 | `ExecLease.ModelReferences` |
| 无快照时逐字节同旧 | 没有租约／不属主／该代未发布快照时为 nil，语义与不带变参的调用完全相同（回落到正在装配的这个视图）——可选接缝不得改变老路径 | `agent/session.go` 装配处 |

引用快照里**没有模型指针逃逸到代际之外**：它不写任何耐久记录，也不进进程级表的第二份副本，`Register/Lookup` 仍是唯一的全进程存储。

## 已知缺口与演进方向

- 诊断面目前只给出计数与名字，缺"哪个持有者长期不落账"的直接定位；
- 借用壳的误用只能靠测试钉住，运行时没有断言；
- 关闭未收敛时的报告内容是可读的，但缺一个供运维二次判断的机器可解析结构。
