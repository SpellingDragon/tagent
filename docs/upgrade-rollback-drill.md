# 升级 / 回滚演练口径

> 本篇原为 inbox-v1 时代的运维 runbook（spill 遗留、目录锁、分区预检等）。该生产实现已由 runtime-architecture-convergence 移除：交付与恢复责任现全部落在事实链上（owed 记账、重启补交、config_change 控制流水），独立的 inbox/锁/指纹机制面不复存在。历史原文见 git。governance 演练引用本页时，按下面的口径记录。

## 一条升级/回滚演练必须记录什么

| 项 | 判据 |
|---|---|
| 运维可观测符号 | 真实错误串/具名错误值；定位只用「文件 + 符号」，不写行号 |
| 只读诊断 | 先给出不改状态就能回答问题的动作 |
| 纠正措施 | 显式、可审计；禁止隐式改写历史数据 |
| 佐证 | 具名测试（崩溃窗口/并发/重启各至少一腿），非人工 PASS |
| 回滚前提 | 存在未结清义务（如 owed）时拒绝降级，排空为 0 方可 |

## 现行架构下真正需要演练的两件事

1. **跨重启补交**：进程在结果产生后、投递确认前被杀，重启后 owed 记账驱动补交恰一次（`tests/integration/host/entry_delivery_owed_test.go`）。
2. **配置热换与回退**：发布换代在途请求保旧视图、失败不换代不落事实（`tests/integration/host/` 的 reload 族锚）。
