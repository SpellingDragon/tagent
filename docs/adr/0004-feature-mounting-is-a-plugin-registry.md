# 特性挂载是自由注册的插件清单，不是 schema 专属节

**Status**: accepted（2026-11-05 用户裁决，boundary-closure r13；实施在 changes/09-meditation-autonomy/ 任务 1.3c）

背景缺陷：tagent 的插件机制在**代码层**早已成立（插件实现标准端口——如冥想 driver 的 plugin.Instance/PostCommitObserver——经 WithPlugins 按 agent 绑定），但**配置与装配层**把每个特性焊成 agent 声明的 schema 专属节（`agents.<id>.meditation`），装配根持有专属解析路径（resolveHostMeditation 等）。后果：新增一个特性仍然要改配置 schema 与装配根——"三挂点拓展＋配置挂载"的纪律在最后一公里被内建硬编码卡死，自由注册名存实亡。

定案：agent 声明提供**通用 `plugins:` 挂载位**——`- id: <插件> with: {参数}`；参数 schema 由插件自带；装配根只做"列表→注册表→绑定"的通用解析，不认识任何具体特性名。特性特有的一切（参数校验、跨字段约束、冲突声明如"一进程一条反思循环"）下沉为插件自己的装配校验与元数据。拓展特性的完整路径＝写一个实现标准端口的插件→注册→在目标 agent 声明里加一行引用——装配根零改动。冥想因此从"schema 里的特权节"归位为"第一个一等公民插件"。

- **代价与取舍**：通用挂载位损失 schema 的静态可读性（yaml 里不再一眼看出"这是冥想"），换来的是扩展面与核心解耦；参数校验从装配期集中式变为插件分散式，需以插件自校验＋具名拒绝补偿。
- **机械固化（r15 补充裁定）**：本裁决经三道钉强制——golden/runtime/architecture.json 登记插件注册表与冥想插件包（--implementation 门）；lint 拦特性专属 schema 节与装配根专属解析路径（带正反样例自测）；两门接入 preflight/CI 逐提交执行。裁决不靠自觉，靠门红。
- **不做的事**：~~不引入运行期动态装卸（注册表是装配期解析）~~ **该子句已被 ADR 0007 取代（2026-11-08 用户裁定）：注册表扩展为代际作用域运行期生命周期**；其余不变——不改变六端口/三挂点契约本身；冥想既有行为语义（状态机、能量守恒、send 四道门）零变化——变的只是挂载形态。
- **依据**：用户裁决（r13）；机制与配置两层的现状落差实证（driver 已是插件 vs resolveHostMeditation 专属路径）；三挂点拓展纪律（r1 交付事件化裁决确立、09 三挂点映射延续）。
