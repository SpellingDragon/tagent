# 三挂点是整个项目迭代的核心原则，突破须经认真讨论并由规则机械守护

**Status**: accepted（2026-11-05 用户裁定，boundary-closure r19；守护套件=一级 F0 任务）

事件 x（生产）、插件 f(x)（管线）、消费 g(x)（读链）三挂点是本项目一切特性拓展的**唯一轨道**（docs/wiki/mechanism-tour.md §2）。本变更全程的裁决反复收敛到同一条判据：交付义务上链（弃旁路账本）、冥想状态机（弃虚事件）、配置链驱动（弃双轨真相）、插件自由注册（弃 schema 专属节）、契约只留不变量（机制细节不冻结）——每一次都是把某处滑出三挂点的实现拉回轨道。

**突破的六种形态**（本变更实证过全部六种）：
1. 特性专属 schema 节（如 agents.<id>.meditation 取代通用 plugins/tools 声明）；
2. 装配根特性专属解析路径（resolve<Feature> 形态符号）；
3. 旁路账本/第二真相（KV 欠条、内存发布记录、源文件与链双轨）；
4. 合成/自管谱系事件作驱动输入（虚事件喂不醒任何东西，伪主动权）；
5. 机制细节冻结进主规格（阻塞挂点式演进，每加能力都要规格手术）；
6. 私设配置面（统一挂载面之外的可配置项）。

**机械守护套件**（四条规则，接入 preflight/CI，逐提交执行）：
- R1 schema 节白名单：agent 声明只允许通用节（plugins/tools/memory/meditation 等既有白名单外的特性名节即红）；
- R2 装配符号扫描：装配根出现 resolve<Feature>/validate<Feature>/<feature>Port 形态的专属路径符号即红；
- R3 持久真相登记：新增持久存储/前缀/账本必须登记进统一注册表（golden），未登记的旁路持久面即红；
- R4 规格卫生：主 spec 的 requirement 文本不得含 .go 文件名、函数调用形态、数值常量（机制细节应住实现文档）。
每条规则带正反样例自测；规则修改本身需附正反例。

**突破协议**（突破不是禁止，是不许无声）：任何确需突破三挂点的迭代，必须同时满足——①一份 ADR 论证三挂点为何不足以承载该需求；②用户显式讨论裁定；③在守护注册表登记例外条目（含理由与复审期限）。三缺一即守护规则保持红。守护规则的红不是障碍，是"这次突破经过了认真讨论"的机器证词。

- **代价与取舍**：四条规则有维护成本（白名单/注册表随架构演进更新）；换来的是核心原则不靠自觉——本变更里六种形态全部曾无声出现，靠九轮拷问才逐一抓回，机械守护把它们变成提交即红。
- **不做的事**：守护不裁决设计优劣（那是评审与拷问环的事），只裁决"是否无声滑出轨道"；既有 grandfather 面在套件落地时一次性登记，不追溯改写。
- **依据**：用户裁定（r19）；全变更裁决轨迹（r1/r11/r12/r13/r14/r18 的共同判据）；六种突破形态的实证（各轮拷问报告）。
